三个主流 AI agent 框架的记忆系统设计完全不同。本文基于真实源码逐行阅读，做源码级对比。

## 🟩 Hermes —— 简单可靠透明的常驻事实记忆

- **存储**：`MEMORY.md`（笔记）+ `USER.md`（用户画像）两个纯文本；历史会话 SQLite + FTS5
- **注入**：会话开始读两文件 → 冻结快照 → 注入系统提示词**每轮常驻**
- **写入**：`memory` 工具落盘立即生效但**不改系统提示词**（保前缀缓存 KV cache 复用）；下一会话新快照
- **召回**：`session_search` FTS5（发现/滚动/浏览三模式，零 LLM，血缘去重）
- **压缩**：native 压缩 + 本地 ContextCompressor 兜底

**优点**：简单、透明、零依赖、缓存友好
**缺点**：全量注入吃 token，没有语义检索

## 🟦 OpenClaw —— 常驻根记忆 + 语义检索 + 梦境晋升

- **存储**：`MEMORY.md`（根记忆）+ `memory/*.md`（日期快照）+ SQLite（向量索引 / standing intents）
- **注入**：MEMORY.md 常驻；辅助记忆通过 `memory_search` 工具**按需检索**
- **梦境晋升**（核心）：managed cron job 定期运行 → 对短期记忆候选**多维评分** → 高分晋升到长期记忆
- **向量检索**：本地 embedding 混合检索

**优点**：语义搜索、自动记忆整理、不全量注入
**缺点**：架构复杂、需要 embedding 模型、梦境评分阈值难调

## 🟨 DeepSeek Harness —— 会话持久化 + 工作空间归属

- **存储**：`.zstd` 压缩的会话文件（header 含 cwd）+ workspace.json 账本
- **注入**：按工作空间归属加载会话
- **归属判据**：`realpath(session.cwd) === workspace.path`
- **特点**：会话即记忆，无独立记忆层

**优点**：会话完整保留、按项目隔离
**缺点**：无跨会话记忆、路径绑定严格（迁移会丢）

## 融合方案（如果要设计一个更好的）

| 能力 | 来源 | 说明 |
|---|---|---|
| 常驻根记忆 | Hermes | 简单可靠，缓存友好 |
| 语义检索 | OpenClaw | 按需召回，省 token |
| 梦境晋升 | OpenClaw | 自动整理，但要调阈值 |
| 会话持久化 | DSH | 完整保留对话历史 |
| 路径无关 | DSH 教训 | 用符号链接而非硬路径 |

## 关键结论

1. 没有完美的记忆架构，只有权衡（简单 vs 智能 vs 省 token）
2. 常驻注入适合小记忆（几 KB），大记忆必须按需检索
3. 记忆晋升（自动整理）是趋势，但阈值和评分维度需要大量调优
4. 路径绑定是所有工具的通病，符号链接是通用解法

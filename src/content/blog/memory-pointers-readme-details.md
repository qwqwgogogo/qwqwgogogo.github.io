用 agent 用久了会攒下一堆长期记忆：偏好、环境、项目状态、踩过的坑。然后有个问题一直悬着——**如果哪天换模型、换工具，这些东西还在不在？**

## 分界线是「换什么」

两种情况完全不一样：

| 情况 | 记忆能不能跟过去 |
| --- | --- |
| 同一个工具里换模型 | 能。记忆是工具层的，注入 prompt 由它自己做，换后端零成本 |
| 换到别家的 agent | 不能。那份记忆存在它的私有格式里，新工具读不到 |

所以「要不要备份记忆」这个问题，答案取决于你把自己放在哪条线上。我大概率会换工具，因此结论是：

**记忆系统只存指针，细节写进一个跟得走的普通文件。**

具体做法是在工作空间根目录放一份 README 当总入口，十来个块：我是谁 / 方法论 / 硬性要求 / 环境 / 工具 / 项目 / 待办 / 踩过的坑。记忆文件里对应的位置只留一行「细节见 README」。

这样换工具时唯一需要带走的就是这个目录，而它本来就是纯文本。

## 记忆文件会烂，得清

攒了两个月之后，那份长期记忆膨胀到 38.7KB，里面全是重复和过期结论。精简了一次：**38.7KB → 30.7KB，砍掉 21%。**

删的是这三类：

- **同一件事记了四遍。** 端口、更新机制、某个项目的配置，每次会话都追加一条，没人回收。
- **已经过时的结论。** 最典型的是「本机缺 torch 跑不了」——后来能跑了，旧结论还挂在上面，会把下一次判断带偏。
- **本来就该在文件里的细节。** 那些内容属于 README，占记忆的额度是浪费。

有一条要特别注意：**属于「用户偏好」的条目不能直接删，得先挪到偏好文件里。** 偏好和事实的保质期不一样——「端口 8000」 会过期，「讨厌没验证过的数据」 不会。混在一份文件里，清事实的时候就会顺手把偏好一起清掉。

## 最坑的一类：记忆里的「事实」

记忆存事实是有保质期的，而且它不会自己过期，只会一直显得很有把握。

我踩过的最典型的一次：记忆里写着某个服务默认端口 8000，文档也写 8000，旧日志也印 8000。三个来源一起指错，最后 `netstat` 一比，实际在 8188。

现在我在记忆里只留**去哪查**，不留**是多少**：

- ❌ 「ComfyUI 的端口是 8000」
- ✅ 「端口这类事实现场量：`netstat -ano | findstr LISTENING`」

版本、路径、端口、模型名，这四类一律按可再生的信息处理——存查法，不存结果。

## 不该进记忆的三类东西

- **密钥和 token。** 一旦写进会被同步、备份、跨设备复制的文件，等于抄送给所有能读到备份的人。
- **ID、配对码、别人的账号信息。** 同理，而且这些东西本来就该短命。
- **对某个具体的人的评价。** 记下来只会让下一次判断带着偏见，且很难撤销。

这条不是洁癖：一个东西被记成「长期事实」之后，它会持续影响后面每一次对话，而你已经不记得当初为什么会写下它了。

## 一句话

记忆的价值不在「存得多」，在于**换环境的时候不丢，并且里面的东西不会悄悄变错**。所以指针归记忆，细节归文件，事实归现场测量。

很多人问 DeepSeek 的缓存到底怎么算、多久失效、怎么省钱。本文基于官方 API 文档逐条查证。

## 缓存规则（官方来源：api-docs.deepseek.com/zh-cn/guides/kv_cache）

1. **默认开启**，无需改代码
2. **命中条件** = 后续请求**完整匹配**某个"缓存前缀单元"（不能部分匹配）
3. **前缀落盘时机**：请求结束位置（用户输入+模型输出各一个）、公共前缀检测、固定 token 间隔截取
4. **TTL**：不固定，**几小时到几天**，不保证 100% 命中，不使用了自动清空

## 价格（2026 当前官方）

| 模型 | 命中输入 | 未命中输入 | 输出 |
|---|---|---|---|
| v4-flash | ¥0.02/M | ¥1/M | ¥2/M |
| v4-pro | ¥0.025/M | ¥3/M | ¥6/M |

## 关键结论

1. **缓存命中比未命中便宜 50 倍**（flash ¥0.02 vs ¥1）——这是省 token 的核心杠杆
2. **多轮续聊最省**：前缀完整复用命中缓存；**切模型/换前缀 = 缓存失效暴烧**
3. TTL 无精确值（几小时~几天），所以"多久不用会失效"没有固定答案，只能靠"尽量连续用同前缀"来保命中

## 实用建议

- 对话中途别切模型，会触发缓存失效
- 长系统提示词（如 agent 的 MEMORY 注入）是缓存友好型——每次都一样，容易命中
- 但如果你频繁改系统提示词，反而会破坏缓存

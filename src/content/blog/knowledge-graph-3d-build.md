站点里有一页 [/knowledge](/knowledge/)：一团能拖能转的点，点一个词，右边列出它出现在哪几篇、连着哪些词。看起来是个炫技组件，实际上一半的工作量在「怎么让它别是假的」——图里每个点都得能追溯到某段已经发出去的文字。

这篇记五件事：数据怎么抽、一张图为什么要拆成两条线、术语解释怎么挑、渲染怎么省、以及 Astro 静态站塞 three.js 会踩的几个坑。

## 数据：规则而不是词表

生成脚本是 `scripts/build-knowledge.mjs`，挂在 `prebuild` 和 `predev` 上，产物 `src/data/knowledge.json` 和 `src/data/knowledge-408.json` 进仓库，所以 CI 里 `npm run build` 会重新生成一次。它只做一件事：读已经发布的文字，抽术语，连线，算坐标，写 JSON。

脚本每次跑都打两行统计，长这样：

```
site: 162 节点 / 305 边（weight>=2 的 2 条） · 孤点 0 · 最大度 45 · 概念 159（筛掉 55 个：挑不出原话 51、连不出关系 4）· 解释 158/159
  节点类别: concept 159 / project 3 / note 0 / subject 0
exam: 825 节点 / 2621 边（weight>=2 的 98 条） · 孤点 0 · 最大度 93 · 概念 708（筛掉 0 个：挑不出原话 0、连不出关系 0）· 解释 708/708
  节点类别: concept 708 / project 0 / note 114 / subject 3
```

文章那条线的术语判定不查任何词表——词表会腐烂，还会诱导我为了让图好看去补文章。用的是纯形状规则，四类写法算术语：

```
MCP / RSS       全大写缩写
ComfyUI         多个大写的名字
sizeof          反引号里出现的标识符
Wan2.2          带版本号或点划线的写法
```

再加两道门槛：带斜杠的路径不当概念，全站只提一次的词剔掉（全大写缩写和首页项目标签除外）。日志里抄来的盘符路径在扫描前先整段抹掉，不然那种写法中间的一段目录名会被当成一个术语——它不是一个概念，只是路径经过的一截。

第二条门槛是有原因的。第一版没有它，图上飘着一堆只被提过一次的点，连一条线都没有，看着像噪声不像信息。只提一次的词不值得一个点——图谱里孤点的存在感比列表里的一行还低。

## 为什么要拆成两张图

拆之前是一张 481 个点的图：文章里的术语、笔记里的考点、项目、科目全糊在一起。结果是两边都读不了——考点图上飘着只在命令行和日志里露过一次的工具名，文章图上混进「装填因子」「阶」这种只在 408 里成立的词，而我点开「阶」想查它哪来的，它其实挂在 B 树那篇笔记里，跟文章一句话关系都没有。

所以脚本现在是同一个函数跑两遍，只是喂不同的料：

```
site  文章 + 首页项目条目   概念靠形状规则抽      边：篇内共现 + 项目连标签
exam  114 篇笔记            概念只认 tags 声明的   边：篇内共现 + 笔记连考点 + 科目连笔记
```

四条区别都是硬的。**语料不同**：`contentDocs` 决定词从哪来，文章线不看笔记一个字，考点线也不读文章。**种子不同**：`seed='shape'` 让形状规则自己长点，`seed='declared'` 只认 frontmatter 里声明过的考点——中文没有分词能力，硬切只会造出「的一次握手」这种怪词，所以这一条线上 `DMA`、`B+树` 能进图，是因为我把它们写进了 tags，不是因为它们长得像术语。**出处不同**：面板上那句解释的候选句子池也跟着分线，考点线的 `glossDocs` 只有笔记，文章里顺带提到「溢出」的那句话抢不走它的解释。**边不同**：`linkProjects` 和 `linkNotes` 两个开关，文章线没有笔记节点，考点线没有项目节点，两边各自闭环。

一次构建写出两个 JSON，页面各取一个。拆图那一次，前端那份 3D 场景代码一行没改——它只认 `nodes`/`edges`/`kind`，两条线的节点类别颜色本来就是分开的四种。后来笔记长到 114 篇、点长到 825 个，场景代码才动过一次，那是性能的事，写在下面渲染那一节。

## 边只连真实归属

共现关系最容易造假。规则是：一篇文章里按出现次数排序，前 5 名互相连线（这些是真的在同一篇里一起出现过），第 6 名之后只连本篇第一名。后者不算共现，算归属——它保证不会出现孤点，但也不假装「这两个词在同一篇里并提过」。

其余的边都是明写的归属：项目连它自己的标签，笔记连它的考点，科目连它下面的笔记。

笔记那条有个额外校验。脚本不信任声明：它回正文里数一遍，`mentions(tag)` 为 0 就丢掉并打警告。

```
  ! osi-seven-layers 的考点「拥塞控制」在正文里找不到，这条不进图
```

这条校验真拦下来过。写 C 内存布局那篇时，我在 `tags` 里标了「内存布局」和「内存对齐」，但正文里没有这两个词的完整写法，脚本回正文数到 0，两条警告原样打出来。改正文、让这两个词各自出现在句子里，警告才消失。规则得立在脚本里，因为下一个写笔记、然后忘记正文其实没展开的人是我自己。标了考点而正文没写的词，在图上会表现为「我好像复习过这一节」，比没写更糟。

数数这活儿本身也有坑。带汉字的词和纯英文的词得两套比法：

```
带汉字    I/O接口  写成 I/O 接口  → 两边抹掉空格才对得上
纯 ASCII  某词 + 空格 + 某数       → 原样比，抹了空格反而数到 0
```

规则是「词里有汉字才抹空格」，判据在词身上，不在正文身上——第一版按正文判，一句英文里只要掺进汉字，整段的空格就被抹平了，那个带空格的写法假装自己不存在，报出来一句「正文里找不到」，我看着那条警告以为是自己在骗人。

## 解释：从原文里挑，不新写一句

有了点之后自然有人问：能不能点一个词就给它一句解释。最省事的做法是让模型现写几百条定义，但这张图的全部可信度就在于每个点都能追溯到某段已经发出去的文字——解释句如果是生成的，等于我的博客在替我说我没说过的话。所以脚本一个字都不生成，它只做检索：在提到这个词的那些句子里，挑一句最像解释的原文，连着出处一起放进节点。

挑句子是个打分题。正文先切句（按 `。！？` 和换行），丢掉代码块、表格行和标题，也丢掉 frontmatter 里的 description——那是「这篇讲什么」的目录句，当解释会读成「xx 是什么」，其实它只是在列小标题。留下的句子还要去掉行首列表符号和反引号。候选句长度卡在 12 到 120 字之间。加分项只有一条硬的：句子里出现「是指」「就是」「负责」「意味着」「所谓」「包括」这类下定义的说法，加 4 分；有破折号或冒号再加 1 分；再按离 44 字的距离给一点点偏好，只是同分时的微调。同一个词在多篇里都被提及时，取分数最高的那句。

还有一条归属规则：某个词被某篇笔记声明成考点，就只从那些笔记里挑。我在正文里提一句「某某词全空着」，不等于我在讲那个词。

最后一道是括号。词只出现在插入语里，这句讲的也不是它：报错文本被整个抄进正文时，括号里那几个英文单词只是原文，不是这句在解释的对象。但短括号不能一起砍——中文考点后面紧跟的那一小段英文对照就在短括号里，而那句正是解释。所以规则是形状：括号里带顿号或逗号、或者长过 24 字的当列举屏蔽，短的不屏蔽。

句子末尾也算形状。引出下文的冒号和分号会剪掉，剪完以「所以」收尾的句子整个淘汰——那半句不是解释，是半句。

长度这一项以前是扣分，而且扣得能扣穿：一句 78 字的话光靠长度就变成负数，直接被判「不算解释」。结果一批中文考点全空着——它们各自只有一句像样的话，那句话没冒号、还偏长。门槛应该是「这句话里真的有这个词，并且它撑得起一句解释」，不是「这句话长得像定义」。所以现在 12 到 120 字是硬门槛，过了门槛的句子一律有资格参选，长度只影响排名。

英文词还要多一道：整词匹配，而且把连字符算进词内。不然 `PATH` 会命中 `clip-path`，`seq` 会命中 `sequence`——第一版就挑出过「被 clip-path 收成一条缝」当作 PATH 的解释，看着完全像回事，其实说的是 CSS。

## 挑不出原话，就别放这个点

以前解释是可选字段：挑不出来就留空，点一下只有出现次数和一堆链接。后来发现的问题不是「空着不好看」，而是空着的那批点几乎都不是术语——它们只在表格单元格、命令行和别人的日志原文里露过一次，我从来没有用散文讲过它。给它们一个格子，图上就全是「我好像讲过这个」。

所以这一轮加了一道最后的筛子：概念节点挑不出一句原话，就不建这个点。首页项目标签豁免（那是我自己写的词，出现一次也算数），其余一律要有一句能点开的话。豁免不等于留白——这种标签点开时面板里不编定义，只照实说「这句原话挑不出来，它只是首页项目条目上写的标签」。

后来又补了第三道闸门：连一条关系都算不出来的词也丢掉。一个词只在一篇文章里出现过、而那篇没有别的合格术语，它就没有任何归属，挂在球面上谁也不挨着；一颗飘着的点比列表里的一行更没有信息量，所以宁可不画。

这两份名单我不贴在正文里。这篇文档本身也是语料：把被筛掉的词原样抄一遍，它们就在这里又出现了一次，下一轮构建立刻有了共现对象，「被筛掉」这件事自己会把自己撤销。上一版我贴过，这一版不贴。

文章线 214 个候选点筛到 159 个：51 个挑不出原话，4 个连不出关系。留下的 159 个里 158 个有原话，只有 1 个是豁免的项目标签（它只作为首页项目的标签挂在图上，正文确实没讲过）。考点线筛掉 0 个——不意外，那 708 个词全是我在 frontmatter 里一个个声明过的，声明过又通过了「正文真写过」那一关，正文里就必然有一句在讲它。上次那个讲四次挥手的例子从文章线上消失了：它现在只在考点图上，出处是那篇讲握手和挥手的笔记——同一个词在两张图上各有各的原话，这正是拆开的意义。

这一版给渲染那一节补了性能那一段，候选点就从 205 涨到 214：多出来的全是我在正文里新写的那几个英文词。「这篇文档自己也是语料」这句话，写到第三遍又应验一次。

新加的那篇五十二周安全计划也给文章线添了一批候选点，`Kali`、`SQLMap`、`DVWA`、`XSS` 这些全部卡在同一道门槛上：它们在正文里只作为清单里的一行出现过，我没有用散文讲过它们。这恰好是这道筛子想挡的东西——一个只在表格里露过面的工具名，不构成「我写过这个概念」。

这些词为什么挑不出句子，原因就两种。多数压根没有散文句子讲过它们，只在表格行、命令和日志原文里露过一次：

```
TLB / FIFO      只在一行表格里（讲全相联的代价 / 讲替换算法）
findstr / GUI   只出现在 netstat 命令和日志原文里
Roaming / PCL   从一张目录迁移对照表里抄出来的路径名
OpenMAIC        有一句完整介绍，但那句写到 140 字才出现第一个句号
Xmx             整词匹配把它挡在外面：正文里每次都写成 -Xmx
```

表格行是我主动丢掉的：一行 `| 全相联 | 标记 + 块内偏移 | 电路最贵 |` 拼起来不像句子，硬当解释放进面板就是在骗人。长句是硬卡掉的：讲到一半不换行，我也没办法——为了几个词把上限抬高，进来的就全是叙事。最后那条是正则的代价：连字符算词内字符，所以「前面带横杠的写法」永远匹配不上，而这种写法恰恰是它唯一的出现方式。挡掉 clip-path 误命中和漏掉这一个，是同一条规则的两头。

「考点优先」只保证第一遍：声明过这个词的笔记先挑，挑得出句子就用它；挑不出来的退回全库再找一遍，指到真的说过这句话的那篇去。留白只留给一个字都没说过的词——而现在这种词根本不会出现在图上。

还有一类只有这篇讲抽取机制的文章才会有的坑：它自己也是语料。正文里点名一个词，那个词就可能挑走一句「我在讲抽取规则」当作自己的解释。上一版这颗点是 PATH，这次它的原话跑到别篇文章里去了，于是换成这颗：

```
seq
全站提到 3 次 · 连着 1 个词
  不然 PATH 会命中 clip-path，seq 会命中 sequence——第一版就挑出过「被 clip-path 收成一条缝」当作 PATH 的解释，看着完全像回事，其实说的是 CSS。
  出自 把博客正文抽成两张能转的 3D 图
```

这句是真话，出处也点得回去，可它讲的是我的正则，不是讲这个东西。它回答的是「我写过什么」，不是「它是什么」——这就是为什么出处必须跟着显示，点一下就能跳回那段上下文自己判断。上面那些举例的词名，能放进代码块的全放进代码块，不进句子池。

## 坐标：构建时算死，不做力导向

点位用的是斐波那契球面均布，半径 120，`Math.cos/sin` 一轮循环算完，写进 JSON。两张图各算各的，所以同一批点在第一张图和第二张图上的位置没有关系，别拿位置对比。

```js
n.x = +(Math.cos(theta) * r * RADIUS).toFixed(2);
n.y = +(y * RADIUS).toFixed(2);
n.z = +(Math.sin(theta) * r * RADIUS).toFixed(2);
```

代价说清楚：**位置本身没有含义**。它只负责把点摊开，不让它们叠在一起。想读懂关系要看线和右侧面板，不能看「谁在左边」。

换来的好处是稳定的。力导向布局每次刷新都会收敛到不同状态，两帧之间点还在抖，用户记不住任何东西——一张你每次打开都要重新认的图，等于没有图。构建时算死之后，同一个词永远在同一个位置，我可以指着屏幕说「右上那颗绿的」。

## 渲染：八百个点要合并着画

第一版的场景是「一个点一个 mesh」（three.js 版本 0.187）：所有点共用一个 `SphereGeometry(1, 22, 16)`，靠 `mesh.scale.setScalar(radius)` 撑大小；每条边共用一个 `CylinderGeometry(1, 1, 1, 6)`，长度缩放、再用四元数把 Y 轴对齐到两点连线方向。这套写法在 154 个点上没问题——软件渲染实测 11 FPS。笔记从 46 篇长到 114 篇、点从 322 长到 825 之后，同一台机器上掉到 2 FPS，转一下卡半秒。

原因是 draw call 的数量跟着点和边一起涨：825 个球 + 2621 根圆柱 + 825 张标签贴图，一帧四千多次提交，每次都带着各自的材质。GPU 其实没干什么活，全卡在提交上。所以现在场景里只剩这几样东西：

```
825 个点      → 1 个 InstancedMesh（矩阵一份、颜色一份）
539 圈光晕    → 1 个 InstancedMesh，只给挂标签的那四十个
2621 条边     → 3 组 LineSegments：淡的、粗的、跟选中点相关的
825 张标签    → 41 张：连得最多的 40 个 + 一张会重绘的「选中专用」
```

边的处理最值得说。圆柱换成线段之后不能再靠半径分粗细（WebGL 里 `linewidth` 一直是 1 像素），所以按权重拆成两组，用两种透明度区分；跟当前选中点相连的那些边单独一组，染成 rust。选中一个点，就是把三组顶点的数组重填一遍、再告诉几何体这次画到第几个——2621 条边也就一万多个数，一次点选的代价远小于每帧维护 2621 个 mesh 的材质。同样条件重测，考点那张 2 FPS 变 7–10 FPS，JS 堆从 36 MB 掉到 10 MB；文章那张 11 FPS 变 13–16 FPS。这是软件渲染（swiftshader）下的数字，有独显的机器只会更宽，但手机和核显用户拿到的就是这个下限附近的量级。

半径按连接数来：`2.4 + Math.sqrt(deg) * 1.5`，点超过三百个再整体乘 0.7。开平方是因为度数是长尾的，两张图最粗的那个点累加到 46 和 103（上面脚本打的是不数权重的邻居个数），直接线性缩放会让一个点吃掉半个屏幕。0.7 是截图里量出来的：八百个球按原半径摆，前半球被盖掉将近一半，整张图就是一堵墙，缩到七成才露出线。点密的时候球的段数也从 22×16 降到 12×8——省的是顶点数，这个尺寸上看不出圆不圆。

标签用 `CanvasTexture`：2D canvas 画一行字，贴到 `Sprite` 上。这样文字永远正对镜头，不需要额外字体文件，也不用引 troika 那类 SDF 文本库——代价是位图，缩得很近会糊。我按 `devicePixelRatio`（上限 2）画的，正常距离看不出来。

标签的门槛从「连接数 ≥ 5」改成了「按连接数排序取前 40 个」。前者在文章那张图上是 32 个标签，正好；到考点这张图上变成 539 个，全挂上去就是一团马赛克，等于没有标签。不在前 40 之列的词，选中时用另一张会重绘的贴图单独显示——一张画布、一张贴图，换词只改画布内容，不新建纹理，否则点几百次就攒出几百张贴图。名字本身右侧面板一直写着，所以收掉标签不丢信息，只丢「一眼扫到」的方便。

四类节点四种颜色， ink 棕黑、rust 项目、teal 笔记、olive 科目。选中态原来是靠 `emissiveIntensity` 分档（选中 0.4 / 邻接 0.16 / 其余 0.04），非邻接点压到 0.42 透明度——这两个都是逐 mesh 的属性，实例化之后一个网格只有一份材质，都用不了了。现在改成往底色混：颜色和纸色 `#f6f3ec` 插值，画出来和半透明叠在纸上几乎一样，代价是「淡」只能靠颜色不能靠 alpha。

第一版的混色比例直接抄了那个 0.42，截图出来整颗球是奶白的。原因是两盏灯的强度（半球光 2.1、平行光 2.4）是配着半透明材质调的：材质透明时后面的纸色会透上来，看着不刺眼；换成实色之后同样的光强把淡灰推到接近爆掉，淡和没淡分不出差别。改法是淡的那批不再混纸色而是混一个更深的灰 `#8f897c`、比例给到 0.8，两盏灯降到 1.35 和 1.7。被压暗的词，它的标签也必须跟着暗（0.95 对 0.42），不然「浅灰点 + 清晰黑字」看着像选中了但又不是。

## 别一直画

渲染闸门四条，缺一不可：

```js
const loop = (time) => {
	raf = requestAnimationFrame(loop);
	if (!inView || !visible) return;                // 舞台离屏 / 标签页切走
	if (dirty) { dirty = false; repaint(); needsRender = true; }   // 选中或悬停变了才算一次
	if (sel && animate) { needsRender = true; }     // 只有选中的那圈光晕在呼吸
	if (!needsRender && controls.update() !== true) return;   // 机位没动、也没要重画
	needsRender = false;
	controls.update();
	renderer.render(scene, camera);
};
```

`inView` 来自 `IntersectionObserver`（threshold 0.01），`visible` 来自 `visibilitychange`，`needsRender` 由 `controls` 的 `change` 事件置位，`dirty` 由点选、悬停和尺寸变化置位。rAF 队列是一直排着的，但绝大多数帧只做几次布尔判断就 return。滚动到图下方、切走标签页的时候 GPU 是空的——这页开着自动旋转（速度 0.42），不闸门就会一直转下去。

掉到 2 FPS 的第二半原因在这儿，而且是更丢人的那半：以前的 `paint()` 挂在每帧上，八百多个材质和两千多条边的材质被逐帧重写一遍——选中点是哪个、邻接的是哪些，这些一帧都不会变的东西，我却每帧算一次。现在它叫 `repaint()`，只在 `dirty` 那一支跑；每帧剩下的只有「选中那圈光晕换个半径」这一件事。呼吸动画也顺势从「缩放选中点自己的 mesh」改成「缩放它外面那圈光晕」，因为改点的尺寸要重写整份实例矩阵（八百条），而改光晕实例矩阵只有四十条。

拖动时停自转，抬手 7 秒后再恢复；点选判定是「按下和抬起的位移小于 6 像素」，否则算成拖拽，不误触选中。点选用的射线检测也从「对八百个 mesh 各求一次交」变成「对实例网格求一次交」，拿 `instanceId` 反查是哪个词。

## 包：three.js 和图谱 JSON 都不进首屏

页面脚本先跑，`webglWorks()` 探测过了才 `import('./knowledge-gl')`。那份 JSON 也是动态 import——两张图分别 72 KB 和 425 KB，静态引就全塞进同一个 chunk，而读者一次只会看其中一张。

| 文件 | 原始 | gzip |
| --- | --- | --- |
| 交互脚本（选中、面板、探测） | 6,037 B | 2,814 B |
| 文章线 JSON（`/knowledge` 才加载） | 71,688 B | 17,078 B |
| 考点线 JSON（`/knowledge/408` 才加载） | 425,404 B | 106,699 B |
| 动态 chunk（three.js + OrbitControls + 场景） | 576,244 B | 140,997 B |

哪条路径加载哪份数据，是在 `boot()` 里用 `location.pathname` 判的，不是编译期分两个入口——模块在文档存活期只执行一次，判晚一步就会拿错图。

探测失败或 import 抛错，就在同一块舞台上画矢量降级版，坐标复用 JSON 里那批——服务端做了一次固定角度的正交投影（yaw −0.55、pitch 0.34），所以没 WebGL 的机器看到的结构和能跑的是**同一张图**，不是另画一张简版。降级版一样能点：可点的那几个词各包一个 `<g>`，挂 `data-node-id`、`role="button"`、`tabindex="0"`，Enter 和空格在 `main` 的委托监听里转成同一次选中；`<g>` 不是原生按钮，键盘行为只能自己接。

代价以前写在这儿：降级版是服务端直接渲染进页面的，文章那张 95 KB（148 个点），考点那张涨到 601 KB、gzip 54 KB（825 个点、2621 条边一个元素一个元素铺出来就是三千多个 DOM 节点，而且这八百多个能按 Tab 停下来的点本身就是无障碍的灾难）。这一版把它压下去了，办法不是少画，是**别一个元素画一个东西**：

```
2621 条边       → 2 条 <path>（淡的一笔、粗的一笔，d 里全是 M…L…）
708 个考点      → 3 条 <path>，按连接数分三档粗细
117 个科目/笔记/项目 → 还是各画各的 <circle>，点少，颜色要对得上图例
可聚焦的点       → 从 825 个收到 16 个（连得最多的那批），其余靠下面那排按钮走键盘
```

考点那种小圆点用的是 SVG 的一个性质：**一段长度为零的路径加上 `stroke-linecap: round`，渲染出来就是一个圆点，直径就是 `stroke-width`**。所以一个点只花十几个字符（`M x y h.01`），而不是一个带六个属性的 `<circle>`。`h.01` 不是 0 是因为有些渲染器会直接跳过零长度子路径。

现在同一张页的 HTML 是 219 KB、gzip 36 KB（文章那张 51 KB / 11 KB），图上一个点都没少。它 3D 一起来还是被 `display: none` 收掉，不进无障碍树，但字节已经付了——这条只能承认，静态站没有服务端的第二个渲染路径。

## Astro 这边踩的三个坑

**1. 页面脚本一个文档只执行一次。** 站上有页间过渡，`<script>` 不会在每次换页时重跑。所以装配 DOM 的逻辑全塞进 `boot()`，由 `astro:page-load` 每次过渡后调用，并用 `stage.dataset.kbBooted` 挡重复；换页前在 `astro:before-swap` 里 `dispose()` 掉上一个 WebGL 上下文。浏览器同时存的 WebGL context 有上限（大概十几个），不清的话，来回点几次知识库就白了。

**2. `<script>` 里的 `{expr}` 不插值。** 想在页面脚本里带构建时算好的数值是不行的，脚本拿到的是原始字面量。所以数据走 `src/data/*.json` import，页面自己的那段脚本只查 DOM。

**3. scoped style 打不到 JS 建出来的节点。** 选中面板每次重建，新节点身上没有 Astro 的作用域属性，样式全得写成 `.detail :global(.name)` 这种形式。第一次做的时候面板是裸文本，才反应过来。同样的坑还有一次：两张图共用一个组件，服务端渲染好的那排按钮是插槽里来的，也没有本组件的作用域属性，得走 `.column :global(.chips button)`。

顺带一个动效基座上的老坑：`IntersectionObserver` 的 `threshold` 必须是 0。被 `clip-path` 收成一条缝、或被 `scaleX(0)` 压成零面积的元素，面积就是 0，任何大于 0 的阈值永远不会命中。

豁免表也踩过一次小的。首页项目标签的集合是按小写存的键，比对时传的是原样大小写，结果两个本该豁免的标签双双被门槛筛掉，项目节点的那条边一起断了，图上只剩一颗孤点。规则没错，错在两条线的大小写口径不一致。

## 值不值

技术上不新，3D 力导向图十年前就有。有意义的是这几条约束：**数据只能来自已发布的文字、每张图的语料只限自己那一类、挑不出原话就不放点、构建时算死坐标、包不进首屏、没 WebGL 也得能用**。六条都在限制「图能骗人」的空间。

代价也很实在：825 个点第一眼看过去就是一团，没有布局语义，得靠右侧面板把关系翻译成文字。真要读关系，下面那两列词表比这团星点有效得多——它一直在那儿。也正因为这一点，标签才只挂到四十个封顶：这张图上「看清」从来不是靠星点，是靠点下去之后的那段原话。

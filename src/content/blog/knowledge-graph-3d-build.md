站点里多了一页 [/knowledge](/knowledge/)：一团能拖能转的点，点一个词，右边列出它出现在哪几篇、连着哪些词。看起来是个炫技组件，实际上一半的工作量在「怎么让它别是假的」——图里每个点都得能追溯到某段已经发出去的文字。

这篇记四件事：数据怎么抽、术语解释怎么挑、渲染怎么省、以及 Astro 静态站塞 three.js 会踩的几个坑。

## 数据：规则而不是词表

生成脚本是 `scripts/build-knowledge.mjs`，挂在 `prebuild` 和 `predev` 上，产物 `src/data/knowledge.json` 进仓库，所以 CI 里 `npm run build` 会重新生成一次。它只做一件事：读所有已发布的文章正文、笔记正文和首页的项目条目，抽术语，连线，算坐标，写 JSON。

脚本每次跑都打一行统计，长这样：

```
knowledge.json: 212 节点 / 431 边（weight>=2 的 19 条） · 孤点 0 · 最大度 40 · 术语解释 154/196
  节点类别: concept 196 / project 3 / note 10 / subject 3
```

术语判定不查任何词表——词表会腐烂，还会诱导我为了让图好看去补文章。用的是纯形状规则，四类写法算术语：

```
MCP / RSS       全大写缩写
ComfyUI         多个大写的名字
sizeof          反引号里出现的标识符
Wan2.2          带版本号或点划线的写法
```

再加两道门槛：带斜杠的路径不当概念，全站只提一次的词剔掉（全大写缩写和首页项目标签除外）。

第二条门槛是有原因的。第一版没有它，图上飘着一堆只被提过一次的点，连一条线都没有，看着像噪声不像信息。只提一次的词不值得一个点——图谱里孤点的存在感比列表里的一行还低。

## 边只连真实归属

共现关系最容易造假。规则是：一篇文章里按出现次数排序，前 5 名互相连线（这些是真的在同一篇里一起出现过），第 6 名之后只连本篇第一名。后者不算共现，算归属——它保证不会出现孤点，但也不假装「这两个词在同一篇里并提过」。

其余三类边都是明写的归属：项目连它自己的标签，笔记连它的考点，科目连它下面的笔记。

笔记这条有个额外校验。考研 408 的笔记是中文正文，脚本没有分词能力，硬切只会造出「的一次握手」这种怪词，所以中文考点是我在 frontmatter 的 `tags` 里自己声明的。但脚本不信任声明：它回正文里数一遍，`mentions(tag)` 为 0 就丢掉并打警告。

```
  ! osi-seven-layers 的考点「拥塞控制」在正文里找不到，这条不进图
```

这条校验真拦下来过。写 C 内存布局那篇时，我在 `tags` 里标了「内存布局」和「内存对齐」，但正文里没有这两个词的完整写法，脚本回正文数到 0，两条警告原样打出来。改正文、让这两个词各自出现在句子里，警告才消失。规则得立在脚本里，因为下一个写笔记、然后忘记正文其实没展开的人是我自己。标了考点而正文没写的词，在图上会表现为「我好像复习过这一节」，比没写更糟。

## 解释：从原文里挑，不新写一句

有了点之后自然有人问：能不能点一个词就给它一句解释。最省事的做法是让模型现写一百多条定义，但这张图的全部可信度就在于每个点都能追溯到某段已经发出去的文字——解释句如果是生成的，等于我的博客在替我说我没说过的话。所以脚本一个字都不生成，它只做检索：在提到这个词的那些句子里，挑一句最像解释的原文，连着出处一起放进节点。

挑句子是个打分题。正文先切句（按 `。！？` 和换行），丢掉代码块、表格行和标题，也丢掉 frontmatter 里的 description——那是「这篇讲什么」的目录句，当解释会读成「xx 是什么」，其实它只是在列小标题。留下的句子还要去掉行首列表符号和反引号。候选句长度卡在 12 到 120 字之间。加分项只有一条硬的：句子里出现「是指」「就是」「负责」「意味着」「所谓」「包括」这类下定义的说法，加 4 分；有破折号或冒号再加 1 分；再按离 44 字的距离给一点点偏好，只是同分时的微调。同一个词在多篇里都被提及时，取分数最高的那句。

还有一条归属规则：某个词被某篇笔记声明成考点，就只从那些笔记里挑。我在正文里提一句「某某词全空着」，不等于我在讲那个词。

最后一道是括号。词只出现在插入语里，这句讲的也不是它：报错文本被整个抄进正文时，括号里那几个英文单词只是原文，不是这句在解释的对象。但短括号不能一起砍——中文考点后面紧跟的那一小段英文对照就在短括号里，而那句正是解释。所以规则是形状：括号里带顿号或逗号、或者长过 24 字的当列举屏蔽，短的不屏蔽。被这条砍掉的全是「只在别人的报错文本里挂过一次」的词，它们本来也不该有自己的格子。

句子末尾也算形状。引出下文的冒号和分号会剪掉，剪完以「所以」收尾的句子整个淘汰——那半句不是解释，是半句。

长度这一项以前是扣分，而且扣得能扣穿：一句 78 字的话光靠长度就变成负数，直接被判「不算解释」。结果一批中文考点全空着——它们各自只有一句像样的话，那句话没冒号、还偏长。门槛应该是「这句话里真的有这个词，并且它撑得起一句解释」，不是「这句话长得像定义」。所以现在 12 到 120 字是硬门槛，过了门槛的句子一律有资格参选，长度只影响排名。

英文词还要多一道：整词匹配，而且把连字符算进词内。不然 `PATH` 会命中 `clip-path`，`seq` 会命中 `sequence`——第一版就挑出过「被 clip-path 收成一条缝」当作 PATH 的解释，看着完全像回事，其实说的是 CSS。

渲染出来是这样：

```
TIME_WAIT
全站提到 7 次 · 连着 5 个词
  副作用：主动关闭方堆太多 TIME_WAIT 会吃掉本地端口，高并发短连接的服务端要考虑连接复用。
  出自 TCP 三次握手与四次挥手
```

那行引用不是定义，是「原文里怎么说到它」。`ACK` 挑中的那句其实在讲四次挥手为什么要先回一个 ACK——它回答的是「我写过什么」，不是「它是什么」，所以出处必须跟着，点一下就能跳到那段上下文里去看。

还剩 42 个词没有解释，分成两种。多数是压根没有散文句子提到过它们，只在表格行、命令和代码里露过一次：

```
TLB / FIFO      只在一行表格里（讲全相联的代价 / 讲替换算法）
malloc          只在段表的单元格里
findstr / GUI   只出现在 netstat 命令和日志原文里
OpenMAIC        有一句完整介绍，但那句写到 140 字才出现第一个句号
```

表格行是我主动丢掉的：一行 `| 全相联 | 标记 + 块内偏移 | 电路最贵 |` 拼起来不像句子，硬当解释放进面板就是在骗人。长句是硬卡掉的：讲到一半不换行，我也没办法，为了几个词把上限抬高，进来的就全是叙事。这两种情况一律留白，不补一句看起来完整的话。

还有一个只有这篇讲抽取机制的文章才会有的坑：它自己也是语料。正文里点名一个没解释的词，那个词就会挑到一句「它没被解释过」当自己的解释。所以上面那几条举例，词名全放在代码块里，不进句子池。

中文考点一个不落地有句子可挑，因为它们本来就是笔记正文正在讲的东西；空着的 42 个全是英文标识符。整张图的解释覆盖 154/196。

## 坐标：构建时算死，不做力导向

点位用的是斐波那契球面均布，半径 120，`Math.cos/sin` 一轮循环算完，写进 JSON。

```js
n.x = +(Math.cos(theta) * r * RADIUS).toFixed(2);
n.y = +(y * RADIUS).toFixed(2);
n.z = +(Math.sin(theta) * r * RADIUS).toFixed(2);
```

代价说清楚：**位置本身没有含义**。它只负责把点摊开，不让它们叠在一起。想读懂关系要看线和右侧面板，不能看「谁在左边」。

换来的好处是稳定的。力导向布局每次刷新都会收敛到不同状态，两帧之间点还在抖，用户记不住任何东西——一张你每次打开都要重新认的图，等于没有图。构建时算死之后，同一个词永远在同一个位置，我可以指着屏幕说「右上那颗绿的」。

## 渲染：一百多个球共用两份几何体

three.js 版本 0.187，场景里所有点共用一个 `SphereGeometry(1, 22, 16)`，靠 `mesh.scale.setScalar(radius)` 撑大小；所有边共用一个 `CylinderGeometry(1, 1, 1, 6)`，长度缩放、再用四元数把 Y 轴对齐到两点连线方向：

```js
mesh.quaternion.setFromUnitVectors(upAxis, dir.normalize());
```

半径按连接数来：`2.4 + Math.sqrt(deg) * 1.5`。开平方是因为度数是长尾的，最大度 23，直接线性缩放会让一个点吃掉半个屏幕。

标签用 `CanvasTexture`：2D canvas 画一行字，贴到 `Sprite` 上。这样文字永远正对镜头，不需要额外字体文件，也不用引 troika 那类 SDF 文本库——代价是位图，缩得很近会糊。我按 `devicePixelRatio`（上限 2）画的，正常距离看不出来。

只有连接数 ≥ 5 的点常驻标签，其余的点等 hover 或被选中才亮字。这个阈值是量出来的：一百多个标签一起挂就是一团马赛克。

四类节点四种颜色， ink 棕黑、rust 项目、teal 笔记、olive 科目。选中态靠 `emissiveIntensity` 分档（选中 0.4 / 邻接 0.16 / 其余 0.04），非邻接点整体压到 0.42 透明度——被压暗的词，它的标签也必须跟着暗，不然「浅灰点 + 清晰黑字」看着像选中了但又不是。

## 别一直画

渲染闸门四条，缺一不可：

```js
const loop = (time) => {
	raf = requestAnimationFrame(loop);
	if (!inView || !visible) return;              // 舞台离屏 / 标签页切走
	const moved = controls.update() === true;      // 惯性回弹还在动
	const pulsing = animate;                       // 用户关了就停
	if (!dirty && !moved && !pulsing) return;
	...
};
```

`inView` 来自 `IntersectionObserver`（threshold 0.01），`visible` 来自 `visibilitychange`，`dirty` 由 `controls` 的 `change` 事件和指针移动置位。rAF 队列是一直排着的，但绝大多数帧只做两次布尔判断就 return。滚动到图下方、切走标签页的时候 GPU 是空的——这页开着自动旋转（速度 0.42），不闸门就会一直转下去。

拖动时停自转，抬手 7 秒后再恢复；点选判定是「按下和抬起的位移小于 6 像素」，否则算成拖拽，不误触选中。

## 包：three.js 不进首屏

页面脚本先跑，`webglWorks()` 探测过了才 `import('./knowledge-gl')`。构建产物因此分成两块：

| 文件 | 原始 | gzip |
| --- | --- | --- |
| `/knowledge` 首屏脚本（动效基座 + 交互 + 内联的图谱 JSON） | 28,701 B | 7,734 B |
| 动态 chunk（three.js + OrbitControls + 场景） | 569,814 B | 139,650 B |

图谱那份 JSON 现在 27 KB 出头，被打包器直接内联进了首屏脚本——它本来就是 import 进来的常量，这样反而少一次请求。点会变多，包也会跟着长，但量级一直是 KB，不是 MB。

探测失败或 import 抛错，就在同一块舞台上画 SVG 降级版，坐标复用 JSON 里那批——服务端做了一次固定角度的正交投影（yaw −0.55、pitch 0.34），所以没 WebGL 的机器看到的结构和能跑的是**同一张图**，不是另画一张简版。降级版一样能点：每个 `<g>` 上挂 `data-node-id`、`role="button"`、`tabindex="0"`，Enter 和空格在 `main` 的委托监听里转成同一次选中；`<g>` 不是原生按钮，键盘行为只能自己接。

## Astro 这边踩的三个坑

**1. 页面脚本一个文档只执行一次。** 站上有页间过渡，`<script>` 不会在每次换页时重跑。所以装配 DOM 的逻辑全塞进 `boot()`，由 `astro:page-load` 每次过渡后调用，并用 `stage.dataset.kbBooted` 挡重复；换页前在 `astro:before-swap` 里 `dispose()` 掉上一个 WebGL 上下文。浏览器同时存的 WebGL context 有上限（大概十几个），不清的话，来回点几次知识库就白了。

**2. `<script>` 里的 `{expr}` 不插值。** 想在页面脚本里带构建时算好的数值是不行的，脚本拿到的是原始字面量。所以数据走 `src/data/knowledge.json` import，页面自己的那段脚本只查 DOM。

**3. scoped style 打不到 JS 建出来的节点。** 选中面板每次重建，新节点身上没有 Astro 的作用域属性，样式全得写成 `.detail :global(.name)` 这种形式。第一次做的时候面板是裸文本，才反应过来。

顺带一个动效基座上的老坑：`IntersectionObserver` 的 `threshold` 必须是 0。被 `clip-path` 收成一条缝、或被 `scaleX(0)` 压成零面积的元素，面积就是 0，任何大于 0 的阈值永远不会命中。

## 值不值

技术上不新，3D 力导向图十年前就有。有意义的是这几条约束：**数据只能来自已发布文字、构建时算死坐标、包不进首屏、没 WebGL 也得能用**。四条都在限制「图能骗人」的空间。

代价也很实在：一百多个点第一眼看过去就是一团，没有布局语义，得靠右侧面板把关系翻译成文字。真要读关系，下面那两列词表比这团星点有效得多——它一直在那儿。

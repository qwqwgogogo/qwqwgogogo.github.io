用 MiMo v2.5 做主力模型时，遇到了一个严重的工具调用循环 Bug。同一个会话内发生了 4 轮独立循环，累计约 65 次无效重复调用。

## 事件时间线

| 阶段 | 发生了什么 | 消息数 |
|---|---|---|
| 模型切换触发循环 | 切换瞬间上下文打断，模型开始疯狂重复 `ls` 命令 | 35次重复调用 |
| 用户中断 + 讨论 | 发消息打断 → 讨论原因 | ~10条有效消息 |
| 工作空间检查又循环 | 查工作空间，又开始循环 `ls` | 11次重复调用 |
| 用户告知新路径 | 给了新路径 → 又循环 `ls` 新路径 | 11次重复调用 |
| 终于找到新路径 | 直接给完整路径，找到文件 | 5次重复调用 |
| 更新 MEMORY 又循环 | memory replace 的 old_text 匹配失败，循环 | 3次重复调用 |

## 现象与根因

**触发条件**：
- 上下文被模型切换打断时
- 收到系统循环警告（`repeated_exact_failure_warning`）时不调整行为
- 工具返回错误时（如参数不匹配）

**量化数据**：同一轮内最多重复 **35 次完全相同的命令**，系统从第 3 次就发出警告，但模型完全无视。

**根因**：
1. 模型切换打断推理链 → 模型没有正确处理新信息
2. 系统警告是"软"的（只警告不强制中断）
3. MiMo 缺乏自我监控能力（无法说"等等，我已调了 10 次了"）

**对比**：更强的模型（GPT-4o、Claude）在收到循环警告后通常会调整行为，恢复更快。

## 缓解措施

1. **连续 2 次同一任务失败 → 强制停止重试**，分析原因，总结为可复用的经验
2. 不要死循环重试同一方案
3. 关键路径操作（如 memory replace）先验证参数格式
4. 模型切换后立即发一条明确指令，重建上下文

## 关键结论

- 用中小模型做 agent，必须有外部的循环防护（不能只靠模型自觉）
- 系统警告对弱模型几乎无效，需要硬中断机制
- 工具参数语义（如 old_text vs content）对弱模型不直觉，文档要写得更明确

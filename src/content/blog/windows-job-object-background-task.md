一个桌面程序的插件市场提示「请完全退出后再更新」。我不想守着，就想让它自己等：我关掉窗口，脚本检测到，跑安装，跑完通知。听起来是个二十行的事，实际花了两个会话，中间两次误判。

## 第一版：监视进程被连坐

思路很直白——起一个后台进程，轮询那个主进程还在不在，不在了就执行安装命令。用宿主 agent 的 shell 工具起，`Start-Process` 分离出来，窗口关了，PID 拿到了。

然后我正常关掉那个桌面程序。**监视进程一起没了**，日志最后一行停在轮询中间，没有异常，没有退出码，就是没了。

原因是宿主把每次工具调用跑在一个作业对象（job object）里，而且设了 kill-on-close：作业里的整棵进程树，在句柄关闭时全部清掉。`Start-Process` 起的子进程仍然是这个作业的后代，所以「分离」只是没有控制台，不是脱离作业对象。

这条很反直觉，因为我们平时说的「后台进程」默认是脱离父进程就能活。在作业对象面前不是。

## 中间那些被挡掉的路

要让进程活得比宿主久，得让它的父进程不是宿主。常规做法就那几条：计划任务、WMI 持久化、启动文件夹放个快捷方式、服务。

第一版所在的会话里，这几条全被拒——那个会话的权限只允许写工作区，`schtasks`、WMI 一类操作根本调不动。所以当时给出的结论是「必须你双击启动」：由资源管理器拉起，父进程是 `explorer.exe`，不在宿主的作业对象里，能活。这是绕开的办法，但要用户每次手动双击，等于没自动化。

后来换了一个会话，权限完整，`schtasks` 和计划任务的 COM 接口都能用了，才走到真正的解法。**顺便修正一个我自己的判断**：我一度把「做不到」归结为 Windows 的限制，其实那是会话权限的差异。同一个脚本、同一台机器，两次会话结论完全不同——先确认权限边界，再确认技术边界，不然会去绕一个根本不存在的墙。

## 生效的那版：登录触发的计划任务

```
PID 22808 (powershell.exe) ← 父进程 svchost.exe
```

监视进程由任务计划程序启动，父亲是 `svchost.exe`，压根不在宿主的作业对象里，宿主怎么退都杀不到它。注册的任务要点三个：

- 触发器用**登录时**，而不是「现在跑一次」——中途重启电脑它还会继续等，不用我记着重新挂；
- 身份是 `InteractiveToken`，这样它弹出来的终端窗口在我桌面上看得见，不是跑在黑里；
- 装完**自删**。这条不是洁癖：留下的任务每次开机都跑一遍轮询，一个月后我只会记得「我好像有个后台脚本」，但想不起它是干什么的、该不该还在。

零操作达成。但还有一个坑没踩完。

## pnpm 的 24 小时不装新东西

要装的插件版本是当天发布的。命令照官方提示执行，报的是：

```
[ERR_PNPM_NO_MATURE_MATCHING_VERSION] dshmarket@1.66.42 was published ... within the minimumReleaseAge cutoff
```

这个 profile 开了 pnpm 的 `minimumReleaseAge: 1440`——发布不满一天（1440 分钟）的版本默认不装。这不是 bug，是供应链投毒的冷却期：新版本恶意包最常见的窗口就是发布后的头几个小时。

市场自己的报错里给了绕过开关 `--config.minimum-release-age=0`。我在临时目录实测过：加上就能解析到那个版本。脚本先按默认规则装，撞到上面那条错误码再重试一次，重试时才带上这个开关。

**这个开关要不要用，我没有很好的答案。** 用，等于为了自动更新把冷却期关掉，而冷却期防的正是这种「急着装最新版」的场景。不用，自动更新就只能装到一天前的版本——其实这才是多数时候该装的。现在的折中是：只在这一个包、这一条命令上放行，不做全局配置，也不写进 `.npmrc`。

## 最坑的是它其实已经成功过一次

翻日志发现，第一版那个「被杀掉」的监视进程，在被杀之前已经完整跑成过一次安装：

```
1.66.39 -> 1.66.42 (exit 0)
```

而现在界面提示我要装的还是 1.66.39。也就是说：状态已经变了，提示没变，我盯着提示看了半天，以为一次都没成功。

如果我只相信 UI 的提示，就会再挂一个 watcher 去装同一个版本，然后再怀疑是不是自己哪儿写错了。**能被程序自己核对的事实，别看提示。** 所以最后那版脚本的收尾不是弹窗，是把安装日志和退出码留在一个我能一眼找到的地方——`exit 0` 比任何「更新成功」的文案都可靠。

三件事值得记住：

1. 进程树不是可靠的后台，作业对象能连坐；想活就换一个不属于自己的父进程。
2. 「做不到」先分清是技术限制还是权限限制，两者的修法完全不同。
3. 自动化的产物要么自删，要么留一份可核对的日志，不然一个月后它就成了一个没人认识的后台进程。

这篇不是学习成果，是一份排课表。我把它写出来是因为之前那份计划散在本地笔记里，改了好几轮之后发现真正有价值的不是「学什么」——OWASP Top 10 就那十项，谁都一样——而是**一周只塞一件事**这个切法。

站里已经有两篇自己写的网络基础笔记，正好是这条路线第一周要用到的东西：[学习 OSI 七层模型](/notes/osi-seven-layers/) 和 [TCP 三次握手、四次挥手](/notes/tcp-handshake/)。它们在这份计划里不是「学过就完了」，是第 1 周抓包练习的说明书——看不懂握手，Wireshark 里那六个包就只是六个包。

## 三段是怎么切的

| 阶段 | 周次 | 一句话目标 | 结束时应该能干什么 |
| --- | --- | --- | --- |
| 基础夯实 | 1-12 | 看懂数据包，玩转 Linux，理解漏洞原理 | 抓一段 HTTP 流量，说出每个包在干什么 |
| 技能深化 | 13-36 | 独立完成 Web 渗透和内网基础扫描 | 给一个靶机，从信息收集写到可交付的报告 |
| 高级进阶 | 37-52 | 攻防对抗、体系化建设、复杂问题 | 在本地域环境里同时演红队和蓝队 |

切的依据不是难度，是**依赖**：没搭好虚拟机就别碰工具，没搞懂 HTTP 就别碰注入，没做过单台靶机就别碰域。所以每一段的第一周都在搭环境，而不是学新概念。

## 第 1 周长什么样

每周固定六天有任务、周日只复盘，这个模板从第 1 周用到第 52 周，只换内容不换骨架：

| 时间 | 主题 | 具体任务 | 资源 / 工具 |
| --- | --- | --- | --- |
| 周一 | 网络基础 | OSI 七层、TCP/IP 协议栈，重点是三次握手和四次挥手 | 自己那两篇笔记 |
| 周二 | 网络协议 | HTTP/HTTPS 的请求响应格式、状态码、Cookie 和 Session 机制 | MDN Web Docs |
| 周三 | Linux 基础 | 装 Ubuntu 或 Kali 虚拟机，练 `ls` `cd` `grep` `find` `chmod` | 《鸟哥的 Linux 私房菜》 |
| 周四 | Linux 进阶 | 用户与权限、文件系统结构、Vim、Shell 基础语法 | 在线练习环境 |
| 周五 | 数据库基础 | 装 MySQL，写增删改查，理解表结构 | MySQL 官方文档 |
| 周六 | 实践 | 在 VMware 里配好 Kali 和 Windows Server；用 Wireshark 抓一次 HTTP 流量并分析包结构 | VMware、Wireshark |
| 周日 | 复盘 | 复习本周内容，整理笔记；在 CTFHub 上做一道 misc 签到题 | CTFHub |

周六是全周唯一「必须动手」的日子，周日是全周唯一允许失败的日子。这两条是我后来才想明白的：把实操压到一天，其余六天就不会骗自己说「看懂了」；把复盘固定下来，才不会攒到某周末一次性补——那种补法一次也没成功过。

## 第 15 周：从原理切到工具

| 时间 | 主题 | 具体任务 | 资源 / 工具 |
| --- | --- | --- | --- |
| 周一 | OWASP Top 10 | SQL 注入的原理与分类：联合查询、报错注入、布尔盲注 | 《Web 安全深度剖析》 |
| 周二 | 工具 | BurpSuite 拦 HTTP 请求，配浏览器代理，用 Repeater | BurpSuite |
| 周三 | 工具 | SQLMap 自动化检测与利用 | SQLMap 官方文档 |
| 周四 | 漏洞实操 | 在 sqli-labs 上做注入练习，手打和工具各来一遍 | sqli-labs、DVWA |
| 周五 | XSS 与 CSRF | 存储型 / 反射型 XSS 的利用差异，CSRF 的成因 | XSS-labs |
| 周六 | 综合渗透 | 起一台简单靶机（Metasploitable 这类），走信息收集 → 漏洞扫描 → 拿到 Web Shell | VulnHub、HackTheBox |
| 周日 | 复盘与报告 | 写一份渗透测试报告：漏洞点、利用过程、修复建议 | Markdown |

这一周唯一真正的产出是周日那份报告。工具用熟了不等于会做安全，报告写不出来就说明前面六天只是在点按钮。修复建议那一栏最难写，因为它要求你知道这个漏洞在真实业务里会被怎么滥用——这恰好是靶场给不了的东西。

## 第 40 周：内网、防御和应急响应

| 时间 | 主题 | 具体任务 | 资源 / 工具 |
| --- | --- | --- | --- |
| 周一 | 内网基础 | Windows 域环境概念、活动目录（AD）与工作组的区别 | 《内网安全攻防》 |
| 周二 | 内网信息收集 | 用 `netstat` `ipconfig` `net view` 收集拓扑信息 | CMD / PowerShell |
| 周三 | 权限提升 | 本地提权、令牌与会话机制、凭据保护的原理 | Windows 内部资料 |
| 周四 | 防御 | 防火墙规则、IDS/IPS 告警原理、Windows 事件日志分析 | Wazuh |
| 周五 | 应急响应 | 走一遍安全事件处理流程，分析勒索与挖矿样本的行为特征 | Process Monitor |
| 周六 | 红蓝对抗 | 本地搭一套域控环境，红队尝试渗透域控，蓝队配 GPO 防御 | 本地域环境 |
| 周日 | 合规与复盘 | ISO 27001 与等级保护 2.0 的基础条款 | 公开标准文档 |

周三那天我只排了原理，没排工具，也没列具体利用链——这一周的目标不是「打进去」，是「知道它为什么能被打进去、以及防守方在哪一步能看见」。原计划里写得很清楚的一条约束我保留了：**所有实操只在本地隔离网络的靶场和自建域环境里做，不在物理机上直接实验，也不碰任何不属于我的系统。**合规那一栏放在周日也不是凑数，等保 2.0 那几条要求恰恰是防守方的验收标准，绕开它，前面所有技术都落不到工作里。

## 五条执行建议

1. **环境是前提**：第一周之前先把虚拟化和隔离网络配好。不要在物理机上做实验。
2. **不要只看不练**：每个命令都要自己敲一遍，看懂和会做之间差的是一整个周六。
3. **善用搜索**：报错是常态，会搜错误码比会背工具参数更基本。
4. **记笔记**：每个漏洞的复现过程和当时的命令都要落字，一周后你只会记得「我打过这个」。
5. **允许滑周**：某周有事就只完成周一到周五的理论部分，实操推到下周末。计划断了不等于作废，硬追才会作废。

## 这份计划现在走到哪了

计划就是计划，不是成绩单。现在能确认落到地上的只有第 1 周那两篇网络基础笔记——它们已经写完发在站里；Linux、数据库、抓包那几行和后面两段都还停在纸上。我把它发出来的一部分原因就是这个：一张还没执行完的表放在本地文件夹里，永远不会有人知道它走到哪了。

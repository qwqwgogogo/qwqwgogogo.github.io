## 为什么必须有接口

外设在工作方式、数据格式和工作速度上与 CPU、主存差别巨大。主机部件用高速元器件，各有自己的时钟与独立的时序控制，与外设之间是完全异步的工作方式：打印机慢、数据格式是特定的打印指令，内存快、数据以二进制形式存放。要解决同步与协调、速度匹配、数据格式转换这三件事，就得在外设与主机之间加一块逻辑部件，这就是外设的 I/O 接口，也常写作 I/O 模块。

接口像翻译兼协调员：把主机发出的高速复杂指令和数据转换成外设能够理解执行的形式，再把外设的反馈与数据转换回主机能处理的格式。各种 I/O 控制器、设备控制器（包括适配卡、适配器）都属于 I/O 接口这个范畴；在大型机里，I/O 模块甚至承担大量复杂的外设控制任务，等同于一台专门处理外设事务的小处理器。

## 两个侧面与四项职能

接口有主机侧与外设侧两个接口。内部接口通过 I/O 总线与 CPU、主存相连，外部接口通过各种电缆连到外设，二者合起来在 CPU、主存与外设之间建立起信息传输的通路。

四项职能对应四类硬件：

| 职能 | 硬件 | 说明 |
| --- | --- | --- |
| 数据缓冲 | 数据缓冲寄存器 | 主存与 CPU 快、外设慢，用缓冲区让两边按各自速度工作，避免数据堵塞或丢失 |
| 错误与状态检测 | 状态寄存器 | 保存设备是否完成、是否准备好、是否出错等信息供 CPU 查询 |
| 控制与定时 | 控制逻辑与定时电路 | 接收总线上的控制命令与定时信号，规定通信过程中动作的先后关系 |
| 数据格式转换 | 串并转换等部件 | 外部接口格式与内部接口格式互转，例如磁盘读写数据在控制器里做串/并转换 |

设备出错分两类：一类是电路故障等异常情况，一类是数据传输错误，后者可以通过字符校验码检出。状态寄存器的价值就在于让 CPU 不必猜设备状态，读一下就知道该等、该发、还是要处理故障。

## 通用结构

不同接口在控制外设的数量、传输速度、格式处理能力和与主机交互的复杂性上各不相同，但通用结构大体一致，主机侧通过 I/O 总线连内存和 CPU，设备侧通过电缆连外设。

- **数据缓冲寄存器**：暂存数据，用来适应主机与外设之间的速度差异。
- **状态寄存器与控制寄存器**：前者记录设备是否准备好接收、是否有数据可读、是否出错；后者接收 CPU 的启动、停止、参数设置等命令。有的设计把两者合并成一个寄存器以节省硬件资源。
- **地址译码与 I/O 控制逻辑**：译码逻辑分析总线上的地址信号，判定当前被访问的是哪台设备、哪个寄存器；控制逻辑协调数据流向、产生控制信号并做错误检测。
- **数据线、地址线、控制线**：数据线传内容，地址线选对象，控制线带读/写、中断请求等信号。
- **设备侧电缆**：USB 线、IEEE 1394 线、串行或并行电缆、网线、SCSI 电缆等。

## 状态寄存器与控制寄存器的关系

传送方向相反：状态寄存器把来自外设或接口内部的状态信息交给 CPU，控制寄存器把来自 CPU 的命令交给外设或接口内部逻辑。访问时间通常错开：CPU 要交替地读状态、写命令，两类操作在时间上是分开的，这种错开正好保证数据传输顺畅、系统稳定。合并设计可行但要付出代价：为了简化结构、节省资源，两者可以合并为一个寄存器，前提是接口里必须有一套机制区分当前这次访问是在读状态还是在写命令。

判断读写方向靠的就是控制线：写信号有效时数据由主机进接口，读信号有效时数据由接口出主机，这两个信号还可以直接参与地址译码，比如用写信号选中接收寄存器、用读信号选中发送寄存器。

## I/O 总线与接口之间怎么交互

早期 I/O 总线是并行的，一组共享的地址线、数据线、控制线承担主机与设备之间的全部通信，接口里每个可访问的寄存器都有自己的地址。总线的信号至少包括四类：地址线指定要访问哪个寄存器，读/写控制信号说明是取还是放，仲裁信号在多个设备同时请求时决定谁先使用，握手信号在设备与 CPU 之间建立同步，例如设备准备好后发一个信号、CPU 确认后再传。

一次完整交互可以拆成六步：

1. **地址译码**：接口控制逻辑解码地址线上的信息，判断本次访问指向数据寄存器、状态寄存器还是控制寄存器。
2. **读/写控制**：写信号把主机数据送进数据缓冲寄存器，读信号把寄存器内容送向主机。
3. **命令字译码**：CPU 的命令编码成命令字写入控制寄存器，接口逻辑译码后确定要执行的具体操作。
4. **数据传输**：主机到外设方向先写缓冲寄存器再经外设接口逻辑送出；外设到主机方向先读入缓冲寄存器再经数据线交给主机。
5. **状态收集**：状态寄存器汇集设备是否就绪、是否有数据、是否出错，由主机读状态端口获得。
6. **握手与仲裁**：并行总线上用应答信号协调传输，用仲裁信号决定谁获得总线。

并行 I/O 总线直观易实现，但共享性质让多设备同时访问时可能冲突，且线宽与线长限制了速率提升，因此现代系统更多改用串行总线。

## 具有主控能力的接口

普通接口只能被动响应 CPU 的读写。当一个接口具备主控能力，例如 DMA 控制器，它能够自主发起总线事务并控制数据传输，不需要 CPU 直接干预。这时控制线上的信号改由 DMA 控制器生成，地址线的方向变成从 DMA 控制器输出到总线，用来指定数据传输的源地址或者目的地址。处理大量数据时这种能力价值最大：CPU 可以同时执行其他任务，形成真正的并行。

## 底层 I/O 软件看到什么

程序员通常不需要了解外设的机械或者物理特性，比如磁盘转速、磁头移动方式、网络信号的传输介质——这些细节被封装在硬件和接口内部。这种抽象让软件开发更简单，系统更好维护和扩展。

要写底层 I/O 软件，需要知道三件事：设备控制器提供给 CPU 访问的有哪些寄存器、它们的地址与功能；控制寄存器与状态寄存器里每一位的含义；接口与外设之间通信的电气特性与协议，包括信号时序、数据格式和错误处理机制。

操作方式只有三条：向控制寄存器写入特定值来启动或者控制外设，例如开始读取、停止设备、设置传输速率；读状态寄存器掌握外设与控制器的当前状态，判断能否安全收发、是否需要处理错误；直接读写数据缓冲寄存器完成数据的输入与输出。访问这些端口靠专门的 I/O 指令，例如 x86 里的 IN 与 OUT 指令，前者从指定端口取数据到寄存器，后者把寄存器数据写入指定端口。因为这类操作会影响系统稳定性与安全性，所以它们属于特权指令，只能在内核模式执行，普通应用程序不能直接访问硬件，这既防止误操作也防止恶意程序破坏。端口地址必须在系统初始化时正确配置，通常由固件或者操作系统在加载阶段完成。

## I/O 端口及其编址

所谓 I/O 端口，实际上就是 I/O 接口里那些可被 CPU 访问的寄存器：数据缓冲寄存器是数据端口，控制寄存器与状态寄存器分别是控制端口和状态端口。为了让 CPU 能快速选择设备并对端口寻址，必须给所有接口中可访问的寄存器编址。编址方式只有两种。

**独立编址**（也叫 I/O 映象方式、专用 I/O 指令方式）给端口一套独立于主存的地址空间。端口地址不占用存储空间，系统里存在一个与存储地址无关的 I/O 地址空间，CPU 必须具备专用的输入输出指令和配套控制逻辑。它的好处是端口地址不占内存容量、专用 I/O 指令短、执行快、程序里 I/O 操作清晰易读；毛病是 I/O 指令种类少，一般只能做基本的传送操作，而且 CPU 要提供存储器读/写与 I/O 读/写两套控制信号，控制更复杂。Intel 处理器就是这种方式：I/O 地址空间有 2 的 16 次方共 64K 个编号，每个编号对应一个 8 位端口，两个连续的 8 位端口可当一个 16 位端口使用，并配套提供 IN 和 OUT 指令。

**统一编址**（也叫存储器映象方式）把端口地址包含在主存地址空间里：从整个寻址空间中划出一部分给 I/O 设备，其余给存储器，靠地址码区分操作对象。端口与存储单元按同一套编址方法排列，共同构成一个统一的地址空间。好处是端口可用的编址空间大、易扩展，而且访存指令能用在端口上，指令丰富、功能齐全，连 AND、OR 这类逻辑指令都能直接操作控制或者状态寄存器；毛病是占用了存储器地址、有效容量减少，而且访存指令一般比专用 I/O 指令更长，访问端口的速度可能更慢。

| 对比项 | 独立编址 | 统一编址 |
| --- | --- | --- |
| 地址空间 | 端口与内存各一套，互不冲突 | 端口占用内存地址，混在一起分配 |
| 访问指令 | 必须有专用 I/O 指令 | 普通访存指令即可操作端口 |
| 硬件信号 | 需要区分访存与访端口的控制线 | 不需要这根线，但可用内存变少 |
| 指令能力 | 只能做基本传送，功能受限 | 任何对内存的运算都能对端口做 |
| 典型代表 | x86 的 IN、OUT 端口空间 | 把设备寄存器映射进内存地址空间 |

选择依据是需求：看重 I/O 操作速度与指令清晰就用独立编址，需要大编址空间与灵活的指令就用统一编址。实际系统里两种混用的情况不少，某些设备走独立编址、另一些走统一编址，兼取两者优点；Linux 既提供端口指令式的接口，也支持把设备寄存器映射进内存地址空间，两条路子都活着。

## 三个易错点

**把端口当成设备**。端口是接口里的寄存器，不是外设本体；一台设备通常有多个端口，一个端口只对应一次读写对象。

**混淆统一编址与共享地址空间**。统一编址并不意味着端口和内存单元可以互相替代，被划给端口的地址段就不能再放内存，这也是它减少存储容量的原因。

**以为独立编址不需要地址译码**。两种编址都要译码，区别只在译码是否还要参考那条区分存储器与 I/O 的控制信号。

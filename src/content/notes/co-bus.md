## 一句话

总线是**共享**的传输线：所有部件挂在同一组线上，同一时刻只能有一个发送者说话。共享带来省线，也带来两件必须解决的事——谁先说（仲裁）和怎么说（定时）。

## 三组线，按功能分

| 线组 | 方向 | 传什么 |
| --- | --- | --- |
| 数据线 | 双向 | 实际内容 |
| 地址线 | 单向 | 指向谁，根数决定可寻址范围 |
| 控制线 | 有入有出 | 读、写、中断请求、总线请求、时钟、复位 |

按连接范围分：**片内总线**在 CPU 内部连寄存器和 ALU；系统总线连 CPU、主存和 I/O 模块，通常又拆成数据总线、地址总线、控制总线；再往外是连接外设接口控制器的 I/O 总线，以及跨机器的通信总线。分层的原因是速度差：让慢设备去抢 CPU 到主存那条高速总线，整台机器都得跟着等。

## 带宽题

总线带宽就是单位时间能搬多少数据，算法是**宽度除以 8，再乘以每秒传输次数**：

```
带宽(B/s) = 总线宽度(bit) / 8 × 工作频率 × 每个时钟传输次数
```

三个坑：一是宽度指数据线根数，不是地址线；二是地址和数据**共用一组线**（复用）时，一次传输要先发地址再发数据，等效带宽直接对折；三是题目常给「一个传输周期占 n 个时钟」，那每秒传输次数就是频率除以 n，别把频率当传输次数。

时钟周期是最小的节拍，多个时钟拼成一个总线周期（也叫传输周期），几个总线周期拼成一个机器周期，一条指令由一到多个机器周期组成——这条链子背下来，凡是从频率推吞吐的题都能自己搭出来。

## 仲裁：谁拿到总线使用权

总线仲裁要解决的是多个设备同时请求总线时先满足谁，判据只有两种来源：固定的物理顺序，或者会轮转的计数。三种实现的成本差别就在多用了几根线。

链式查询把所有设备串在同一根优先级链上，离控制器越近的设备优先级越高，好处是线最少，坏处是一处断线后面的设备全部失声。

| 方式 | 线 | 特点 |
| --- | --- | --- |
| 链式查询 | 一根忙线 + 一根菊花链请求线 | 最省线；优先级由物理位置定死，排在最前面的设备天然最高；一处断线全盘失效 |
| 计数器定时查询 | 一根忙线 + 一组设备地址线 | 计数器从 0 数还是从上次的值继续数，决定了优先级是固定还是轮转，可用程序改 |
| 独立请求 | 每个设备各一对请求线、授权线 | 优先级随便定、响应最快，代价是线最多 |

**固定优先级**的毛病是饿死：总线一空闲，永远是最靠前的那个设备拿到。**轮转**（上次服务的下一个优先）保证没人饿死，代价是最坏延迟变大。

## 同步还是异步

同步通信由公共时钟定节拍：一次传输占几个时钟周期事先约定，控制器只管按点发，速度快、控制简单，但要求所有挂在这个总线上的设备速率接近，而且**最长的那台决定整体节拍**。

异步通信不设公共时钟，靠**请求—应答**握手：谁发数据就拉一次请求，收方准备好再拉应答。按应答之后的行为分三种：不互锁（发完请求就松手，最快，最不安全）、半互锁（收方的应答要等发方撤销请求才撤销）、全互锁（双方都要等对方撤销才撤销，最慢最可靠，用于距离不确定或速度差异极大的场合）。异步的长处是设备快慢不一也能凑一起用，短处是握手本身要花时间，延迟不可预测。

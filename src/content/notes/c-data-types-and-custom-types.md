## 先说清楚这一节要解决什么

数据结构课之所以先讲 C，是因为后面所有结构都要落到内存上：链表结点是一次 `malloc`，顺序表是一整块连续空间，树是结点之间互相指。C 的语法本身并不难，难的是它把「内存怎么规划」这件事完全交给了写程序的人。语言标准只规定下限和换算规则，具体宽度由编译器和目标平台决定，所以同一段代码在两块机器上可能得到两个不同的 `sizeof` 结果。

学习材料上，以程序语法为目标的教材适合在报错时按例子回查，专门讨论类型与内存的章节、指针专题和链接装载部分才是这门课真正需要的；剩下的函数与工程化内容属于项目组织层面，可以往后放。工具链方面没有硬性版本要求，主流平台各自的 GNU 与 LLVM 编译器都能用，IDE 只是编辑器、编译器、调试器的打包，不参与语言规则的制定。

## 数据类型是什么

**数据类型是编译器用来解释一段内存的约定，它同时规定了这块空间有多宽以及能对里面的值做哪些运算。** 早期编程直接和存储地址打交道，数值和字符在机器里都只是 0 和 1，取错地址或者对字符做乘法都不会被拦住。引入类型之后，程序员声明一个容器，地址分配和运算合法性检查都交给编译期去做，这就是类型的全部意义：它是一个容器，容器有宽度，宽度决定容量上限。

在内存里，能被独立寻址的最小单位是字节；磁盘上的最小读写单位是块，通常是 512 字节；网络上传递的最小单位是比特。这三个数字经常被混为一谈，而 `sizeof` 量的永远是第一类——内存字节数。

**sizeof 是一个编译期就能算出结果的关键字，它返回的是这个类型或这个对象实际占用的字节数。** 它不做除法、不检查边界，只是把布局信息取出来。要注意 `sizeof` 作用于数组名和作用于指针时结果完全不同，这一点在数组与指针那节里展开。

C 的类型分成两大族：基本类型和自定义类型。基本类型是语言自带的容器，宽度只有 1、2、4、8 字节这几种量级；自定义类型是程序员用说明符把已有成员组合出来的新容器。

## 语言标准只规定下限

跨平台代码最容易出问题的是假设某个类型「就是 4 字节」。标准里的约定是相对顺序而不是绝对宽度：**ISO C90 规定 `char` 是 1 字节，`short` 不小于 `char`，`int` 不小于 `short`，`long` 不小于 `int` 且至少 4 字节，`long long` 至少 8 字节。** 换句话说，`int` 在某个编译器上是 2 字节还是 4 字节都合规，`long` 在 Linux 的 GCC 上是 8 字节、在 Windows 的编译器上是 4 字节也都合规。

要写死宽度就得靠 typedef 和固定宽度的整数别名。**typedef 只是给已有类型起一个别名，它不产生新类型，也不改变任何宽度，但用它把宽度写死之后，跨平台移植就只剩一处要改。** 需要精确 64 位时，与其赌 `long` 的宽度，不如统一用一个明确指向 8 字节整型的别名，换平台时只调整这一条声明。

## 整型：常量、变量与字符表示

整型常量在源码里有两套写法。一套是进制表示：十进制、八进制、十六进制三种字面量指向同一个内存值，写法只影响人怎么读。另一套是字符表示：**字符常量在内存里存的就是它的 ASCII 码值，因此字符和整数之间可以直接参与同一套算术运算。** ASCII 有几个常被拿来出题的性质：数字字符 `'0'` 到 `'9'` 连续，大写字母比对应的小写字母小 32，空格是 32，而 0 到 31 这一段是不可打印的控制字符，只能用转义写法表示。可打印字符占据中间那段编码，字符常量写成 `'A'` 和写成 65 在存储层面没有区别。

整型变量本身没有神秘之处：**给一块内存空间起一个程序里方便访问的名字，这就是变量的定义动作。** 声明只告诉编译器容器多大，不保证里面的初值有意义；不初始化就读，读到的是那块地址上原本残留的位模式。

## 赋值与运算：截断、补位、有无符号

C 里的赋值号不做算术，它规定的是一个内存动作：**把等号右边那块内存里的位逐位拷贝到等号左边那块内存里。** 两边宽度不一样时，就必然多出一块或者少一块，于是产生两种行为。

**把宽类型的值交给窄类型变量时，超出的高位会被丢掉，这种行为通常称为截断。** 截断不报错，低位保留、高位消失，数值和符号都可能变。**反过来把窄类型赋给宽类型时要在高位补出若干位，无符号数补 0，有符号数补的是符号位，这个动作叫补位。** 补位规则决定了「小容器装大容器」是安全的，而「大容器装小容器」是否安全取决于有没有符号位。

运算层面同样按有符号和无符号分两套：

| 场景 | 有符号数 | 无符号数 |
| --- | --- | --- |
| 宽赋窄 | 高位丢弃，符号可能反转 | 高位丢弃，值取模 |
| 窄赋宽 | 高位补符号位 | 高位补 0 |
| 右移一位（除以 2 的位操作） | 高位补符号位 | 高位补 0 |
| 加满溢出 | 行为未定义，实际按补码回绕 | 明确对 2 的幂取模 |

乘除法按算术规则走，而位运算直接作用于位模式，所以同一个右移动作在两种类型上结果不同。混合运算更要注意：一旦表达式里同时出现有符号和无符号操作数，无符号数的「等级」更高，有符号的那一侧会先被转换成无符号，于是一个本该是负数的操作数变成一个极大的正数，比较运算的结果随之翻掉。这类问题不是编译错误，而是逻辑错误，是整数题里最典型的失分点。

浮点类型默认占 4 字节，双精度占 8 字节。**浮点数的精度问题来自二进制小数无法精确表示某些十进制分数**，能精确表示的只有分母是 2 的幂的那一类。因此浮点比较不能用等号，累加顺序会影响结果，误差随运算次数累积。

## 结构体：累加组合

结构体不是数据类型，它是一个说明符，作用是把若干已有成员按累加规则拼成一个新容器，并告诉编译器这块内存怎么规划。声明只描述布局，定义才真正分配空间；访问成员用点号，通过指针访问用箭头。

**字节对齐要求每个成员的起始地址是它自身对齐值的整数倍，编译器为此会在成员之间插入填充字节。** 默认规则下，成员的排列是从当前地址往后找到第一个满足对齐要求的位置，整个结构体的大小还要是最大成员对齐值的整数倍，所以尾部也可能出现填充。把三个成员按「1 字节、2 字节、4 字节」的顺序排和按「4 字节、1 字节、2 字节」排，占用空间可以差出一倍——**成员的声明顺序本身就是布局的一部分**，这不是风格问题而是内存问题。

想让编译器放弃填充，可以用预处理的方式指定按几字节对齐，代价是访问效率下降，某些架构上还会引入非对齐访问的限制。

当一个成员只需要几个比特时，为它分配一整个字节很浪费。**位域把若干个小整数字段压进同一个存储单元，用冒号后面跟一个数字声明它占几位，常见于状态标志和硬件寄存器映射。** 位域内部的排列顺序同样依赖实现，所以它适合在单个平台内部使用，不适合当作跨平台的存储格式。

## 共用体：共享组合

共用体和结构体的语法几乎一样，区别全在内存上：结构体是累加组合，共用体是共享组合——所有成员从同一块起始地址开始摆放，整体大小取最大成员所需的空间。

**共用体是为了达到底层连续区域访问的特殊行为而设计的**，典型用途是把同一块字节分别按不同宽度解释，或者在确定当前存放的是哪一种成员的前提下节省空间。它不提供任何「记录当前存的是哪个成员」的能力，读一个从未写过的成员得到的是位模式的重新解释，这是它最容易出错的地方。

## 枚举：一个失败的类型

枚举看起来是第三种自定义类型，但它在类型检查上的表现远不如前两者：**枚举本质上就是一个整型，标准并没有要求编译器禁止把其它整数赋给枚举变量，所以它被称为一个失败的类型。** 枚举真正提供的只有两件事——给一组相关的整数常量起可读的名字，以及让第一个成员默认从 0 开始依次递增。既然底层仍是整数，比较、赋值、越界取值都不会被拦住，用它做「有限状态」的约束时必须自己保证合法性。

## 对照着背

| 概念 | 一句话口径 |
| --- | --- |
| 类型 | 解释内存的约定，规定宽度和允许的运算 |
| 标准规定 | 只给宽度下限和相对顺序，不给绝对字节数 |
| 赋值号 | 右块内存逐位拷贝到左块内存 |
| 宽到窄 | 高位丢弃，即截断 |
| 窄到宽 | 高位补符号位或补 0，即补位 |
| 结构体 | 成员累加摆放，受对齐规则支配 |
| 共用体 | 成员共享同一起始地址 |
| 枚举 | 底层是整型，没有类型限定约束 |

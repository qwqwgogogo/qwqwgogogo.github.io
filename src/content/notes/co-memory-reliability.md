## 一句话

层次结构前面所有的讨论都在算速度，但存储器还有一条底线：**它存的东西必须是对的**。一位数据悄悄翻了个面，命中时间再短也只是更快地拿到错误答案。提高可信度的办法只有一类——用冗余换检错和纠错的能力。

## 先分清三个词

系统面向用户时只有两种状态：提供的服务和用户需求相符，叫**服务实现**；对不上，叫**服务中断**。

- **失效**：从服务实现滑到服务中断这件事本身。
- **恢复**：从中断状态回到实现状态的过程。

失效按能不能自愈再分两类。**间歇性失效**在正常与异常之间来回跳，症状时有时无，最难诊断——日志、监控、故障注入都得用上，它还会带来数据不一致和不可预期的响应。**永久性失效**一旦发生就不会自己恢复，必须维修或更换；它反而好判断，代价是系统设计时就得备好冗余，否则服务连续性直接断掉。

## 可靠性与可用性的量

**可靠性**关心「能连续正确工作多久」，用平均无故障时间 MTTF 度量，即从开始运行到首次故障的平均时长，MTTF 越长越可靠。当 MTTF 大到不好读时，业界更常用年失效率 AFR，直接给出一年的预期失效概率，横向比较不同器件时更直观。

**可用性**关心「用的时候它在不在」，它把故障停机、计划内维护、升级等所有不可用时间都算进去，通常写成百分比：

```
可用性 = (运行时间 - 停机时间) / 运行时间 × 100%
```

维修这一侧的指标是平均修复时间 MTTR；平均故障间隔 MTBF 描述连续两次故障之间的平均时长，等于 MTTF 加上 MTTR。现代可靠性工程的口径更倾向直接用 MTTF，避免 MTBF 在含维修时间时引起的混淆。

把三者串起来：

```
可用性 = MTTF / (MTTF + MTTR)
```

这个式子说明提高可用性只有两条路：**把 MTTF 拉长，或把 MTTR 缩短**。前面讲的都是怎么拉长 MTTF，后面要讲的冗余编码则同时改善两头——它既能让错误不发生（纠正掉），也能让故障更快被发现。

## 三类手段

**故障避免**：从设计、材料、制造、软件测试入手，减少零件数、用成熟工艺、留足散热，把故障概率压到源头。

**故障容忍**：假定故障一定会发生，靠冗余让系统照样运行。硬件上是磁盘镜像、RAID、双电源、多路径网络；信息上是校验码，ECC 内存和奇偶校验码就属于这一类；软件上是多重实例和热备份，主服务出问题自动切到备用。

**故障预报**：传感器和监控持续采集温度、电压、电流、负载，用数据分析识别劣化的早期趋势，在到达故障阈值前预警并安排预防性维护——本质上是把 MTTR 里「发现故障」那一段提前做掉。

还有一个更虚的维度叫可信性，它不止是「不坏」，还包括用户是否信任系统能始终正确地完成任务，涉及安全性、隐私和数据完整性，靠设计原则和合规验证来保证，而不是靠一条公式。

## 冗余编码怎么开始：汉明距离

两个等长二进制串之间不同位的个数叫汉明距离。码字之间**最小的**汉明距离决定这套编码的检错纠错能力，这是所有编码分析的起点。

判据是：要检测 e 个错、同时纠正 t 个错，需要最小汉明距离 `d ≥ e + t + 1`。

- 只想发现一位错：`d = 2` 就够——出错后的串离原码字距离 1，不会撞成另一个合法码字。
- 想纠正一位错：`d = 3`——出错后仍能唯一地认出最近的那个合法码字。
- 想纠一位错同时检测两位错：`d = 4`。

只把 `d` 做到 2 是不够的，因为它分不清「某一位错了」和「另一位错了」，也分不清一位错还是两位错。纠错必须有足够的距离余量。

## 奇偶校验：最便宜的 d=2

在数据位之外加一位校验位，使整个码字里 1 的个数满足约定：**奇校验**凑成奇数，**偶校验**凑成偶数。读出时重算一遍，奇偶性不对就说明出错了。

它的能做的和不能做的都很清楚：

- 能检测奇数个比特翻转。
- 检测不出偶数个比特翻转——两位同时翻，奇偶性没变。
- 就算报了错，也说不出是哪一位错的，只能请求重传。

代价是一位冗余，收益是一半的错能被发现，因此在总线传输、串口、磁盘扇区的字段校验里到处都在用。它是「检测」，永远不是「纠正」。

## 汉明码：把校验位放在 2 的幂上

汉明码的做法是把多个校验位交错插进数据位里，让每个校验位负责一片位置的奇偶性，出错时把各校验位的结果拼成一个二进制数，直接指出错在哪一位。

排布规则是：**位号为 2 的幂（1、2、4、8…）放校验位，其余放数据位**。第 k 个校验位负责那些「位号二进制表示中第 k 位为 1」的位置。4 个数据位需要 3 个校验位，正好由这个不等式定下来：`2^k ≥ n + k + 1`，n 为数据位数，k=3 时 `8 ≥ 8` 成立。

7 位码字的排布：

```
位号   1   2   3   4   5   6   7
内容   P1  P2  D1  P3  D2  D3  D4
```

覆盖关系（偶校验）：P1 管 1、3、5、7；P2 管 2、3、6、7；P3 管 4、5、6、7。

代入 `D1 D2 D3 D4 = 1 0 1 0`：

```
P1 = D1 ⊕ D2 ⊕ D4 = 1 ⊕ 0 ⊕ 0 = 1
P2 = D1 ⊕ D3 ⊕ D4 = 1 ⊕ 1 ⊕ 0 = 0
P3 = D2 ⊕ D3 ⊕ D4 = 0 ⊕ 1 ⊕ 0 = 1
```

发出码字为 `1 0 1 1 0 1 0`。

接收端重新算三个校正子 `S1 S2 S3`，都正确时全 0；若第 5 位被翻转，收到 `1 0 1 1 1 1 0`，则：

```
S1 = 位号含 1 的那几位异或 = 1⊕1⊕1⊕0 = 1
S2 = 1⊕1⊕1⊕0 = 0
S3 = 1⊕1⊕1⊕0 = 1
```

校正子按 `S3 S2 S1` 读作二进制 `101`，也就是十进制 5——出错位置正是第 5 位，把它翻回来即可。**校验位的个数决定能表示多少个「无错 / 第几号位错」的状态**，这也是汉明码只需要三位冗余就能定位七位里任意一位的原因。

## 纠一位、检两位

基本汉明码的 `d = 3`，只能纠一位错，两位错会被它误判成某个一位错并「纠正」成另一个错误结果。解决办法是在汉明码之外**再加一个覆盖全码字的总奇偶校验位**，最小距离从 3 提升到 4：三个校正子定位错在哪一位，总校验位判断到底有没有发生偶数位错。

代价是校验位要多一位，但收益是「纠一位」和「检两位」能同时做到，这正是 ECC 内存的标准做法。它的必要性来自真实的故障形态：存储器里的错既有孤立的单比特翻转，也有一个字线故障引起的多位同时坏——只防前一种的编码在服务器上不够用。

## 一个可用性的算例

某器件标称 MTTF 为一万小时，出故障后平均要花两小时定位并更换，那么

```
可用性 = 10000 / (10000 + 2) ≈ 99.98%
```

也就是每 5000 小时的运行里大约有 1 小时不可用。把同样的目标换成「四个 9」的口径，允许的停机时间立刻被压缩到小时级以下，单靠缩短 MTTR 是达不到的——这时唯一现实的做法是加冗余，让一个部件坏掉时服务不停。

反过来的算例同样常考：要一个 16 位的数据字能纠一位错，需要几个校验位？代入不等式 `2^k ≥ n + k + 1`，n=16 时 k=5 才满足（`32 ≥ 22`），k=4 时 `16 < 21` 不够。所以 16 位数据要配 5 位校验，一共 21 位。**校验位数量随数据位只对数增长**，这就是纠错码在大字上摊薄成本、在小字上显得昂贵的原因。

## RAID 和 ECC 是同一件事的两个尺度

前面那些编码处理的是一位到几位的翻转，把同一思路放大到设备尺度，就得到磁盘冗余的做法。

**镜像**把同一份数据写到两块盘上，坏一块不影响读取，代价是容量减半。**带奇偶校验的条带**把数据切成条带分布到多块盘，另设一块盘存各条带的异或值，坏任一块都能用其余盘的值异或恢复出来，代价是只多花一块盘的容量。**分布式奇偶**再把校验值也摊到所有盘上，避免出现那块永远在写的瓶颈盘。

这三档的取舍和汉明码里「加一位还是加三位」是同一种权衡：冗余越多，能容忍的同时故障越多，可用空间和写入开销也越大。选择依据只有一个——这套系统需要扛住几个部件同时坏。

## 把 MTTR 缩短的那一半

提高可用性的一半工作其实不在「少坏」，而在「坏得容易被发现、发现后好修」。

磁盘把温度、起停次数、重映射扇区数这些计数器持续记在自己的自检数据里，控制系统定期读它们，一旦发现重映射扇区在增长，就能在一块盘真正失效之前把它换掉——这是故障预报最典型的落地形态：牺牲一点点可用容量，换掉一次服务中断。

间歇性失效之所以难对付，也正因为它是「发现」这一段在拖后腿：故障不复现，就没有可修的现场。工程上的应对是把它转成可观察的对象，用持续的参数采集把偶发异常钉成趋势，再用故障注入去复现那条路径。诊断时间从几天压到几小时，MTTR 就跟着压下来了。

## 回到层次结构

这一篇的东西落在哪几层，是可以逐个指认的：主存用 ECC 内存防单比特错；磁盘扇区里除了数据还留着标识、间隔和纠错码；闪存控制器一边做磨损均衡一边用 ECC 检测和纠正失效单元，并把制造时就有缺陷的单元标成不可用，从而抬高成品率；再往下，RAID 和磁盘镜像用整块磁盘的冗余来对抗永久性失效。

层次结构讲「快」，可信性讲「对」。两者叠加，才是这台机器真正能用的原因。

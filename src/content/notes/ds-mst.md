## 生成树：定义和六条性质

一个连通图的生成树是极小的连通子图，它含有图中的全部 `n` 个顶点，但只有足以构成一棵树的 `n-1` 条边。三个顶点的完全图就有三棵互不相同的生成树；`n` 个顶点的无向完全图，生成树最多有 `n^(n-2)` 棵。

把性质列全，答题时逐条对照：

| 性质 | 说明 |
| --- | --- |
| 可以有多棵 | 同一张图按不同走法能得到不同的树 |
| 顶点数、边数固定 | 任何一棵生成树都是 `n` 个顶点、`n-1` 条边 |
| 树内无环 | 生成树本身就是一棵树 |
| 边最少 | 删掉任意一条边就不再连通 |
| 加边必成环 | 在生成树上补任意一条原图中的边，一定出现环 |
| 完全图上限 | 最多 `n^(n-2)` 棵 |

## 先明确目标

只有带权图才谈最小生成树：在所有生成树里，边的权值之和小于或等于其它任何生成树权值之和那一张，就是最小生成树，缩写 MST；不带权的连通图只能谈生成树。它不是一棵「路径最短」的树——两点之间在树里绕的路可能比图上直接的那条边长得多，MST 优化的是**总的建造成本**，例如铺线缆、修路。

两个立刻能答题的性质：MST 的边数一定是顶点数减一；如果所有边的权值互不相同，最小生成树是唯一的（权值有相等时可能有多棵树，但它们的权值之和相同）。

判定的依据只有一条：**对任意把顶点分成两半的割，横跨这个割的那些边里权值最小的那条，一定属于某棵最小生成树**。两个算法就是各自用不同的方式反复用这条性质。

## Kruskal：从一堆边里挑

具体做法是：先把所有边按权值非递减排好序，然后依次考察，每拿一条边先判断它会不会和已经选中的边构成环，不成环就收下，直到取满 `n-1` 条边。Kruskal 每步只挑当前最短且不造成环的那条边，这种取法正是贪心算法的典型形态。

算例：九个顶点 `V0` 到 `V8`、十五条带权边，按权值排好是 1、2、3、4、5、6、6、7、8、9、10、11、12、14、18。依次收下不成环的边，得到 `V4-V7`(1)、`V2-V8`(2)、`V0-V1`(3)、`V0-V5`(4)、`V1-V8`(5)、`V3-V7`(6)、`V1-V6`(6)、`V6-V7`(9) 共八条，正好是顶点数减一，权值之和 36。轮到 `V5-V6`(7) 和 `V1-V2`(8) 时，两端已经连通，加上就成环，只能舍弃。

课件判断成环用的是「终点」数组：顶点按编号存进一个数组，另建一个等长的终点数组，每个顶点的终点定义为「与它连通的最大顶点」，初始时各顶点的终点就是它自己。考察边 `X-Y` 时比较两端的终点，相同则成环、舍弃；不同则收下这条边，并把该连通块里所有顶点的终点刷新为较大的那一个。整个例子十步走下来，终点数组随着合并不断被刷新，最后一次更新后所有顶点的终点相同。

瓶颈在两处：排序，以及「两点是否已连通」的判断。用并查集维护连通块，每次合并就是两次找根加一次连接，近似常数，于是整体是「边数乘边数的对数」这一量级——**跟顶点数无关**。稀疏图（边数远小于顶点数的平方）就选它。把边按权值排好之后存放在边集数组里逐条考察，是它最常见的实现方式。

## 贪婪算法：两个算法共同的思想底色

克鲁斯卡尔的做法可以抽象成一种更一般的策略，即贪心算法（也叫贪婪算法）。它的思想是：总是作出在当前看来最好的选择，不从整体最优加以考虑，只保证每一步是局部最优，并期望最终结果也是整体最优。

它有两个基本要素。一是贪心选择性质——整体最优解可以通过一系列局部最优的贪心选择来达到；这也是它与动态规划的主要差别：动态规划自底向上，贪心自顶向下，以迭代方式相继作出贪心选择，把问题简化为更小的子问题，而且每一步的贪心选择都要证明能够导向整体最优。二是最优子结构性质——问题的最优解里包含其子问题的最优解，这是一个问题能用动态规划或贪心求解的关键特征。

基本思路是从某个初始解出发，逐步逼近给定的目标，以便尽快求出更好的解；当搜索到某一步无法再向前推进时就停止。它的局限也要写清楚：不能保证最后得到的解是最佳的；不能用来直接求最大解或最小解；只能求出满足某些约束条件的可行解的范围。实现过程可以写成一句伪代码——从初始解出发，只要还能朝总体目标前进一步，就从可行解的解集中取出一个解元素，最后由全部解元素组合出可行解。

贪心法能拿整体最优的两个标准例子，就是单源最短路径和最小生成树；即使得不到整体最优，它也常常给出最优解的一个很好的近似。

## Prim：从一棵树往外长

Prim 把顶点分成两类：已经在生成树里的 A 类和还没进去的 B 类。初始时全部顶点都在 B 类；任选一个顶点从 B 移到 A，此后每一步都在「B 类顶点到 A 类顶点」的边里挑权值最小的那条，把对应的 B 类顶点移进 A，直到 B 类为空。走过的顶点和走过的边合起来就是最小生成树。

换成更常见的表述：任选一个顶点作为初始树，每次在所有「一端在树内、一端在树外」的边里挑权值最小的，把那个树外的顶点拉进来。要高效找出这个最小值，就给每个树外顶点维护一个「到树的最短距离」，每加一个顶点就更新它邻接的那些——这套维护法跟 Dijkstra 的框架几乎一样，差别只在松弛的比较对象。

同一张九顶点的图，Prim 用邻接矩阵表示，无边处记为无穷大。从 `V0` 出发：邻接点里 `V1` 是 3、`V5` 是 4，先收 `V1`；此后候选中最小的是 `V5`；接着依次是 `V8`、`V2`、`V6`、`V7`、`V4`、`V3`。顶点进入的顺序为 `V0`→`V1`→`V5`→`V8`→`V2`→`V6`→`V7`→`V4`→`V3`，权值之和同样是 36——两个算法走的路不同，总成本一致。

用邻接矩阵实现，总代价是顶点数的平方，**与边数无关**。所以稠密图上 Prim 占便宜：边多到接近完全图时，按边排序的代价反而更大。

## 选哪个

| | Prim | Kruskal |
| --- | --- | --- |
| 每步做什么 | 找离当前树最近的顶点 | 找不构成环的最短边 |
| 出发点 | 顶点 | 边 |
| 时间量级 | 顶点数的平方 | 边数乘边数的对数 |
| 适合 | 稠密图 | 稀疏图 |
| 需要的数据结构 | 顶点到树的距离数组 | 边集数组加并查集 |
| 中间结果 | 始终是一棵树 | 是一片森林，逐步合并 |

最后一条差别常被考：Kruskal 的过程里始终维持的是生成森林，中途拿到的并不是一棵树；Prim 每一步都保证自己手里那部分已经是一棵连通树。

## 这一节到底在解决什么

给定一个带权连通图（连通网），在众多的生成树里筛出权值总和最小的那一棵，就是这一节的全部目标。Kruskal 从边的角度出发，用贪心反复选边；Prim 从顶点的角度出发，逐步找出与已选顶点集合相连的最小权值边。

实际场景都是「把若干个点连起来、总造价最低」：架设网线时顶点是城市、边是通信线路、权是线路长度或造价，要求出总代价最小的方案；给一片房子拉最少的电线让每家都通电；铺设道路；以太网桥接的自动配置要选出无环的转发拓扑以避免环路；聚类算法里也可以先按相似度建树再砍掉最长的边。此外它还出现在纠错码编码、图像配准、序列数据存储、粒子交互局部性模拟这类研究问题里。

## 两个一定会错的点

第一，权值有相等时「最小生成树唯一吗」——不唯一，但**总权值唯一**，所以「算出来的权值和不同就是写错了」是对的自查手段。第二，图不连通时根本不存在生成树，只有各连通分量各自的最小生成树，合起来叫最小生成森林；拿到题目先确认连通性，别默认。

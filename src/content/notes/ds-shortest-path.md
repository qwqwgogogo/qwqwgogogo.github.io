## 源点、终点与最短路径

一条路径起始的第一个顶点称为源点，最后一个顶点称为终点。图中任何一个顶点都可以充当源点，也都可以充当终点，这两个名字只是相对某一条具体路径而言的说法。

对无向图来说，从源点到终点的最短路径是所含边数最少的路径。无权图不需要动用带权算法：从源点做一次广度优先搜索，一旦遇到终点就终止搜索，走过的层数就是路径长度。例子是一张九个顶点的图，按层展开依次得到 `V0`；`V1`、`V2`；`V3`、`V4`、`V5`；`V6`、`V7`；`V8`，于是 `V0` 到 `V8` 的最短路径是 `V0`→`V1`→`V3`→`V6`→`V8`。

带权图上的最短路径指的是那条**路径上各边权值之和最小**的路，不是边数最少，也不要求唯一。题目形态有两种：单源最短路径（一个起点到所有其它顶点）和每对顶点之间的最短路径。前者用 Dijkstra，后者用 Floyd——**这两个名字怎么选，取决于「几个源点」**，这是最直接的判据。

两种算法都建立在同一个动作上：如果经过某个中间顶点能让距离变短，就用更小的那个值更新记录，这一步叫松弛。

## 最短路径有什么用处

换乘次数最少或者耗时最少的出行路线，本质就是带权图上的最短路径问题；导航系统底层的道路规划同样落在这类问题里。这类应用决定了算法往往要一次回答「从这个起点到其余每个顶点各要多久」，也就是单源到全部顶点，而不只是两点之间那一条。

## Dijkstra：贪心加一个「已确定」集合

维护两个距离：已经确定最短路的顶点集合，以及每个未确定顶点「从起点出发、只经过已确定顶点、再最后一步直达它」的距离。每轮从未确定的里面挑距离最小的那个，宣布它已确定，然后用它去松弛自己的邻居。

它为什么正确，靠的是一个前提：**所有边权非负**。因为非负，所以「现在看起来最短的那个」不可能再被别的路绕得更短——任何绕路都要多付非负的代价。一旦允许负权边，这个前提就塌了：某个已确定的顶点可能被一条经过它的负权边变得更短，而算法已经不再回头看它，结果就错。

Dijkstra 的实现靠三个辅助向量。辅助向量 `D`：`D[i]` 记录当前找到的从源点 `v` 到 `Vi` 的最短路径长度，初值取源点到各顶点的直接边权，没有边就置为无穷大。路径向量 `P`：保存最短路径上 `Vi` 的前驱顶点下标，初值全部为 0。最终向量 `Final`：`Final[j]` 为 1 表示源点到 `Vj` 的最短路径已经求出，源点自己先置 1。每一轮的动作固定：在还没置 1 的顶点里挑出 `D` 值最小的那个置为 1，再用它松弛邻接点，同时更新 `P`。

算例是九个顶点的带权无向图。确定顺序依次是 `V0`、`V1`(1)、`V2`(4)、`V4`(5)、`V3`(7)、`V5`(8)、`V6`(10)、`V7`(12)、`V8`(16)。注意 `V2` 的值是 4 而不是直达边权 5，因为经 `V1` 中转的 1+3 更短；`V3` 的值 7 来自 `V4` 的 5 加上 2。结束时 `D` 依次是 0、1、4、7、5、8、10、12、16，`P` 依次是 0、0、1、4、2、4、3、6、7。要还原 `V0` 到 `V8` 的路径，就从 `V8` 顺着前驱倒回去：`V8`←`V7`←`V6`←`V3`←`V4`←`V2`←`V1`←`V0`，即 `V0`-`V1`-`V2`-`V4`-`V3`-`V6`-`V7`-`V8`，总长 16。

用邻接矩阵的朴素实现是顶点数的平方；用堆来取未确定里的最小值，可以降到接近「边数乘边数的对数」，稀疏图上更划算。路径要求出来时，再存一个前驱数组，从终点顺着指回起点即可。

## Floyd：枚举中继点

把每对顶点之间的当前已知最短距离存成一张二维表，然后三重循环：最外层依次考虑每一个顶点当作**允许中转的中间点**，内层两重枚举所有点对，问「经过这个中转点会不会更短」，会就更新。k 循环放在最外层是关键——它的含义是「允许使用的中转点集合逐步扩大」，写成最内层就只对最后一轮生效，结果是错的。

Floyd 的目标是一次求出任意两个顶点之间的最短路径，维护两个 `n` 阶二维数组：距离表 `D` 和路径表 `P`。写法上把它看成一个方阵序列 `D^(-1)`、`D^(0)`、……、`D^(k)`、……、`D^(n-1)`，其中 `D^(-1)` 就是图的邻接矩阵，而 `D^(k)[i][j] = Min{ D^(k-1)[i][j], D^(k-1)[i][k] + D^(k-1)[k][j] }`。含义是 `D^(k)[i][j]` 表示从 `Vi` 到 `Vj`、中间顶点序号不超过 `k` 的最短路径长度，跑到 `D^(n-1)` 就是最终结果；`k` 为 0 时中转项退化，所以 `D^(0)` 与 `D^(-1)` 相同。

三个顶点的小例子最能说明这个式子在做什么：`V0-V1` 是 1、`V1-V2` 是 3、`V0-V2` 是 5。允许经 `V1` 中转之后，`D^(1)[0][2] = Min{5, 1+3} = 4`，比原来的直达边更短。它的精妙之处就在这里：通过不断更换 `Vi` 与 `Vj` 之间的中转顶点，把所有可能的中转结点都试一遍，两点之间的最短距离才浮出来。

把上面那张九顶点的图交给 Floyd，演算是依次取 `k = 1` 到 `8`，每一轮拿第 `k` 列的值加上第 `k` 行的值去和当前的 `D[i][j]` 比较取小，`P` 同步更新。到最后一轮会发现，左上角已经确定的那块区域不再变化，因此 `D^7` 与 `D^8` 是同一张表。最终 `V0` 那一行是 0、1、4、7、5、8、10、12、16，和 Dijkstra 的结果一致；`V8` 那一行是 16、15、12、9、11、9、6、4、0。

Floyd 的代价是顶点数的立方，空间是顶点数的平方（距离表和路径表各一份）。它能处理负权边，因为不依赖「一旦确定就不改」这个前提；但**不能有负权回路**——绕一圈能让总权不断减小，最短路径就根本不存在，而它的循环会把这种环一路减下去。

## 三个选择判断

| 场景 | 选什么 |
| --- | --- |
| 无权图、只要边数最少 | 直接广度优先，一遍就够 |
| 单源、边权非负 | Dijkstra，稀疏图配堆 |
| 所有点对、或存在负权边 | Floyd |
| 存在负权边且可能有负权回路 | Bellman-Ford（或其队列优化 SPFA） |

顺带一条常考的概念题：最短路径的任意一段也一定是最短路径——这叫最优子结构，是所有这类算法能递归下去的前提。反过来，「两点之间的最短路径唯一吗」不成立，权值组合出相同的两条路都很常见；而**最短路径一定不含回路**（非负权时，去掉回路只会更短或相等）。

## 负权这件事的两种口径

公开教材里常见的分工是：带负权边的图不能交给 Dijkstra，Floyd 则只要求不存在负权回路。课件总结把两者都归入「无法处理带负权值的图」，理由是很现实的：真实网络里负权很少见，考试时也基本不涉及。真要为负权准备工具，答案是 Bellman-Ford 和它的队列优化版本 SPFA。

## 收尾：两个算法各自的位置

Dijkstra 是单源点算法，可以用小顶堆优化「取未确定顶点里最小值」这一步；Floyd 是多源点算法，一次给出所有点对。Dijkstra 只解决单源问题，把每个顶点轮流当作源点跑一遍，同样能得到所有点对之间的多源结果，代价也是顶点数的立方，只是实现不如三重循环简洁。

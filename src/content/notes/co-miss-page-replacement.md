## 一句话

上层没找到、要把下层的块搬上来，这件事在 Cache 和在主存里都发生过一次，只是处理者不同：Cache 缺失由硬件当轮处理完，缺页则要陷入操作系统去做一个真正的决策——**换出哪一页**。前者的代价用纳秒计，后者用毫秒计，所以后者才值得配一整套算法。

## Cache 缺失在硬件里走完的八步

一次缺失并不只是「去主存读一下」。控制单元要按次序做完这些事：

1. **判定缺失**。索引选中一行后，把请求地址的标记和该行标记比对，同时看有效位。标记不符或有效位为 0，都算缺失，两者不能混为一谈。
2. **决定是让流水线等着还是继续**。最简单的做法是停顿，把这条指令卡住直到数据回来；更复杂的设计允许后面的无关指令先走。
3. **发出缺失处理信号**，通知存储控制器有请求要处理。
4. **算出要访问的地址**。多级 Cache 时是下一级的地址，落到最后一层时是完整的物理地址——注意此刻用的已经是转换过的物理地址，而不是程序给出的逻辑地址。
5. **等待并接收数据**，整块从下层沿总线搬上来。
6. **腾出位置**。行是空的就直接填；行满了就按替换策略选一条逐出，被逐出的行如果脏位为 1，还要先把它写回下层。
7. **更新表项**：写入新标记、置有效位、清脏位或按需置脏位。
8. **恢复执行**，把数据交给等待中的指令；有预取策略的话，顺带把相邻的块也提前拉进来。

取指缺失和数据缺失是同一条流程，差别只在第 4 步那个地址从哪来。

**取指缺失**要用的地址是当前 PC 减 4：取指阶段结束时 PC 已经自增指向下一条指令，所以要回到引发缺失的那条指令的地址上去取。**数据缺失**的地址则由访存指令的有效地址计算得出，基址加变址加偏移那一套算完才是它。

顺序执行的机器在第 2 步只能等；乱序机器可以在等待缺失数据期间继续发射不依赖这个结果的其他指令，让缺失延迟藏到别的计算后面去。更进一步的做法是非阻塞 Cache——一次允许多个缺失同时在途，用专门的记录表把「哪些块正在搬、谁在等它」登记下来，后续命中同一在途块的请求可以直接挂上去，而不必再发一次主存访问。

## 缺失要分三类看

同样是缺失，成因不同，药也不同：

- **强制缺失**：第一次碰到某个块，Cache 再大也躲不掉，属于冷启动。
- **容量缺失**：程序当前活跃的数据集就是比 Cache 大，装不下，只能逐出还要再用的块。
- **冲突缺失**：总数据量装得下，只是几个热点块映射到了同一行，互相挤掉。

加大容量治容量缺失，提高相联度治冲突缺失，预取治的既不是缺失率也不是这三类本身，而是缺失惩罚——它赌下一块马上要用，提前把它搬进来，让等待和计算重叠。

## 缺页之后，操作系统要做的事

缺页是一次内部中断。CPU 停下当前指令，转入操作系统的缺页处理程序，接下来的流程是：在磁盘上找到那一页所在的块，发起读盘；找一个空闲物理块，没有空闲就按置换策略挑一页换出，被换出的页若改过就必须先写回磁盘；把新页读入该块，修改进程页表和系统段表；必要时更新快表；最后回到被中止的那条指令**重新执行**它，而不是从下一条继续。

衡量这一套代价的指标是缺页率：在一串页面引用中，缺页次数占引用次数的比例。它直接决定平均访存代价——把一次缺页的磁盘访问折进等效访问时间，缺页率乘上那个巨大的毫秒级数字，权重远超 Cache 那点缺失。降低缺页率只有两条路：给进程多分几个物理块，或者把置换算法做得更好。

## 页面置换算法

置换决策只在**所有物理块都已被占用且发生了缺页**时才需要做出。评价标准也只有一个：谁被换出去之后，接下来这段时间里的缺页次数最少。

| 算法 | 判据 | 实现代价 | 特点 |
| --- | --- | --- | --- |
| 最优化 OPT | 未来最长时间不再被用到的页 | 需要预知未来，做不到 | 只作理论下界，用来衡量别的算法差多少 |
| FIFO | 最早装入的那一页 | 一个队列即可 | 简单，但有反常现象 |
| LRU | 最久没有被访问的那一页 | 计数器或栈，开销大 | 贴合局部性，是缺省答案 |
| 时钟（最近未用 NRU） | 用访问位近似 LRU | 一个引用位加一个循环指针 | 工程和考试里的折中方案 |

LRU 的依据是局部性：最久没被碰过的页，将来被碰到的概率也最小。它的软肋是顺序扫过一大片数据时，刚装进来的下一页会被当作「最久未用」踢掉，一轮扫描下来命中率反而难看；而且真做精确的 LRU，要为每页维护时间戳或一个双向链表，页多了这个开销就压不住。

时钟算法是把 LRU 便宜的近似：每页一个访问位，硬件在页被访问时把它置 1；置换时从指针处开始循环扫描，遇到访问位为 1 就清零并跳过，遇到 0 就淘汰它并把指针停在这里。它区分的是「最近用过」和「最近没用过」这两档，而不是完整的先后次序，代价只有一位。

## 一段引用串上的账

物理块 3 个，引用串为 `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1`（共 20 次引用）。

按 FIFO 走一遍，队列头是最先进来的页：前三个引用 7、0、1 填满三个块，都是缺页；接着 2 进来时淘汰 7；然后 0 命中；3 进来淘汰 0；再遇到 0 时淘汰 1……一路算完，缺页 15 次，缺页率 75%。

换成 LRU 跑同一条串：每次淘汰的是组内最久未被引用的那一页，同样一路走完，缺页 12 次，缺页率 60%。

两个数字差距的根因很清楚：FIFO 只看「谁来得早」，LRU 看「谁好久没被用」。这条串里 7 来得最早却几乎再没被用到，而 0、2、3 反复出现，按到达时间淘汰正好把要复用的页踢掉了。**页面置换算法的好坏，就是用同一条引用串上的缺页次数比出来的。**

## Belady 异常

把上面的引用串在 3 个物理块下用 FIFO 跑，缺页 9 次；给足 4 个物理块再跑，缺页反而变成 10 次。

**分配的物理块多了，缺页次数却不降反升**，这个现象叫 Belady 异常，是 FIFO 特有的毛病。

它的原因是 FIFO 的淘汰顺序只和装入时刻有关，和访问的最近性毫无关系：多给一个块会改变整个队列的相位，让本来该被踢掉的页活下来、把另一批页推进被淘汰的位置，于是整个淘汰序列被打乱。

LRU 和 OPT 属于栈式算法——它们在 n 个块下的驻留集合，必然是 n+1 个块下驻留集合的子集，因此永远不会出现这种反常。

这一条既是考点也是判据：问哪种算法可能出现 Belady 异常，答 FIFO；问为什么 LRU 更稳，答它具备栈性质。

## 工作集与抖动

工作集指的是进程在最近一段长度为 Δ 的引用窗口里用过的那些页的集合，它随执行过程变化，刻画的是「这一瞬间这个进程真正需要驻留多少页」。

系统给所有进程分配的物理块总数是有上限的。如果各进程的工作集加起来超过主存容量，就会出现一种恶性循环：某进程要用的页不在主存，缺页换入；为了腾位置，另一个进程的活跃页被换出；那个进程随即缺页，又把这个进程刚换进来的页踢出去。**绝大部分时间都花在换页上，真正执行的时间反而寥寥**，这就是抖动。

抖动一旦发生，唯一有效的处置是把某个进程整体挂起、把它占的块让出来，让剩余进程的工作集能装下——这一步通常由系统的对中调度（工作集调度）完成：按各进程工作集的实际大小来分配和回收物理块，而不是让所有进程平均摊。

## 两条容易混的线

第一条线是**调入策略**：页是缺页时才拿进来（请求调页），还是提前预测着批量拿进来（预调页）。后者把磁盘顺序读的开销摊薄，代价是可能搬来一堆用不上的页。

第二条线是**写回时机**：改过的页在被换出时写回磁盘，这就是脏位的作用——没改过的页直接丢弃即可，省一次写盘。它和 Cache 里写回策略的脏位是同一个思路，只是这里一次写盘是毫秒量级，所以省掉的这一次价值大得多。

把两条线合起来看就能明白：**缺失处理和页面置换其实是同一个问题在两个尺度上的投影**——都是「上层放不下，必须决定留谁踢谁」，区别只在于踢掉一页的代价，比逐出一行贵了几个数量级。

也正因如此，两者在描述方式上可以一一对应：Cache 说命中时间、缺失率、缺失惩罚，主存与磁盘之间就说访问页时间、缺页率、缺页代价；Cache 用相联度和容量换缺失率，主存用多分物理块换缺页率；Cache 用预取藏延迟，虚存用预调页藏延迟。把这套对应关系记牢，两边的大部分题目都不用重新推导。

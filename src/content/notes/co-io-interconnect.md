## 交换信息是一切的前提

计算机系统的两大主体是主存与各种外部设备，而所有功能都由 CPU 执行存放在主存里的指令序列来实现。指令执行过程中，CPU 要频繁地跟主存和外设交换数据：从主存取指令和操作数、把运算结果写回主存、把数据送给外设输出、接收外设发来的中断信号告知事件已经完成。要支撑这些交换，系统内部必须有通信线路把各部件连起来，通信线路加上相关的控制机制，合起来就是互连结构。互连结构可以只是简单的一条总线，也可以是交叉开关矩阵或者网格网络，选择依据是系统规模、性能需求和可接受的设计复杂度。

## 分散连接与总线连接

部件之间的互连有两种基本方式。

**分散连接**也叫点对点连接，指每个部件与其他部件之间都单独拉线。早期计算机和小规模系统里比较常见，好处是信号路径简单、能实现点对点的精确控制；问题是部件数增加时连线数量按组合数增长，布线复杂、成本高昂、扩展性差。

**总线连接**让多个部件共享一组公共传输线，按传输内容分为地址总线、数据总线和控制总线。它的优势是灵活与经济：加新部件容易、连线数量大幅减少、成本下降，只要遵循同一套通信协议和标准，部件还可以互换。它的短板同样来自共享——多个部件同时要用时会出现通信瓶颈，导致传输延迟。为此现代系统普遍采用总线仲裁、优先级调度和多级总线架构来提高总线利用率、减少冲突。多年来总线连接是系统设计的主流，个人计算机、服务器和嵌入式系统里都扮演核心角色，标准本身也在演进，PCI Express、SATA、USB 都是为更高的传输速率和更低的功耗而生。

| 方式 | 连线代价 | 扩展性 | 带宽特性 | 典型用途 |
| --- | --- | --- | --- | --- |
| 点对点连接 | 随部件数平方增长 | 差 | 每对部件独享，无竞争 | 早期小系统、现代高速串行链路 |
| 总线连接 | 少而共用 | 好，加设备即可 | 共享介质，需仲裁 | 主流单机内部互连 |
| 交叉开关 | 端口数平方级的开关矩阵 | 中等 | 可同时建立多条通路 | 高性能计算、多处理器互连 |
| 片上网络 | 规则的网络拓扑 | 好 | 包交换、多跳 | SoC 内部众多模块互连 |

随着需求进一步提高，一些系统开始改用更高级的互连方式，比如交叉开关或者片上网络，用来克服总线连接的瓶颈与可靠性限制；代价是设计复杂性和成本上升。

## 三层总线与桥接器

一台典型机器内部的总线是分层的，慢的设备不该去抢 CPU 到主存那条高速通路，否则整机节拍会被最慢的一环拖住。

- **处理器—存储器通路**：CPU 与主存之间通过处理器总线和存储器总线相连，这条总线相对较短，通常是高速总线。CPU 芯片通过插座安装在处理器总线上，内存条通过插槽接入存储器总线。某些系统中处理器总线与存储器总线被分开，中间由桥接器衔接，好处是两侧可以各自按自己的节拍工作，数据传输的调配更灵活。
- **I/O 通路**：各类外设借助自己的设备控制器连到 I/O 总线上，I/O 总线再通过桥接器与主存和 CPU 相连。设备控制器的职责是把设备特有的信号转换成 I/O 总线能理解的通用信号。传统上 I/O 总线速度较慢，PCI Express 出现之后 I/O 总线的速度被大幅提升。
- **桥接器**：连接两个不同总线段、隔离两侧时序与电气特性的部件，同时负责把不该跨层的流量挡在外面。

前端总线是 CPU 与主存之间那条高速数据通路的旧称，它的速度对系统整体性能影响很大。在现代处理器里这个概念逐渐被更高效的接口取代：内存控制器被集成进 CPU 内部，称为集成内存控制器，芯片之间的连接改用 DMI 或者 Infinity Fabric 这类高速链路，封装形式也演进为 LGA 之类的 land grid array 与 Socket AM 系列插座。

## 芯片组：北桥与南桥

典型的基于总线互连的系统里有两类桥芯片，合称芯片组，是各部件相互连接与通信的桥梁。

**北桥**作为内存控制器集线器，负责连接 CPU 与主存，并处理 CPU 与高速图形设备（如显卡）之间的 DMA 请求，使 CPU 能高效访问内存与显存，对需要处理大量图形数据或者执行复杂计算的应用至关重要，因此它管的是高速数据传输。

**南桥**作为 I/O 控制器集线器，管理低速外设与 CPU 之间的通信，集成了多种外设控制器，例如 USB 控制器、磁盘控制器、以太网控制器，还负责提供主板上的扩展槽，供用户加装额外的 I/O 控制卡，因此它管的是较慢速的设备。

两块芯片通过特定总线相互连接，并与 CPU 及其他部件通信。这种设计的价值在于性能与可扩展性同时兼顾：更换或升级芯片组中的某一块，就能在不改动整个系统的情况下提升性能与功能。这一结构在过去很常见，如今已被更先进的互连取代——北桥的功能大多并入 CPU，南桥的角色交给平台控制器中心这类芯片，外围设备则统一挂在 PCIe 链路上。

## 交叉开关与片上网络

**交叉开关**是一种点对点式的互连结构，任意输入端与任意输出端之间都能直接连通，不必经过中间节点。由于数据从源到目的无需在总线上竞争，延迟明显下降，特别适合要求高带宽低延迟的场合，例如高性能计算集群、数据中心内部服务器互连、多处理器系统内的通信。它的限制也很清楚：规模扩展性受限，成本与功耗随端口数量迅速上升。

**片上网络**（常写作 NoC）针对的是另一类问题：单芯片系统里模块太多，传统总线或者交叉开关满足不了内部通信需求。它把芯片上的处理器核心、内存控制器、I/O 接口等功能模块用类似网络的结构连起来，通常采用包交换，像互联网数据包那样路由与转发，因此能有效处理多点对多点通信，支撑复杂的并行与分布式计算任务。它的难点在于需要复杂的路由算法与调度策略来保证通信效率和公平性，还要处理拥塞控制与错误恢复。

两条路线的共同点是：用更多的硬件换取更高的并发带宽，同时把设计复杂度推给实现者。选型时需要在性能、成本、功耗与设计复杂性之间权衡，而不是默认越先进越好。

## 为什么共享一条线会变成瓶颈

总线的所有优点都来自共享，所有缺点也来自共享。同一时刻只有一个发送者能说话，于是部件数量一多，请求就要排队；排队就需要仲裁，仲裁就多花几拍；更麻烦的是延迟变得不可预测——同样的访存请求，总线空闲时几拍完成，拥塞时可能要等上很多拍。共享还意味着电气负载：挂的部件越多，线的电容越大，信号边沿越慢，能跑的频率就越低，这就是负载能力这项指标存在的原因。

因此现代系统不会真的让所有部件挤在一组线上，而是按速度分层再加桥接：处理器—存储器那一段最短最快，专供取指令与访存；图形与高速存储设备挂在下一层；键盘、串口这类慢设备留在最外层的 I/O 总线上。桥接器在层与层之间做缓冲与转发，把慢层的流量挡在高速层之外，只在数据确实要跨层时才搬运。局部总线就是这种思路的产物：它短、离 CPU 近、跑得快，早期用来接显卡与高速网卡，后来这类高带宽设备陆续改用点对点的高速串行链路，本质上还是同一个动机——别让慢设备分享快通道。

外设发出的中断请求同样要走这条互连结构：它占用控制线，是设备主动向主机发起的请求，因此总线上必须预留请求与应答的通路。换句话说，互连结构不仅要支撑 CPU 主动读写设备，还要支撑设备主动通知 CPU，这两件事的硬件代价是分开设计的。

## 接口的位置

无论哪种互连结构，外设都不能直接挂到总线上：设备控制器贴在总线与设备之间，负责信号、格式与时序的转换，并通过端口地址被 CPU 选中。下一节说的 I/O 接口，就是这条链子上主机与外设真正握手的那一段。

判断一个互连方案合不合理，可以只问三个问题：一次传输要经过几段共享线路、同时有多少对部件能真正并行通信、加一个部件时总线的电气负载与仲裁延迟会不会跟着涨。第一个问题决定延迟下限，第二个决定吞吐上限，第三个决定规模天花板。总线的回答通常是三者都受共享限制，交叉开关用矩阵换来了并行但付出了面积，片上网络用多跳换来了可扩展的规则布线。理解了这三问，后面看 DMA 为什么要抢总线、通道为什么要独立成一台小处理器，就都有了着落。

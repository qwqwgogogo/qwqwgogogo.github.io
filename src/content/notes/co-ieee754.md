## 一句话

浮点数就是二进制版的科学计数法，形如 `(-1)^S × M × 2^E`。IEEE 754 要回答的问题是：32 个格子怎么分给符号、阶码和尾数，以及那些不该当成普通数来解释的极端位串该按什么规则读。

## 标准规定的四种长度

IEEE 754 一共规定了四种表示浮点数值的方式：32 位的单精度、64 位的双精度、43 比特以上的延伸单精度（很少使用）和 79 比特以上的延伸双精度（通常以 80 位实现）。这四种里只有 32 位模式是强制要求，其余都属选择性实现。日常遇到的两个基本格式就是单精度和双精度，单精度对应 `float` 型、又叫短浮点数，双精度对应 `double` 型、又叫长浮点数，两者的基数都隐含为 2，不需要占用任何存储位。

## 单精度的三个字段

| 字段 | 位数 | 表示法 | 作用 |
| --- | --- | --- | --- |
| 符号 `S` | 1 | 直接写 | 0 正 1 负 |
| 阶码 `E` | 8 | 移码，偏置 **127** | 决定范围 |
| 尾数 `f` | 23 | 原码小数 | 决定精度 |

规格化数的真值公式：

```
X = (-1)^S × 1.f × 2^(E - 127)
```

尾数用原码表示，阶码用移码表示，这两点各自有理由。尾数是纯数值的有效位，原码形式下符号位独立在外，加减时按定点原码小数处理即可。阶码用移码，是因为比较两个浮点数的大小时要频繁比阶码高低，移码保持数据原有的大小顺序，可以直接按无符号位串逐位比较，省掉解符号的步骤。

## 隐藏位白赚一位精度

规格化的二进制浮点数，尾数最高一位一定是 1。既然恒为 1，标准就规定把它省下来不存，这一位叫隐藏位，于是 23 位尾数实际表示 24 位有效数字。754 把隐藏位 1 的位置规定在小数点之前，也就是尾数形式为 `1.xxx...xxx`。举个转换例子，`(12)₁₀ = (1100)₂`，规格化成 `1.1 × 2^3`，其中整数部分那个 1 不进入 23 位尾数，字段里只写小数点后面的 `1` 补零。

这里有个和通用浮点格式容易混的地方。有些教材里的 32 位短浮点把规格化尾数写成 `0.1xx...xxx`，隐藏的是小数点后第一位那个 1，偏置常数取 128。IEEE 754 隐藏的是小数点左边那个 1，偏置取 127。同样是省一位，藏的位置不同，读题时要先确认说的是哪种格式。

## 偏置值为什么是 127

8 位阶码能表示 `0..255`。如果偏置取 `2^(n-1) = 128`，全 0 对应真值 `-128`，正负两边不对称地占满了整个位串，就没有多余的码型留给特殊值。

IEEE 754 把偏置值定为 `2^(n-1) - 1 = 127`，也就是让位串整体少偏移一格。这样全 0 和全 1 这两端都被征用去做特殊解释，中间可用的 `1..254` 减去 127 后正好落在指数真值 `-126..127`。双精度用 11 位阶码，同一条公式给出偏置值 `2^10 - 1 = 1023`。**看到「偏置 128」先确认它讲的是通用格式还是 754**，这是这一节最容易失分的地方。

## 五类数的划分

阶码的两种极端取值被征用后，解释规则整个换一套。按阶码和尾数的组合，754 把全部位串分成五类：

| 阶码 `E` | 尾数 `f` | 含义 | 真值 |
| --- | --- | --- | --- |
| `0000 0001`~`1111 1110` | 任意 | 规格化数 | `(-1)^S × 1.f × 2^(E-127)` |
| 全 0 | 全 0 | 零 | `±0` |
| 全 0 | 非 0 | 非规格化数 | `(-1)^S × 0.f × 2^-126` |
| 全 1 | 全 0 | 无穷 | `±∞` |
| 全 1 | 非 0 | 非数 | `NaN` |

规格化这一类是最普通的：阶码既不全 0 也不全 1，位串范围 `[0000 0001, 1111 1110]` 即十进制 `[1, 254]`，对应真值 `[-126, 127]`。阶码字段里存的值就是移码值，取出来减 127 得到指数真值。

零这一类不再按公式计算，而是规定固定为 0。符号位仍然有效，所以有 `+0` 和 `-0` 两个位串，一般情况下正负零等效。这一点和补码里零唯一表示不同，是浮点格式的固有问题。

## 非规格化数专门补下溢

阶码全 0 而尾数不为全 0 时，这个数就是非规格化数。它的规则有两处反直觉：隐藏位不再是 1，而是固定为 0；阶码位串虽然按移码本该解释成 `-127`，标准规定不做这个转换，而是把指数固定按 `-126` 算。

```
X = (-1)^S × 0.f × 2^-126
```

这么设计是为了处理阶码下溢：当运算结果的绝对值比最小规格化数 `2^-126` 还小时，程序不至于一下掉到 0，而还能继续算下去。举例来说，想表示 `2^-127`，规格化写法做不到（`1.f × 2^-127` 需要阶码全 0），改用非规格化数就能写成 `(-1)^0 × 0.100...0 × 2^-126`，位串是：

```
0 00000000 01000000000000000000000
```

尾数域里第一个 1 挪到了小数点后第一位。非规格化数能表示的最小正数是尾数只有最低一位为 1 的情形，即 `2^-23 × 2^-126 = 2^-149`。从 `2^-149` 一路到 `2^-126`，可表示的数间隔和规格化区相比逐步变密，这段区间里浮点数是均匀分布而不是成倍分布的，这叫渐降（gradual underflow），好处是极小值相减不至于立刻得到 0。

## 无穷与非数

阶码全 1 且尾数全 0 时，这个位串固定表示正负无穷大。引入无穷有两个作用：一是让计算过程中出现溢出的异常情况下程序还能继续跑，二是给程序提供错误检测的抓手。数值上 `+∞` 大于所有有限数，`-∞` 小于所有有限数，无穷既可以当操作数，也可以是运算的结果，例如一个很大的数相乘就会得到无穷。

阶码全 1 而尾数不为全 0 时，表示的是一个没有定义的数，称为 NaN。像 `0/0`、`0 × ∞`、`∞ - ∞`、负数开平方这些在数学上没有解释的计算，机器就给出 NaN。NaN 最重要的性质是它和任何数（包括它自己）的比较都不成立，所以判断一个结果是不是 NaN 不能靠相等比较，只能靠专门的条件码。

## 表示范围算一遍

规格化正数一侧的上下界可以由极端字段推出。最小值取 `S=0`、`E=0000 0001`、`f` 全 0：

```
X = (-1)^0 × 1.0 × 2^(1-127) = 2^-126
```

最大值取 `S=0`、`E=1111 1110`、尾数 23 位全 1，此时 `f = 1 - 2^-23`：

```
X = (-1)^0 × (1 + 1 - 2^-23) × 2^(254-127) = (2 - 2^-23) × 2^127
```

所以规格化正数的范围是 `[2^-126, (2 - 2^-23) × 2^127]`，负数一侧与之关于原点对应，是 `[-(2 - 2^-23) × 2^127, -2^-126]`。把非规格化数算进来，正数一侧能往下延伸到 `2^-149`，但精度一路下降。双精度按同样方法算，指数范围是 `[-1022, 1023]`，最小规格化正数 `2^-1022`，最大约 `(2 - 2^-52) × 2^1023`。

## 尾数和指数是一场分配

设计浮点格式时必须决定尾数和指数各分多少位。总位数是固定的，比如单精度就 32 位、双精度就 64 位，所以两边此消彼长。增加尾数位数意味着能更精确地表示数值、提高精度，尤其是接近零的小数能拟合得更好；增加指数位数则扩大可表示范围，让非常大和非常小的数都能容纳，动态范围更宽。取舍要看应用：科学计算常常既要处理极大极小值又要保精度，倾向于把总位数做大；而对精度要求不高、却在意速度和内存占用的场合，宁可牺牲一点精度换取更小的存储和更快的运算。要记住浮点数无论如何都会溢出，因为位数终究有限。

## 为什么 0.1 存进去就错了

十进制小数转二进制用乘基取整：

```
0.3 × 2 = 0.6 → 0
0.6 × 2 = 1.2 → 1
0.2 × 2 = 0.4 → 0
0.4 × 2 = 0.8 → 0
0.8 × 2 = 1.6 → 1
0.6 × 2 = 1.2 → 1   ← 从这里开始循环
```

小数部分永远得不到 0，`0.3` 的二进制是 `0.0100 1100 1100 1100...` 无限循环。尾数只有 23 位可存，必须截断，所以这个数在写入的那一刻就已经不等于 0.3 了。`0.1 + 0.2 != 0.3` 不是哪门语言的缺陷，而是二进制表示小数时的固有性质。整数不同，只要位数够用就能精确表示，等到超过 24 位有效数字之后才开始丢低位。

## 定点与浮点的分工

| | 定点数 | 浮点数 |
| --- | --- | --- |
| 小数点 | 位置固定 | 随阶码移动 |
| 决定范围的 | 总位数 | 阶码位数 |
| 决定精度的 | 总位数 | 尾数位数 |
| 数轴上的分布 | 均匀 | 越靠近 0 越密 |
| 零的表示 | 补码唯一 | `+0` 与 `-0` 两种 |

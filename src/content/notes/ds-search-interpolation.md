## 基本思想

插值查找是对二分查找在均匀分布数据上的改进，前提仍然是有序数组。折半的死板之处在于：无论给定值是什么，它每一轮都检查查找区间的正中间，靠不断对折慢慢逼近；如果目标本来就落在表尾附近，从中间起跳就要连砍好几刀才走到头。插值查找没有这个局限，它让要查找的值本身决定探点——给定值在区间值域里靠哪头，就径直往哪头落点：查接近最大值的元素时，第一刀就直接落在表尾附近，而不必先一路对折。

## 公式：把 1/2 换成值的占比

折半求中点的公式可以写成 `mid = low + (1/2)(high - low)`，系数恒为二分之一。插值查找把它替换成 `mid = low + (x - arr[low]) / (arr[high] - arr[low]) · (high - low)`：分式是目标值在当前区间值域中的相对位置，区间两端键值差越大、目标越靠哪头，算出的 mid 就越靠近哪端。当查找的元素靠近 arr[high] 时，公式给出的 mid 也靠近 high；靠近 arr[low] 时 mid 就靠近 low。除这一步之外，其余流程与折半完全一致：比较 mid 处元素与给定值，不相等就把区间收缩到左半或右半，区间为空即宣告失败。

## 公式的来历：把区间当直线插值

公式不是凭空设计的，它就是数值分析里线性插值的离散版本。把键值序列看成一条单调上升的曲线上的采样点，两端点 (low, arr[low]) 与 (high, arr[high]) 之间用直线段近似，那么给定值 x 对应的下标，就是这条弦上纵坐标等于 x 的横坐标：由两点式解出 x 的位置比例 (x - arr[low]) / (arr[high] - arr[low])，再按这个比例去截取区间长度 (high - low)。数据在值域上摊得越均匀，弦与真实曲线的偏差越小，这一刀就落得越准；折半则是永远取比例 1/2 的特例，等于不管曲线形状、闭着眼睛从正中切。

## 实现过程：查 18 只要两次比较

用 15 个元素的有序数组 10, 12, 13, 16, 18, 19, 20, 21, 22, 23, 24, 33, 35, 42, 47（下标 0 到 14）查关键字 18。第一步，low = 0、high = 14，arr[low] = 10、arr[high] = 47，mid = 0 + [(18 - 10)/(47 - 10)] × (14 - 0) = 3，落在元素 16 上。第二步，16 小于 18，把 low 更新为 mid + 1 = 4——这一步与折半的做法相同。第三步，在新区间 [4, 14] 上重算：mid = 4 + [(18 - 18)/(47 - 18)] × (14 - 4) = 4 + 0 = 4。第四步，arr[4] = 18，与给定值相等，返回下标 4，全程只比较了两次。

同一张表让折半来查 18：mid = 7 撞上 21，high 收到 6；mid = 3 撞上 16，low 升到 4；mid = 5 撞上 19，high 降到 4；mid = 4 命中，一共四次。差距的来源很直白：18 在值域 [10, 47] 里只偏下四分之一处，插值公式第一刀就把它指到了附近，折半则坚持从几何正中起跳。

失败的情形值得单独走一遍，因为它暴露了公式的脆弱点。还是这张表，目标换成 17：第一轮 mid = 3，arr[3] = 16 小于 17，low 升到 4；第二轮在 [4, 14] 上按公式算，分子 17 - arr[4] = 17 - 18 是负数，探点落到 low 之前，实现里必须把 mid 夹回区间、取 4。比较 arr[4] = 18 大于 17，high 降到 3，此时 low 越过 high，区间为空，宣告查找失败，同时给出插入位置 4。这一趟说明两件事：分子可能为负，夹逼不是可选项而是必选项；区间两端键值相等时分母为零，同样要提前拦截。

## 小结：界依赖分布，退化只要一个反例

跳跃查找的最优步长靠一阶导数就能求出来，插值查找的性能界证明要难得多，它依赖对均匀分布下顺序统计量的深入分析：n 个关键字独立均匀分布时，成功查找的期望探点次数是 O(log log n)，即双重对数量级。换句话说，在均匀分布假设成立的数据上，插值查找的平均查找长度可以远远低于折半的对数水平。但这条界完全建立在均匀分布的假设上，数组不满足均匀分布时，插值查找的时间复杂度会退化到 O(n)。极端反例：数组 {1, 10, 100, 1000} 查 100——第一轮 mid = [(100-1)/(1000-1)]×3 ≈ 0，落在下标 0；第二轮区间 [1, 3] 上算出的索引是 1；第三轮落在 2，这才找到。每一次都只把区间缩短一格，等价于把整个数组线性遍历了一遍，最坏情形与顺序查找同阶。这个例子的教训是：决定插值查找成败的不是有序与否，而是数值在值域里摊得平不平。

## 适用场景与实现细节

跳跃查找与插值查找常被并列成「两种步长」：跳跃用固定步长，落点与目标值无关，性能上界由表长的平方根决定，对数据分布几乎不敏感；插值用数值驱动的变步长，落点由目标值直接算出，性能上界则由分布的均匀程度决定，摊得平就快、摊不平就退化。前者稳、后者快，共同前提是表必须有序且能按下标直接定位任意元素。

适合插值查找的数据长这样：键在值域内近似均匀铺开的有序数组，例如按号码段均匀发放的学号、日期序列、定长编码的编号。判断能不能用它，先看数据直方图是否接近平坦：值域大、分布匀、表又长，插值的双重对数优势才值得付出每轮的除法；反过来，键值成指数状铺开（如 1、10、100、1000）时公式几乎每轮都被拉回区间边缘，插值反而不如老老实实折半。工程上常拿它和折半混用：区间缩小到一定程度后改回折半，或者先用插值粗定位再用顺序扫尾。实现上有两个必查的边界：分式分子分母都是键值差，区间两端键值相等时除法会出问题，必须先判断；算出的 mid 要夹在 [low, high] 内再使用，防止浮点取整后越界。失败时它同样能指出插入位置——收束后空区间的一侧，这与折半落到判定树外部结点是同一回事。同族的另一个改进是斐波那契查找，它用斐波那契数划分探点，把除法换成加减法，走的是与插值不同的优化路线。

| | 折半查找 | 插值查找 |
| --- | --- | --- |
| 探点 | 区间几何中点 | 按目标值在值域中的占比 |
| 对分布的态度 | 无所谓 | 均匀才好，不均匀退化 |
| 期望平均查找长度 | O(log n) | 均匀时 O(log log n) |
| 最坏 | O(log n) | O(n) |
| 每轮开销 | 一次加法一次除法（除 2） | 两次减法一次除法 |

最后一行提醒一件事：插值每轮的算术开销比折半大，它赢在轮数少。数据量不大或者分布不明时，这份改进未必划算——这也是它在大作业和考研题里总以「折半的改进版」身份出现的原因。

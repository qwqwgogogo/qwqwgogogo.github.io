## 一句话

Cache 的账只有一个式子：`AMAT = 命中时间 + 缺失率 × 缺失惩罚`。所有改进手段都能被归到这三项之一，而判断一个手段值不值，也只看它动了哪一项、有没有把另一项压坏。

## 先给性能定量

CPU 时间可以粗略拆成两块：真正执行指令的时钟周期数，和等待存储系统响应的时钟周期数。等待部分主要由缺失造成：

```
CPU 时间 = (CPU 执行时钟周期数 + 存储器阻塞时钟周期数) × 时钟周期时间
存储器阻塞 = 读次数 × 读缺失率 × 读缺失代价 + 写操作的相关代价
```

写操作是否计入代价取决于策略：写直达时每次写都要访问主存；写回时写命中不产生主存流量，只有被逐出的脏行才付一次写回；写分配策略下写缺失还要先把块读进来，这笔要按缺失算。

拿这组关系算一个结论。原始机器 CPI 为 2，缺失带来的额外 CPI 为 3.44，总 CPI 5.44，存储器阻塞占了 `3.44 / 5.44 ≈ 63%`。把流水线优化到 CPI 1、存储系统原地不动，总 CPI 变成 4.44，阻塞占比反而升到 `3.44 / 4.44 ≈ 77%`。

处理器快了，性能却没按比例涨，因为**分母里被等待占掉的比例更大了**。这就是只提升处理器、不提升存储器的后果，也是层次结构必须跟着一起演化的原因。

## 手段一：把缺失率压下去

缺失率是三分类的（强制、容量、冲突），所以压它要打三个方向。

**加大容量**直接治容量缺失，代价是命中时间变长、成本和功耗上升——大容量要更大的译码和更长的走线，这条限制决定了容量不能无脑加，得让更贵的层做更小的事。

**提高相联度**治冲突缺失。同样容量下，每多一路就多一个可选位置，两个热点块撞车的概率下降。收益递减得很快：从直接映射到两路提升巨大，四路到八路的提升已经很小，而代价（比较器、多路选择、置换状态）却一直在涨。

**优化块大小**在两个方向上同时起作用，下一节单独算。

**替换算法**决定谁被踢掉，LRU 比随机和 FIFO 更贴合局部性，因而缺页时留下的更可能是还要用的块。

**编译器的活儿**：调整数据布局让常被一起访问的项落在同一个块里，避免多个热点地址恰好映射到同一行（该对齐的对齐、该填充的填充），以及下面要讲的分块。

**预取**是唯一一个「不降低缺失次数、但降低有效缺失惩罚」的手段：它赌下一块马上要用，提前发出请求，等真缺的时候数据已经在路上了。硬件预取靠识别顺序与固定步长模式，软件预取由编译器在循环里插入取数指令。它增加的是总线流量，换来的是等待被计算藏起来。

## 手段二：多级 Cache

只有一层 Cache 时，加大它就会拖慢命中时间，两条目标在同一层里互相打架。分成两层之后，目标可以拆开：

| | L1 | L2 |
| --- | --- | --- |
| 优化目标 | 命中时间 | 缺失率 |
| 位置 | 每核私有，紧贴内核 | 片上，可为多核共享 |
| 容量 | 小 | 大 |
| 块大小 | 小 | 大 |
| 相联度 | 低 | 高 |

L1 追求的是「一两个周期内给答案」，所以它小、块小、相联度低，甚至把指令和数据拆成两个独立的 L1——取指和数据访问井水不犯河水，分开之后两边都不会被对方的块挤掉，而且一个时钟周期里能同时读指令、读数据。

L2 追求的是「L1 掉了的东西尽量在我这儿捞回来」，所以它用更大的容量、更大的块、更高的相联度去拦下那些会一路掉到主存的请求。缺失惩罚从主存的百纳秒级降到 L2 的几纳秒到几十纳秒，这就是加一层的全部理由。

关键的账在于：**上一层的缺失率会传染给下一层**。L2 看到的访问次数只是 L1 漏掉的那一小部分，所以哪怕 L2 自身缺失率不低，它对整体 AMAT 的贡献也被 L1 的命中率缩小过一轮。

算例（三级层次）：L1 命中时间 1 ns、缺失率 5%；L2 命中时间 4 ns、对 L1 的缺失中仍有 2% 要落到主存；主存访问 100 ns。

```
AMAT = 1 + 0.05 × (4 + 0.02 × 100) = 1 + 0.05 × 6 = 1.3 ns
```

如果把这些地址空间全压给一层 Cache，让它用 1 ns 的命中时间去面对 5% 的缺失率是做不到的：容量翻到能覆盖工作集时，命中时间就不可能还是 1 ns。两层各让一步，反而拿到了 1.3 ns。

## 手段三：包含策略与排除策略

多层 Cache 之间还有一个必须回答的问题：**下层装的东西，上层是不是也必须装？**

**包含策略**规定上层的任何块都一定在下层里有副本。好处很实在：替换时不必重新分配空间，只要把它从上层踢下去即可；下层因此天然成了上层的后备，管理简单，一致性也更容易维护。代价是下层容量被上层那份重复占用了一部分，实际有效容量变小。

**排除策略**规定上层的块在下层不留副本。好处是下层容量一点不浪费，能真正装下更多内容；代价是替换下来的块要么直接丢弃（下次再缺再从主存拿），要么得另找地方放，控制器要额外跟踪「哪些块现在只存在于上层」。

写缺失时还有一个孪生的选择：要不要把块先拉到 Cache 里再改（写分配），还是干脆只写下面那层（非写分配）。读缺失几乎总是把块取上来，因为局部性赌的就是「邻居也要用」；写侧则不同，写直达常配非写分配，写回常配写分配。

这一组选择合起来决定的其实是一件事：**缺失时数据落在哪一层、什么时候往下掉。**

## 手段四：块大小的取舍

块变大，一次搬进来的邻居更多，顺序访问时后续命中，缺失率下降；块太大又带来三件事。

第一，搬一整块的时间线性变长，缺失惩罚上升。第二，同样容量下行数变少，能放的独立地址范围缩水，冲突缺失和容量缺失都会抬头。第三，块里的数据用不完——如果实际访问只碰到块首几个字，剩下的就是把带宽浪费在没人要的数据上。

所以缺失率对块大小是一条**先降后升**的曲线，中间存在一个最优值。小容量的上层 Cache 适合小块（保住命中时间），大容量的下层适合大块（用突发传输把搬运成本摊平）。现代机器上还有一个配套的约定：Cache 块大小一般等于主存一次突发传输的数据量，两边粒度对齐，谁也不浪费。

至于「按访问模式动态改变块大小」这类想法，属于用复杂度换收益的路子，代价是标记和目录结构都要能表达变长粒度，工程上很少做。

## 手段五：别让流水线干等

非阻塞 Cache 允许一次挂多个缺失，在途的块不阻塞后续访问；配套要有一张记录表登记哪些块正在搬、谁在等它，还要能正确处理「写还没回来的块」和「又请求同一个块」这类情况。

victim buffer 把刚被逐出的块先存在一个小的高速位置里，而不是立刻写回主存——如果它马上又被用到，代价就只有一次小表查找。这一招对写回尤其划算，因为它顺带减少了脏块写回主存的次数。

伪相联是折中的硬件技巧：按直接映射去找，第一次找不到时再看「配对」的那一行，用两倍的查找时间换接近两路的冲突缺失表现，而不用付组相联的完整代价。

## 手段六：分块，把优化交给编译器

Cache 是硬件在赌局部性，程序自己也可以主动制造局部性。分块（也叫 tiling）干的就是这件事：把大数组的遍历切成一块块能整块塞进 Cache 的小任务，让一块数据在被逐出之前被反复用尽。

看一个具体的量级。`A[1000][1000]` 的 32 位整数矩阵，缓存行 64 字节，也就是 16 个整数。

**按行访问**时，一行 4KB 连续排布，读进一行缓存就用掉 16 个元素，每 64 字节的搬运全都物尽其用。

**按列访问**时，相邻两次访问差 1000 个元素、隔着 4000 字节，每次都要重新装载一整行，而那一行里本轮只用到 1 个元素——有效带宽只剩十六分之一，其余十五份是被拉进来又扔掉的。

分块的做法是把矩阵划成 4×4 的子块，一个块正好 16 个整数、正好占满一条缓存行。先在这个块内把行方向的计算做完，再顺手把同一块里的列方向也算完，然后才换下一个块。块内数据的行、列两种访问都命中已经装进来的那些行，跨块的远距离访问频率被压到最低。

再配合循环展开（一次迭代处理更多元素，减少循环控制开销）和预取（算当前块时把下一块提前拉进来），缺失率还能再降一截。

分块的意义不在算法本身，而在**它把「访问顺序」这个程序员能控制的东西，对齐到了「搬运单位」这个硬件决定的尺度上**。硬件能猜局部性，但不能创造局部性。

## 收口

把这六种手段排回 AMAT 的三个变量：容量、相联度、块大小、替换算法、分块影响缺失率；多级 Cache、非阻塞、victim buffer、预取影响缺失惩罚；L1 做小、译码与比较并行、指令与数据分离影响命中时间。

任何一项改进都要回答两个问题：它压的是哪一项，它有没有把另一项顶高。回答不出这两问的优化，在 AMAT 上多半是亏的。

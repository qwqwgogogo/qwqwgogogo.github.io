## 先申明，再使用

C 语言里凡是自己设计出来的东西，程序员都必须告知编译器它在内存上如何规划。数据类型的申明干的就是这件事：告诉编译器你的新模具到底有多大，因此必须先申明再使用，申明在前、使用在后，顺序不能颠倒。

这条规则在自定义类型上最容易看漏。struct 和 union 都不是数据类型，它们是自定义成员组合行为的说明符，只写出关键字而不写出变量名，编译器仍然不知道要留几格内存；枚举同理，它实际上就是一个整型，并没有类型限定的约束。所以「申明」这个词在 C 里承担两件事：一是给出类型本身，二是按这个类型划出一块可以访问的空间。

## 声明的读法：名字往右，括号打断

C 的声明不是读一遍就懂，而是按固定顺序拆：从变量名出发，先看右边再看左边，括号优先。拆对了，再长的声明也能一口念出来。

| 声明 | 读法 |
| --- | --- |
| `int *p;` | p 是指针，指向 int |
| `int *p[5];` | p 先是数组（`[]` 比 `*` 优先级高），5 个 int 指针，这是指针数组 |
| `int (*p)[5];` | 括号把 `*p` 提前，p 是指针，指向一个 5 个 int 的数组，这是数组指针 |
| `int (*p)(int);` | p 是指针，指向一个收 int 返回 int 的函数 |
| `int *p(int);` | p 是函数，返回 int 指针 |

同一个 `*`，位置挪一格意思就换了，判断依据永远是优先级，不是看起来像什么。指针数组和数组指针的差别也在这里：前者的容器是数组、元素是指针，后者的容器是指针、指向的东西才是一个数组。

## typedef 只是起别名

typedef 不创造新类型，它把一个难写的类型换成一个词。三种典型用法值得分开记。

给标量起别名，最常见的用途是跨平台：把某个宽度固定下来，换编译器时只改这一行。给函数指针起别名，省下的是整段括号噪音——把「收 int 返回 int 的函数指针类型」命名成一个词之后，再想表达 5 个这种函数指针，只要写「5 个该别名」即可，与原来那一长串声明完全等价。第三种是给数组类型起别名，把「4 个 int 的数组」整个命名成一个类型，之后凡是想表达指向它的指针，都可以直接在这个名字前面加一个星号。

顺序记法只有一条：先按声明语法把变量读出来，再把变量名换成别名，读出来的那句话就是这个别名代表什么类型。

## 逐层拆一个混合声明

`int (*arr[5])[4];` 这个声明把三种结构叠在一起，按固定动作拆：从名字 arr 出发，右边先遇到 `]`，所以 arr 首先是一个数组，长度 5；左边括号把 `*` 拉进来，所以数组的元素是指针；指针右边又遇到 `[4]`，所以它指向的是含 4 个 int 的数组。合起来念：arr 是一个含 5 个元素的数组指针类型——每个元素都是一个数组指针，各自指向 4 个 int。

拆的时候只要记住两件事：`[]` 和 `()` 的优先级高于 `*`，括号能把优先级强行改写；每拆一层，就把已经确定的部分当作一个整体继续往外读。

## 下标本来就是指针运算

`x[6]` 与 `*(x + 6)` 是同一句话。`+ 6` 加的不是 6 个字节，是 6 个元素，偏移量由 x 指向的类型决定。

二维数组同理，`arr2[2][3]` 展开就是 `*(*(arr2 + 2) + 3)`：第一次 `+2` 在行这个单位上跳，解引用拿到第 2 行那一维数组，第二次 `+3` 才在元素上跳。所以 `int arr2[4][5]` 里 `arr2 + 1` 一步跨过 5 个 int。数组名在这里露出它的真面目：它是一个常量指针，仍然具备指针的运算能力，只是在 sizeof 和取地址两处有被特殊对待的身份。

## 编译器不查越界

`int arr[5];` 之后写一个下标 1000 的赋值，语法完全合法。越界就是编译器不管的事：下标只是地址偏移，它不知道也不关心那块地有多大。这条语句会往 arr 后面第 4000 字节写一个 1，写到谁的内存全看运气。

语法对，合法性失效。长度信息在 C 里不是类型的一部分，传数组进函数要另带一个长度参数，根子在这里；数组无法约束越界的问题，也是这门语言被诟病最多的地方。

## 声明与定义各自做什么

同一句话里，声明负责「让这个名字在这个作用域里可用」，定义负责「真的划出一块内存」。函数写原型是声明，写函数体是定义；变量写 `extern int n;` 是声明，写 `int n;` 是定义。编译阶段两者都能通过，只有定义会生成符号，这就是为什么只声明不定义时错误要到链接期才浮现。

读声明的能力直接决定读头文件的速度：一个 `.h` 里几乎全是声明，它把接口列出来给别的编译单元看，本身不占内存。反过来，把函数体写进头文件，就等于让每个包含它的源文件各自生成一份定义，撞名只是时间问题。

## 优先级只有一句话

`[]` 和 `()` 的优先级高于 `*`，括号可以把优先级强行改写。所有复杂声明的读法都从这一句出发：

- 名字右边先遇到 `[]`，它是个数组，元素类型由剩下的部分决定；
- 名字右边先遇到 `()`，它是个函数，返回类型由剩下的部分决定；
- 名字被括号包住、外面还有一个 `*`，它是个指针，指向括号里那套结构。

三条规则循环套用，直到读完为止。下面这几个声明按同一套动作拆，可以自测：一个含 10 个元素的数组，每个元素是指针，指向返回 int 的函数；一个指针，指向一个含 4 个元素的数组，数组每个元素是收两个 int 返回 int 的函数；一个函数，返回一个指针，指针指向含 5 个 int 的数组。第一个是函数指针数组，第二个是指向函数指针数组的指针，第三个是返回数组指针的函数——三个名字里出现了同样的符号，含义却两两不同。

## 结构体的三种声明写法

struct 是自定义成员组合行为的说明符，不是数据类型，因此写它的时候有三种常见形态，读法各不相同。

第一种是先写出成员表、给出一个类型名，之后再用这个类型名去开变量，类型与变量分两步完成。第二种是写完成员表不命名，直接跟在后面开出若干个变量，这种写法只有变量能用，后面再想声明同类型的对象就得重抄一遍成员表。第三种是给成员表起一个别名，之后凡是想要这个类型的地方都写别名，这是最省心的用法，也是把结构体当参数传递时唯一不容易写错的写法。

三种形态在内存上没有任何区别：占多大空间由成员决定，跟用哪种写法无关。区别只在于名字留在哪里、后续能不能复用。

## 二维数组做形参时为什么第二维必须写

调用时把二维数组名传进去，收到的是一个指向第一维元素的指针，也就是「指向一行」的指针。行内偏移要靠列宽计算，编译器在编译期插入的那次乘法用的乘数正是第二维的大小。第一维可以省略，因为它只影响总长度，不影响任何一次地址计算；第二维不能省略，缺了它，行下标就没有可乘的数，地址算不出来。

同理，指向数组的指针在声明时必须把那一维的宽度写全，否则它连自己加一该跨几步都不知道。这条限制和「数组的长度不属于类型的一部分」并不矛盾：前者是编译器需要宽度来算地址，后者是数组自身并不携带宽度可供运行期检查。

## 三个容易读错的地方

一是把返回指针的函数当成函数指针。`int *f(int);` 里 f 是个函数，调用它才得到指针；`int (*f)(int);` 里 f 才是指针，可以直接调用。两者只差一对括号。

二是在 typedef 里改了名字却没改含义。typedef 不产生新类型，别名代表的是被替换掉的那一整段，用它开数组和用原始写法开数组得到完全一样的内存布局，只是可读性不同。

三是把数组名当成普通指针去自增。数组名是常量指针，具备指针的运算能力却不能被赋值，`arr++` 这类写法编译期就会被拒绝，想移动只能另开一个指针去接。

## 声明读法和表达式读法是一套

C 的设计里，声明与表达式共用同一套语法：一个变量怎么声明，就怎么在表达式里使用它。`int *p;` 声明 p 是指针，于是 `*p` 是它指向的那个 int；`int *p[5];` 声明 p 是含 5 个指针的数组，于是 `p[2]` 是其中一个指针、`*p[2]` 是它指向的 int。读复杂声明时把「假定已经按这个声明写了一次使用」当作校验手段，能立刻发现括号位置放错。

写函数指针的调用时这条规律最有用：`(*f)(3)` 与 `f(3)` 都能编译，前者是把声明里的用法照搬过来，后者是语言允许的简写。反过来看 `int *f(int);`，按同一套读法，`f(3)` 的结果是个指针，再解引用才拿到 int，这就说明 f 本身不是指针而是函数。

## 读法练习的自检顺序

拿到一个陌生的声明，按四步自检：先找变量名；再看它右边第一个遇到的符号是 `[]`、`()` 还是 `*`；然后看有没有括号改变了这个顺序；最后把剩下的部分当成一个整体继续往外读。四步走完，任何一个声明都能读成一句中文。

读出来之后要能反向写回去。如果同一段含义能写出两种形式——一种直接写、一种先用 typedef 把中间那段命名掉——说明真的读懂了，因为这两种形式在内存布局上必须完全一致，写错一个括号就会得到完全不同的布局。

## 对照着背

| 想表达 | 写法 |
| --- | --- |
| 5 个 int 指针 | `int *p[5];` |
| 指向含 5 个 int 的数组的指针 | `int (*p)[5];` |
| 5 个函数指针 | `int (*p[5])(int);`，或先用 typedef 把函数指针类型命名掉再开数组 |
| 数组元素个数 | `sizeof(arr) / sizeof(arr[0])`，只在数组没退化成指针的作用域里成立 |

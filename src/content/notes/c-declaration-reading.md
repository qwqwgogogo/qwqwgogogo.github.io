> 题目和顺序来自数据结构直播课的随堂材料，下面这份是我自己重新写的一版，不是课件原文。

## 一句话

C 的声明不是「读一遍就懂」，是**按固定顺序拆**：从变量名出发，先看右边再看左边，括号优先。拆对了，`int (*arr[5])[4]` 这种也能一口念出来。

## 名字往右，括号打断

| 声明 | 读法 |
| --- | --- |
| `int *p;` | p 是指针，指向 int |
| `int *p[5];` | p 先是数组（`[]` 比 `*` 优先级高），5 个 int 指针 |
| `int (*p)[5];` | 括号把 `*p` 提前，p 是指针，指向一个 5 个 int 的数组 |
| `int (*p)(int);` | p 是指针，指向一个「收 int 返回 int」的函数 |
| `int *p(int);` | p 是函数，返回 int 指针 |

同一个 `*`，位置挪一格意思就换了，所以判断依据永远是**优先级**，不是看起来像什么。

## typedef 只是起别名

```c
typedef int len_t;			// 给 int 起个名字叫 len_t
typedef int (*afun)(int);		// 给「收 int 返回 int 的函数指针类型」起个名字叫 afun
```

`afun xyz[5];` 和 `int (*xyz[5])(int);` 是同一句话——前者只是把后面那串噪音折进了一个名字里。typedef 的用法就一条：**把最难读的那一段换成一个词**，函数指针数组这种类型，不用 typedef 写出来基本没法维护。

顺序记法：先按声明语法把变量读出来，再把变量名换成别名，就是「这个别名代表什么类型」。`afun` 读作「xyz 是 5 个 afun」，展开就是 5 个函数指针。

## 下标本来就是指针运算

```c
x[6]  ==  *(x + 6)
```

`+ 6` 加的不是 6 个字节，是 6 个元素——偏移量由 `x` 指向的类型决定。二维数组同理，`arr2[2][3]` 展开就是 `*(*(arr2 + 2) + 3)`：第一次 `+2` 在「行」这个单位上跳，解引用拿到第 2 行那一维数组，第二次 `+3` 才在元素上跳。所以 `int arr2[4][5]` 里 `arr2 + 1` 一步跨过 5 个 int。

## 编译器不查越界

```c
int arr[5];
arr[1000] = 1;		// 语法完全合法
```

下标只是地址偏移，编译器不知道也不关心那块地有多大。这行代码会往 `arr` 后面第 4000 字节写一个 1，写到谁的内存全看运气。**语法对，合法性失效**——长度信息在 C 里不是类型的一部分，传数组进函数要另带一个长度参数，根子在这。

## 对照着背

| 想表达 | 写法 |
| --- | --- |
| 5 个 int 指针 | `int *p[5];` |
| 指向含 5 个 int 的数组的指针 | `int (*p)[5];` |
| 5 个函数指针 | `int (*p[5])(int);`，或 `typedef int(*afun)(int); afun p[5];` |
| 数组元素个数 | `sizeof(arr) / sizeof(arr[0])`，只在数组没退化成指针的作用域里成立 |

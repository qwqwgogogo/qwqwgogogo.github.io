## 一句话

乘除法的硬件里**没有乘法器和除法器**，只有加法、减法和移位；补码的麻烦全在符号位也参与了运算，所以每一步都得先判断「这次该加还是该减」。

## 乘法：原码分开算，补码一起算

原码一位乘最直白：

1. 乘积的符号位 = 两数符号位**异或**；
2. 数值位 = 两个绝对值做无符号乘法。

硬件上就是「判断乘数当前位 → 是 1 就把被乘数加进部分积 → 右移」，循环 n 次。

补码不能这么干。一个根本的坑：

```
[X * Y]补 ≠ [X]补 × [Y]补
```

把两个补码当成无符号数直接乘，结果是错的，因为补码的符号位带的是 `-2^n` 这个**负的权值**，不是普通的最高位。Booth 算法就是每次看乘数相邻的两位，决定这一步加、减还是不动，把那个负权值摊进每一轮的加减里：

设乘数补码为 `Y_n Y_{n-1} ... Y_0`，真值满足 `Y = -Y_n·2^n + Σ Y_i·2^i`。把这个式子按两位一组拆开，就得到 Booth 的规则——**多看一位，`Y_{-1} = 0` 作初值**，每次考察相邻的 `(Y_i, Y_{i-1})`：

| `Y_i Y_{i-1}` | 操作 |
| --- | --- |
| `00` | 不加不减 |
| `01` | 加 `[X]补` |
| `10` | 加 `[-X]补`（即减 X） |
| `11` | 不加不减 |

做完加法后，**部分积和乘数一起算术右移一位**（补符号位，不是补 0）。循环 n 次，高位留在部分积寄存器、低位留在乘数寄存器，拼起来就是双字长的乘积。

`00` 和 `11` 什么都不做，正是 Booth 的价值：乘数里连续的一长串 1 或 0 只需要在边界处各操作一次，比逐位判断快。

## 除法：恢复余数 vs 加减交替

先回忆关系式：**被除数 = 商 × 除数 + 余数**，且余数绝对值小于除数。

最笨的办法（恢复余数法）是：先减一次除数试试，够减就商 1、余数留下；不够减（结果为负）就**把刚减掉的除数加回去**，商 0。每次试错失败都要多花一次加法。

不恢复余数法（加减交替法）的观察是：既然不够减时余数是负的，那就别加回去。设减完得到负余数 `R`，恢复后左移再减是 `2(R + B) - B = 2R + B`——**「加回除数、左移、再减」这三步合并，就是「左移、再加除数」**，恢复那一步整个省掉。整个算法压成六个字：

> **正、1、减；负、0、加。**

中间余数为正 → 上商 1，余数和商左移一位，下次做**减**法；
中间余数为负 → 上商 0，余数和商左移一位，下次做**加**法。

这样每轮步骤完全规整，差别只在加还是减，控制逻辑简单。只有一个尾巴：**最后一步如果上商为 0，余数是负的，必须恢复一次**（把试商减掉的除数加回去），否则余数不对。

## 原码除和补码除的分别

| | 符号位 | 数值位 | 判够不够减 |
| --- | --- | --- | --- |
| 原码除法 | 被除数与除数符号异或 | 绝对值做无符号除 | 看余数正负即可 |
| 补码除法 | 参与运算 | 全程补码 | 要看余数和除数**是否同号**，同号才够减 |

补码除法里商的末位精度是个麻烦，常见两种处理：**校正法**多求一位商再修正，或者**恒置 1 法**末位直接置 1、不多求那位。

## 对照着背

| 算法 | 每次判断什么 | 移位方向 | 循环次数 |
| --- | --- | --- | --- |
| 原码一位乘 | 乘数最低位是 0 还是 1 | 右移 | n |
| Booth 乘法 | 乘数相邻两位 | 算术右移 | n |
| 恢复余数除 | 减完是否为负，负则回退 | 余数左移 | n |
| 加减交替除 | 余数符号定下次的加减 | 余数和商左移 | n（末商 0 要恢复） |

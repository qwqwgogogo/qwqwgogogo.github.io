## 一句话

Cache 赌的是「主存里的这一小块会反复用」，虚拟存储器赌的是同一件事的下沉版本：「主存里的这一小部分会反复用」。它把主存当成磁盘上更大地址空间的高速缓冲，让程序看见一个连续、私有、比真实内存大得多的地址空间。

## 两个历史动机

**第一个动机是消除物理内存大小对程序设计的限制。** 早期内存既贵又小，写大程序要靠人工把程序切成段、安排哪一段什么时候装进内存、哪一段什么时候覆盖掉，程序员必须清楚物理布局，稍不留神就写错。虚拟存储器把这件事彻底交给了硬件和操作系统：程序可以用比主存大得多的地址空间，不活跃的部分自动留在磁盘上。

**第二个动机是提高内存使用效率和程序之间的隔离。** 每个进程拿到独立的虚拟地址空间，操作系统保证一个进程无法直接读写另一个进程的数据，安全性和稳定性由此而来。页面粒度的分配与回收也提高了复用率。

到了虚拟化普及之后，第一个动机相对退居次要，第二个反而成了主角：一台物理服务器上跑多个虚拟机，靠的正是「每个虚拟机看到的是自己独立且连续的地址空间」这一条，从而能在同一批 DRAM 上动态分配、互不越界。

## 虚拟地址空间与保护

进程产生的地址是**逻辑地址**（虚拟地址），它在一个从 0 开始的连续空间里；真正在地址线上跑、驱动存储矩阵的是**物理地址**。两套地址之间的映射由**地址转换**机制完成，硬件上落在内存管理单元 MMU 里。

MMU 的工作不止换算地址，还要在换算的同时查权限：页表项里带着读写许可和访问位标记，某些页被标成只读或根本不允许访问，进程一旦违反，MMU 就抛出一个异常，由操作系统决定是终止进程、还是调整内存布局。保护就是在这一趟顺路完成的。

编译期用逻辑地址而不是物理地址，程序才能被放到主存的任意位置去运行，装载时不需要重新翻译指令，这也是模块独立编译和链接的前提。

## 页式管理

页式把逻辑地址空间和主存空间都切成**固定大小**的块：逻辑侧的叫页面（页），主存侧的叫物理块（页框）。两者大小严格相等，通常 4KB。

因为长度固定，页面与物理块之间的对应关系可以随时间任意改变，装进去的页不要求位置连续，只要能通过一张表找到就行——这张表就是**页表**。

逻辑地址被天然切成两段：

```
|     页号 P     |   页内偏移 W   |
```

页内偏移的位数由页面大小决定，页面 4KB 就是低 12 位；页号位数由逻辑地址空间大小除以页面大小决定。取页号的过程就是把逻辑地址右移 12 位，取偏移就是与 `0xFFF` 相与，全是指定位段操作，没有任何除法。

转换过程四步：

1. 从逻辑地址拆出页号 P 和页内偏移 W。
2. 以 P 为下标查页表，取出对应的页表项。
3. 检查该项的有效位：为 1 说明这页此刻在主存里，取出物理块号 f。
4. 物理地址 = `f × 页面大小 + W`，偏移原样搬过去，一个比特都不用变。

页表项除了块号，通常还带有效位、地址改变位（脏位）、存取控制（读写执行权限）、存在位与访问统计位。表越大，越需要靠快表去挡——那是下一篇的主题。

**页式的代价是内部碎片**：一页不管装满没装满都要占掉一整个物理块，平均浪费半页。好处是完全没有外部碎片，任何空闲物理块都能装任何一页，内存回收简单到只需要一个空闲块列表。

## 段式管理

段式走的是另一条路：切分的依据是**逻辑意义**，一个主程序段、一个子程序段、一个数据段、一个符号表段，各成一段。段的长度由程序本身决定，因此段长不固定。

逻辑地址被切成两段：

```
|   段号 S   |   段内偏移 d   |
```

系统里有一张段表，每个段表项至少存两样东西：**段基址**和**段长**。转换时以段号查段表，先判断 `d` 是否小于段长——不小于就越界，触发中断，因为偏移已经跑出了这个段的边界，属于非法访问。判断通过，物理地址 = `段基址 + d`。

段式的好处很实在：段的边界就是模块的边界，权限和共享可以按段设置，编译好的模块可以单独增长而不影响别的段。坏处也很实在：段长不固定，主存里就会出现装不进任何一段的空隙，即外部碎片，要靠拼接整理来治；而且段的长度是变长的，页内偏移那种「取低位」的简单切分在这里换成了需要一次比较大小的运算。

段页式是两者的折中：先按逻辑意义分段，段内再按固定大小分页，兼顾了保护共享和没有外部碎片，代价是地址要拆成三段、查表要走两级。

## 一次访存要走几步

页表本身存在主存里，这就带来一个直接的后果：**取一个数据要先取它的地址映射**。

- 没有快表的一级页表：访存 2 次，第一次读页表项，第二次读真正的数据。等效访问时间大约翻倍。
- 有快表且命中：访存 1 次，地址转换在硬件里当场完成。
- 二级页表且快表不命中：读页目录、读页表、读数据，3 次访存。
- 页面根本不在主存：触发缺页，要走操作系统，代价是几个数量级的跃升。

算例（页式，页面大小 1024 字，逻辑地址空间 65536 字）：逻辑地址被切成高 6 位页号、低 10 位偏移。访问逻辑地址 `3200`：页号 = `3200 ÷ 1024 = 3`，页内偏移 = `3200 mod 1024 = 128`。查页表得页号 3 对应物理块号 5，物理地址 = `5 × 1024 + 128 = 5248`。

同一件事换成十六进制看更直观：页面 4KB 时，逻辑地址 `0x3A2B` 的页号是 `0x3`、偏移是 `0xA2B`；若该页落在物理块 7，物理地址就是 `0x7A2B`——低 12 位一个都没动。

## 页表自己也要占内存

页表是一个数组，下标是页号，元素是页表项，所以它的长度直接由逻辑地址空间的页数决定，这一笔账必须会算。

算例：32 位逻辑地址、页面 4KB、每个页表项 4 字节。页数 = `2^32 / 4KB = 2^20 = 1M` 页，单级页表大小 = `1M × 4B = 4MB`。**每个进程一张页表就是 4MB**，几十上百个进程直接把主存吃掉一大块，而且绝大多数表项指向的页根本不在主存里，纯属空转。

解决办法是把页表分级。两级页表下，1M 页的页号被拆成 `10 位页目录号 + 10 位页表号`：页目录 1024 项占 4KB，正好一页；每个页表也 1024 项占 4KB。关键是**只为真正用到的地址区间分配二级页表**，一个只用了低地址和栈区的进程，可能只需要一个页目录加两三个页表，十几 KB 就够，稀疏地址空间的浪费由此消掉。代价是一次地址转换要访问两级表，硬件上还要额外保留页目录基址寄存器。

同理可推三级、四级页表——64 位机器上的多级页表就是这么一层层加出来的，级数每多一级，快表未命中时的访存次数就加一次。

## 缺页与 Cache 缺失不是一回事

两者结构上同构，工程上完全不同，这张对照表值得记牢：

| | Cache 缺失 | 缺页 |
| --- | --- | --- |
| 交换单位 | 块，几十到上百字节 | 页，4KB 量级 |
| 由谁处理 | 硬件，对程序透明 | 操作系统，是一个内部中断 |
| 数据来源 | 主存 | 磁盘上的交换区 |
| 代价量级 | 几十纳秒 | 毫秒量级，差五到六个数量级 |
| 有没有选择余地 | 直接映射下位置唯一 | 必须选一个页换出去，涉及置换算法 |
| 处理不好会怎样 | 性能下降 | 系统可能整片卡死 |

缺页发生时，进程当前这条指令被中止，CPU 陷入操作系统；操作系统在磁盘上找到那一页，挑一个物理块（必要时先把它上面的页写回磁盘），把新页读进来，更新页表和快表，再回到原来那条指令重新执行。**代价这么大，所以判断一个页面置换策略好坏的标准只有一个：缺页次数。**

## 为什么这套东西行得通

支撑虚拟存储器的仍然是局部性：程序在任意时刻频繁访问的页只占它整个地址空间的一小部分。

这一小部分活跃页留在主存里，其余全放磁盘。只要活跃集合装得下，缺页就很少发生，程序感受到的就是一个「又大又像内存一样快」的存储器。

反过来，一旦同时运行的进程太多、各进程的活跃页加起来超过主存容量，系统就把大量时间花在换入换出上，这一现象叫抖动，是局部性假设被破坏后的典型后果。

## 带走的东西

概念上只有三句：地址转换把逻辑地址换成物理地址；页表存这张映射；有效位为 0 就说明这一页不在主存里、要触发缺页。计算上只有两句：页内偏移的位数由页面大小决定，物理地址等于块号乘页面大小再加偏移；段式则要先把段内偏移和段长比一次大小，越界就中断。剩下的都是这三句和两句的展开。

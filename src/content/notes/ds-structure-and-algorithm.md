## 内存需要先被组织起来

C 语言编程的目的，是在内存上管理空间，并实现对空间值的读写。语言本身给出的只是一段段可以读写的地址，而现实世界里的东西之间是有关系的：一份成绩单里学生与课程是多对多，一棵家族树里一个父亲对应多个孩子。要把这段空间构造成物理世界的逻辑，就需要定义高效的结构来处理。

数据结构讨论的正是这两件事：用什么逻辑结构表示物理世界，用什么存储结构让计算机处理起来更方便、更有效。前者关心元素之间是什么关系，后者关心这段关系在内存里怎么摆。

## 逻辑上只有三类关系

按元素和元素之间的逻辑关系来分，一共三类。

**线性逻辑**：元素和元素之间存在 1:1 的关系，前一个后面紧跟后一个，表、栈、队列都属于这一类。

**非线性结构**里的**层级关系**：元素和元素之间存在 1:n 的关系，一个父结点对应多个子结点，树是标准形态。

**非线性结构**里的**图集关系**：元素和元素之间存在 m:n 的关系，任意两个结点之间都可能连着，图是标准形态。

判断属于哪一类，只看一个结点最多能有几个前驱、几个后继，与它存在内存里是什么样子无关。

## 一个运动会的排期问题

田径比赛有六个项目：A 跳高、B 跳远、C 标枪、D 铅球、E 100m 跑、F 200m 跑。每位选手可以报名多个项目，每个项目又有多人报名，于是给出参赛选手的项目表。要安排比赛时间，使每个比赛项目都能顺利进行（同一选手不能同时出现在两个项目里），并且尽可能缩短比赛总时长。

这道题的关键不在怎么排，而在怎么把「选手—项目」这层 m:n 的关系表示出来。用线性结构表达会退化成一张冗长的对照表，用图集把选手和项目都当成顶点、报名关系当成边，冲突才第一次变成可以直接检查的对象。这也是图集关系存在的理由：当元素之间的关系是 m:n，线性结构和层级结构都表达不下。

## 存储方式与常用操作

逻辑结构在计算机里的实现方式叫存储结构，基本手段是顺序与链式两种，另有索引和散列两种派生形式。

**顺序存储**：元素物理上连续，数组就是最典型的形态，元素之间的关系由相邻的位置本身表达出来。

**链式存储**：元素物理上不连续，需要每个元素多保存一个与之关联的其他元素的地址，关系由这些地址显式表达。

**索引存储**在数据之外另建一张表，按关键字直接定位到地址；**散列存储**由关键字算出地址。

常用操作是增、删、改、查四种，效率高低取决于逻辑结构与存储结构怎么配对：知道位置时，顺序存储方便查找，按位置查找很快，按值查找效率低；知道位置时，链式存储方便增加和删除，指定位置直接插入删除，按位置插入删除则效率低。同一种线性表换一种存法，性能结论立刻改写，这就是逻辑结构决定运算、存储结构决定效率的含义。

## 数据结构是哪三件事

先说被装进去的东西：**数据**是描述事物的符号记录，**数据元素**是数据的最小单位，一个数据元素还可以由若干个**数据项**组成——表里的一个结点是一个数据元素，结点里的字段才是数据项。数据结构讨论的从来不是单个元素，而是元素之间的关系。

逻辑结构说数据之间是什么关系，跟内存怎么摆无关，它只有两大家：线性（一对一，比如表、栈、队列）和分支（一对多的树、多对多的图）。再细分就是集合、线性、树形、图形或网四类，树形和网形的差别在一个结点能不能有多个前驱。

存储结构就是数据的逻辑结构在计算机里的实现方式，只有四种基本手段：顺序（相邻存放，靠位置表达关系）、链式（不相邻，靠指针表达关系）、索引（额外建一张表，按关键字直接定位地址）、散列（由关键字算出地址）。

运算分两类：跟存储结构无关的运算描述（插入、删除、查找），以及依赖具体实现的算法。

## 算法和程序不是一回事

算法必须满足有穷性——运行有限步之后一定要停下来，这是它区别于程序的地方。一个程序可以永远跑下去（操作系统就是），所以它不是算法。除有穷性外还要有确定性（每一步含义唯一，不能看情况）、可行性（每步都能用已实现的基本操作完成）、足够个数的输入和输出。五个性质一起记，判断题常拿有穷性做文章。

算法是解决某个问题的想法与思路，程序是依据算法编写出来的、真正可以运行的代码，两者不能混为一谈。

## 线性结构的逻辑描述

一个数据元素序列要成为线性结构，需要同时满足三条：除第一个和最后一个元素外，每个数据元素只有一个前驱数据元素和一个后继数据元素；第一个数据元素没有前驱数据元素；最后一个数据元素没有后继数据元素。

这三条是纯逻辑的，不涉及内存。满足这三条的序列就是线性表，栈和队列是在线性表上限制插入与删除位置之后得到的受限结构。

## 五个名词的层次

从大到小排一遍，避免做题时把层次搞混。**数据**是描述事物的符号记录，是全体；**数据元素**是数据的基本单位，在程序里通常作为一个整体处理，一个数据元素可以由若干个**数据项**组成，数据项才是不可再分的最小标识单位；**数据对象**是性质相同的数据元素的集合，是数据的一个子集；**数据结构**是相互之间存在一种或多种特定关系的数据元素的集合，它由三要素组成——数据元素之间的逻辑关系、逻辑结构在计算机中的表示、以及对数据施加的运算与操作。

题目里问「数据结构研究的是什么」，答三要素即可；问「与计算机硬件有关的是哪一要素」，答的是存储结构，逻辑结构刻意与硬件无关。

## 四种存储手段各有代价

顺序存储把元素放在相邻位置，关系由位置隐含表达，好处是可以随机访问、不需要额外指针，代价是插删要移动一片、容量提前定死。链式存储把元素放在任意位置，关系由每个元素额外携带的地址显式表达，好处是插删只改线、容量随用随取，代价是多一份指针空间、只能顺藤摸瓜。

索引存储在数据之外再建一张表，表项由关键字和指向该元素的地址组成，按关键字查找很快，代价是表本身要占空间、插入删除时表也要同步维护。散列存储由关键字算出地址，理想情况下一次计算就能定位，代价是冲突必须另外处理。

四种手段可以混用：同一张表里主表顺序存放、溢出部分链式存放，就是索引加链式的组合。判断存储结构是否合适，只看这道题的读写比例和长度是否可估。

## 算法的评价标准

一个算法应当具备有穷性、确定性、可行性，以及足够个数的输入与输出，这五条是判断题的常客。衡量它的好坏看两个维度：时间复杂度与空间复杂度，前者是执行时间随规模增长的趋势，后者是所需辅助空间随规模增长的趋势。

同一问题可以有多种算法，选择依据先保证正确与健壮，再比较效率；效率的比较又要在同一规模、同一操作次数定义下进行，否则系数与低次项会把结论带偏。这也是复杂度分析只取数量级、不取绝对秒数的原因。

## 大O 只看增长趋势

时间复杂度就是运行时间随问题规模增长的趋势，把时间频度里最高次幂留下、丢掉系数与低次项，剩下的就是大O 记号里的 f(n)，写成 `T(n) = O(f(n))`。跑 2n 步和跑 100n 步属于同一阶 O(n)，这不是粗心，是故意不看常数——机器和执行细节会换，增长阶不会。

常见的几阶从小到大排：

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

判阶只有一个动作：找最内层循环执行了多少次。几层嵌套就把每层的次数相乘；`i` 每次翻倍就取对数；两个并列循环取较大的那个；递归要看递归树，`T(n) = 2T(n/2) + O(n)` 是 O(n log n)，`T(n) = T(n-1) + O(1)` 是 O(n)。

需要注意的是，大O 描述的是一个上界。真要说最坏情况得讲明场景，快排的 O(n²) 只在最坏输入出现，平均 O(n log n) 才是它真正的名声来源；空间复杂度只算辅助空间，输入本身占的那份不计进去，这个约定不记牢就会把归并排序的 O(n) 算错。

## 对照着背

| 对象 | 判定依据 | 结论 |
| --- | --- | --- |
| 线性逻辑 | 元素之间 1:1 | 表、栈、队列 |
| 层级关系 | 元素之间 1:n | 树 |
| 图集关系 | 元素之间 m:n | 图、网 |
| 顺序存储 | 物理连续，靠位置表达关系 | 查找定位快，插删要挪动 |
| 链式存储 | 物理不连续，靠附加地址表达关系 | 指定位置插删快，按位置访问慢 |
| 数据元素与数据项 | 是否为最小单位 | 结点是元素，字段是项 |
| 算法与程序 | 是否满足有穷性 | 能停下来的才是算法 |

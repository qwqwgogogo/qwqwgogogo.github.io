## 数据结构是哪三件事

**逻辑结构**说数据之间是什么关系，跟内存怎么摆无关。它只有两大家：线性（一对一，比如表、栈、队列）和分支（一对多的树、多对多的图）。再细分就是「集合、线性、树形、图形或网」四类，考题爱在「网状和树形差在哪」上问一句——差在一个结点能不能有多个前驱。

**存储结构**就是数据的逻辑结构在计算机里的实现方式，只有四种基本手段：顺序（相邻存放，靠位置表达关系）、链式（不相邻，靠指针表达关系）、索引（额外建一张表，按关键字直接定位地址）、散列（由关键字算出地址）。同一种线性表用顺序存还是链式存，性能差别立刻不一样，这就是「逻辑结构决定运算，存储结构决定效率」这句总结的意思。

运算分两类：跟存储结构无关的**运算描述**（插入、删除、查找），以及依赖具体实现的**算法**。

## 算法和程序不是一回事

算法必须满足有穷性——运行有限步之后一定要停下来，这是它区别于程序的地方。一个程序可以永远跑下去（操作系统就是），所以它不是算法。除有穷性外还要有确定性（每一步含义唯一，不能"看情况"）、可行性（每步都能用已实现的基本操作完成）、足够个数的输入和输出。五个性质一起记，判断题常拿「有穷性」做文章。

## 大O 只问趋势

时间复杂度就是运行时间随问题规模增长的趋势，记成 `T(n) = O(f(n))`，丢掉常数项和低阶项。所以「跑 2n 步」和「跑 100n 步」是同一阶 O(n)，这不是粗心，是**故意不看常数**——机器和执行细节会换，增长阶不会。

常见的几阶从小到大排：

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

判阶只有一个动作：**找最内层循环执行了多少次**。几层嵌套就把每层的次数相乘；`i` 每次翻倍就取对数；两个并列循环取较大的那个；递归要看递归树，`T(n) = 2T(n/2) + O(n)` 是 O(n log n)，`T(n) = T(n-1) + O(1)` 是 O(n)。

一个坑：大O 描述的是**上界**。真要说「最坏」得讲明场景，因为快排的 O(n²) 只在最坏输入出现，平均 O(n log n) 才是它真正的名声来源；而空间复杂度只算**辅助空间**，输入本身占的那份不计进去，这个约定不记牢就会把归并排序的 O(n) 算错。

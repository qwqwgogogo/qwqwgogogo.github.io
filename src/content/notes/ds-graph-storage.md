## 先把数关系背牢

图 G 由顶点集和边集组成，记作 V 和 E。设顶点数 n、边数 e：

| 概念 | 无向图 | 有向图 |
| --- | --- | --- |
| 完全图的边数 | `n(n-1)/2` | 弧数 `n(n-1)` |
| 度 | 所有顶点的度之和 = `2e` | 入度之和 = 出度之和 = `e` |
| 极小连通子图 | 生成树，`n-1` 条边 | 有向树 |

度就是与该顶点相连的边的条数；有向图里还要分成入度和出度。那两个「求和」是这一节的万能钥匙：题目给一堆顶点的度让你求边数，靠的就是边数等于度之和的一半。

连通指的是两顶点之间有路径；无向图里极大的连通子图叫连通分量——「极大」的意思是再加任何一个顶点就不再连通。有向图里对应的是强连通分量，要求任意两点之间**两个方向都有路径**。一个有 n 个顶点的无向图至少要 n-1 条边才可能连通。

生成树是一个连通图的极小连通子图：它包含全部顶点，恰好 `n-1` 条边。多一条边必定成环，少一条边必定不连通。图不连通时，各连通分量的生成树合起来叫生成森林。

完全图说的是任意两个顶点之间都直接有边相连，所以它的边数被顶点数唯一决定；从完全图里少掉几条边，就是稀疏图，边数接近这个上限的图则称为稠密图。

## 为什么图的存储比线性表和树复杂

线性表是一对一的关系，用数组或者链表就能把关系隐含在物理位置里；树是一对多，把数组和链表的特性结合起来也够用。图是多对多的情况，图上任何一个顶点都可以被看成第一个顶点，任一顶点的邻接点之间也不存在次序关系，元素之间的关系是平面的，而内存的物理位置是一维线性的，无法用存放位置本身来表达这种关系。理论上可以用多重链表来存，给每个顶点开一个能容纳最大度的结点区，可一旦各顶点的度数相差很大，这种方法造成的浪费无法想象。所以实际做法是把顶点和边分开记录，顶点用数组，边按不同的侧重点分成下面几种结构。

## 邻接矩阵

用一个 n 乘 n 的方阵存边，`A[i][j]` 有边就置 1，无边置 0，带权图则把 0 换成无穷大表示「不通」、把权值放在对应格。

优点是判断两点之间有没有边只要一次访存，算某个顶点的度就是数它那一行（无向图）或者分别数一行一列（有向图分别是出度和入度）。缺点是**空间只跟顶点数有关**：稀疏图里几万个顶点挂几十条边，矩阵绝大多数格子都是空的，而稠密图和带权图用它最省事。图的遍历在矩阵上是平方级的，因为每步都要扫一整行。

无向图的邻接矩阵沿对角线对称，所以理论上能压成下三角存，代价是取 `A[i][j]` 不再是一步直达。所谓对称矩阵，就是 n 阶矩阵的元素满足 a[i][j] 等于 a[j][i]，从左上角到右下角的主对角线为轴，右上角的元素与左下角对应的元素全都相等。判边、求度、找邻接点这三件事在对称矩阵上分别是一次访存、一次行求和、一次行扫描。

有向图的弧数组同样是矩阵，但因为边有方向，这个矩阵并不对称：由 V0 到 V3 有弧就把 arc[0][3] 置一，而 V3 到 V0 没有弧，arc[3][0] 仍是零。方向还带来行列分工，某个顶点的入度正好是它那一列的各数之和，出度正好是它那一行的各数之和，两个方向要分开数。

带权图的邻接矩阵把一换成权值，两个顶点之间没有弧时用无穷大表示，这里的无穷大是一个计算机允许的、大于所有边上权值的值。对角线一般填零而不是无穷大，无边与权为零的边也必须用不同值区分，否则最短路算法的初值会出错。

## 邻接表

每个顶点挂一条链表，链上记着与它相邻的顶点。空间降到「顶点数加边数」的量级，遍历也是这个量级，稀疏图用它。

具体构成是：顶点用一个一维数组存储，也可以改用单链表，但数组按下标读取顶点信息更方便；每个顶点 Vi 的所有邻接点构成一个线性表，由于邻接点个数不确定，这个表用单链表存储，结点里存邻接点在顶点表中的下标。无向图里一条边要在两端各挂一个结点，两个结点互为对偶，因此边表结点总数是边数的两倍，第 i 条链表的长度就是顶点 i 的度。

两处硬伤：判断两个顶点是否有边要顺着链表找，最坏 O(n)；有向图里求入度极难，因为按弧尾建表时链表中只记录从自己出发的方向——补一份逆邻接表专门记录谁指向我就解决了，代价是空间和维护翻倍。带权网络的邻接表则在边表结点里多加一个权值字段，其余结构不变。

邻接表还不唯一：同一张图的链表里结点顺序可以不同，所以两张图邻接表相同一定是同构的，反过来不成立。

## 十字链表和邻接多重表

这两个结构是为了补邻接表的两块短板而生的，考点全在谁给谁补。

十字链表服务有向图：每条弧做成一个结点，既有起点又有终点，还挂两根指针——一根串进起点的出边表，一根串进终点的入边表，顶点表里相应地要有出边入口和入边入口两个指针。于是一条边同时属于两条链，出度和入度都能顺着链表数出来，不必再存逆邻接表，空间只多几根指针。它的好处正是把邻接表和逆邻接表整合在一起，既容易找到以 Vi 为尾的弧，也容易找到以 Vi 为头的弧；除了结构复杂一点，创建图的算法时间复杂度与邻接表相同，所以在有向图应用里它是很好的数据结构模型。删除一条弧时要在两条链上分别把它摘出来，但因为数据只有一份，不存在两份表需要同步修改的问题。

邻接多重表服务无向图：邻接表里一条无向边因为两端各记一份，会被存两遍，两个边结点互为对偶，删除时要找两条并保持一致，给已访问的边做标记也标记不彻底。邻接多重表把一条边只存一个结点，结点里记两个端点下标 ivex 和 jvex，再用 ilink 指向依附顶点 ivex 的下一条边、jlink 指向依附顶点 jvex 的下一条边，此外还有权值域和一个访问标记域。两个顶点各挂一条链，链上的结点是共享的。它的遍历也因此要额外记这条边访问过没有，否则同一结点会被绕回来重复处理。若无向图应用的关注点是顶点，邻接表仍然够用；一旦关注点落在边上，比如反复标记和删除边，邻接多重表才显出优势。

## 边集数组

边集数组由两个一维数组构成，一个存储顶点信息，另一个存储边信息，边数组里每个数据元素由一条边的起点下标、终点下标和权组成。它本身不表达邻接关系，不适合做遍历和求度，但因为边是独立条目、可以整体排序，求最小生成树的按边选边做法就靠它，Kruskal 的实现通常直接以它为输入，配合一个记录连通块归属的数组来判断加上某条边会不会成环。

## 选择依据

判据只有一条：算法是围绕顶点推进还是围绕边推进，图是稀疏还是稠密。稠密图、带权图、要频繁判断两点是否相邻，用邻接矩阵；稀疏图、要枚举邻接点做遍历，用邻接表；有向图还要同时管两个方向的度，用十字链表；无向图要频繁操作和标记边，用邻接多重表；要按权排序逐条处理边，用边集数组。

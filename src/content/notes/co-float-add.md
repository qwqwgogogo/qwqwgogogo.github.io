## 一句话

十进制里 `1.23×10^6 + 4.56×10^3` 不能直接把尾数相加，得先把指数对齐——浮点数一模一样。整个流程就五步：**对阶 → 尾数运算 → 规格化 → 舍入 → 判溢出**。

## 第一步：对阶，只能小阶向大阶看齐

原则：阶小的那个数，尾数**右移**，右移位数等于两个阶之差；阶码本身不动，最后取那个大阶。

为什么不能反过来（大阶向左移、把大阶改小）？因为两种移动丢的东西不一样：

- **尾数右移**丢的是最低位——那是**精度**，影响很小，而且可以用附加位先留着；
- **尾数左移**丢的是最高位——那是**有效数字的开头**，一个规格化数左移把 1 移出去了，误差是数量级的。

还有个特例：如果反过来做，阶小的那个数一旦阶码减到越界，就直接变成下溢，本来能算的也算不出来了。

工程上的处理是：**移出的低位不丢，保留在附加位里参加后续运算**，最后再一次性舍入。

## 第二到三步：尾数运算和规格化

对阶之后两个数指数相同，尾数就是普通的定点小数加减。IEEE 754 的尾数是原码小数，所以这一步等价于定点原码加减。注意**隐藏位要先还原**成 `1.f` 再参加运算。

加减完的尾数未必还是规格化形式，要处理：

| 情况 | 操作 | 效果 |
| --- | --- | --- |
| 尾数出现 `00.1xxx` / `01.xxx` 这种最高位不是 1 的 | **左规**：尾数左移一位，阶码减 1，直到第一位是 1 | 阶码变小，可能下溢 |
| 尾数相加进了位，形如 `10.xxx` | **右规**：尾数右移一位，阶码加 1 | 阶码变大，可能上溢 |

左规可能要做多次（结果很小、前面一堆 0），右规最多一次。

## 第四步：舍入，靠三个附加位

IEEE 754 要求中间结果的右边**至少额外保留两位附加位**，实际实现是三位：

| 位 | 名字 | 管什么 |
| --- | --- | --- |
| G | 保护位 guard | 尾数右移时移出来的那一位 |
| R | 舍入位 round | G 右边的下一位，决定往哪舍 |
| S | 粘位 sticky | R 右边**只要有任何非 0 就置 1**，否则为 0 |

粘位是个便宜的压缩：它不关心右边到底有多少位、是什么值，只关心「后面还有没有东西」。有了 S，舍入判断只需要看 `GRS` 三位。

舍入方式有四种：就近舍入（0 舍 1 入，遇到正好一半时**取偶**，这是默认）、朝 +∞、朝 −∞、朝 0（直接截断）。取偶而不是永远进位，是为了让舍入误差在大量运算里正负抵消，不会一路偏。

## 第五步：判溢出，看阶码不看尾数

这是最反直觉的一条：**尾数溢出不是溢出，阶码溢出才是。**

- 尾数相加进了位（`10.xxx`）→ 右规一次就纠正了，值本身没错；
- 右规时阶码 +1，如果阶码本来已经是全 1（规格化可用的最大值），加完就撞上 `1111 1111` → **上溢**，这才是真溢出，机器报异常或把结果置成 `±∞`；
- 左规时阶码 −1，减到 0 → **下溢**，结果按 0 或者转成非规格化数处理。

所以判断的正确顺序是：**先看看该不该动阶码，再动，再看动完有没有越界**。右规之前如果阶码已经全 1，就根本不用右规了，直接判上溢。

## 完整走一遍：`0.5 + (-0.4375)`

```
0.5      = 1.0 × 2^-1        →  E = 126
-0.4375  = -1.11 × 2^-2      →  E = 125
```

1. **对阶**：阶差 1，小阶的 `1.11` 右移一位变成 `0.111`，阶码取大的 `-1`；
2. **尾数运算**：`1.0 + (-0.111) = 0.001`；
3. **左规**：`0.001` 前面三个 0，左移三位成 `1.0`，阶码从 `-1` 减到 `-4`；
4. **舍入**：没有移出位，不动；
5. **判溢出**：阶码 `-4` 远在范围内。

结果 `1.0 × 2^-4 = 0.0625`，和十进制 `0.5 - 0.4375` 一致。

## 乘除法的区别只有一处

乘除**不需要对阶**：乘法是尾数相乘、阶码相加；除法是尾数相除、阶码相减。后面的规格化、舍入、判溢出完全一样。乘法也不需要左规——两个 `1.b` 相乘，小数点左边最多是 `01`、`10`、`11` 三种，只有可能需要右规一次。

## 一句话

主存这一侧的速度天花板来自一个物理事实：**一次存取没做完之前，同一批电路不能开始下一次**。想突破它只有两条路——要么把一大块存储器切成很多能各自独立工作的体，让它们轮班；要么给同一块存储器配两套端口，让两个主设备不必互相等。前者叫多体并行，后者叫双端口。

## 单体为什么是瓶颈

单体存储器的存取周期是从启动一次读写到下次能再启动之间的最短间隔，它包含了选行、放大、读出、送总线这一整套动作。在这整段时间里，地址译码器、存储矩阵、读出放大器全被占着。CPU 就算只想要一个字节，也得等这一整套走完。

处理器速度按摩尔定律往上翻，存储器的存取周期却几乎原地不动，缺口只能靠上层 Cache 去挡。但 Cache 挡不住缺失，一次缺失就直接落到主存上，所以主存自身的吞吐也必须一起想办法。

## 多体并行：两种切法

把主存切成若干个容量相同、各自带独立读写电路和独立数据通路的**存储体**，每个体都能独立地完成一次存取，这是多体并行的物质基础。切法有两种，效果天差地别。

### 高位交叉（顺序方式）

把地址的高位用来选体，低位作为体内的块号。结果是：同一个体内 address 连续排列，编到 M 个体之后才回头。

这种切法的唯一收益是**扩容量**——增加体数就能线性增加地址空间，控制逻辑简单，体与体之间不需要协调。

高位交叉拿不到任何并行好处，因为顺序执行时相邻地址全落在同一个体里，而这个体要等上次存取结束才能再启动。

所以高位交叉不算真正的并行存储体系，它只是把容量堆起来的一种编址约定。

### 低位交叉（编址方式）

反过来，把地址的低位用来选体，高位作为体内块号。具体就是：块号 = `地址 mod 体数`，体内地址 = `地址 div 体数`。

这样顺序编址的相邻字被**均匀散布到不同的体里**：地址 0 在体 0，地址 1 在体 1，一直到地址 M-1 在体 M-1，地址 M 才回到体 0。程序按顺序取指令或按行遍历数组时，接下来要用的字恰好分布在 M 个可以独立工作的体里，于是流水线式存取成为可能。

流水线的规则是：**每隔一个总线传送周期就可以启动下一个体**，不必等前一个体完成整个存取周期。能这么做的条件是每个体被再次启动之前有足够时间恢复，即 `总线传送周期 ≤ 存取周期 / 体数`。

### 算例

四个存储体做低位交叉，每个体的存取周期 `T = 200 ns`，一次总线传送占用 `τ = 50 ns`。先验一下条件：`T / M = 200 / 4 = 50 ns`，正好等于 `τ`，可以流水。

从体 0 开始连续读 4 个相邻字：

| 时刻 | 动作 |
| --- | --- |
| 0 ns | 启动体 0 |
| 50 ns | 启动体 1 |
| 100 ns | 启动体 2 |
| 150 ns | 启动体 3 |
| 200 ns | 体 0 的数据可用，同时可再次启动体 0 |

连续读 `n` 个字所需时间的一般式是 `T + (n-1) × τ`。代入 `n = 4` 得 `200 + 3×50 = 350 ns`，而单体顺序读四个同样的字要 `4 × 200 = 800 ns`，速度提升约 2.3 倍。体数越多、访问越连续，带宽越接近单体时的 M 倍。

如果低位交叉遇到的是**跨体冲突**——两个并发请求恰好落在同一个体上——那一个请求必须排队，流水被打断。这也是低位交叉对「连续、跨步为 1」的访问模式最友好，而对固定大步长跨步访问（比如按列遍历一个 M 行 M 列的矩阵，步长恰为体数的倍数）最不友好的原因：所有访问都会撞到同一个体上，并行度直接归零。

## DRAM 内部的并行：行缓冲与 bank

多体并行的思想在 DRAM 芯片内部也有一份对应物，尺度更小但逻辑一致。

DRAM 把存储阵列划成若干个可以独立操作的 bank，每个 bank 有自己的行译码器和**行缓冲**。访问某个单元时要先激活它所在的行，把整行内容读进行缓冲，之后的列访问才有数据可用。行缓冲命中时后续访问几乎是即时的，代价在换行：关掉当前行需要预充电，再打开新行又要一次激活，这段时间是纯浪费。

有了多个 bank，控制器就可以**交错访问**：一个 bank 正在预充电或刷新时，把请求发到另一个已经打开的 bank 上去，从而把行切换的延迟藏起来。每个 bank 都有自己的行缓冲，这是它能独立工作的前提。

在此之上还有**突发传输**：一次列地址给出后，芯片按固定的顺序自动连续送出若干个数据字，不需要每个字重新送地址。DDR 标准里的 8 位突发长度就是把这一条写进规范的。它和多体并行的目标一致——把每次启动的固定开销摊到更多数据上。

## 双端口存储器

双端口存储器解决的是另一个问题：两个主设备都要访问同一块存储器。

双端口存储器的每个存储单元配两套独立的读写电路，芯片上因此有两组完全分开的地址线、数据线和读写控制线，两个端口可以各自被一个主设备驱动。

典型场景是 CPU 和一个 DMA 控制器（或两个处理器、显示控制器与 CPU）共享同一块缓冲，比如帧缓冲和高速度 FIFO 队列。

判断能不能并行，只看一件事：**两个端口此刻访问的是不是同一个单元**。

- 访问不同单元：两端口各走各的通路，完全并行，互不干扰。
- 访问同一单元：发生争用。若两个都是读，可以允许同时进行；只要有任一方要写，就必须分出先后。

分先后靠芯片内部的**仲裁逻辑**：它比较两个端口的地址选通信号是否重合，再用一片忙（BUSY）和一个等待（READY）标志来通知吃了亏的那一方「这次没读成，请保持地址重试」。被判定先服务的那个端口正常完成读写，另一个端口在这一次被挂住，等仲裁结束后重新发一遍。

仲裁策略可以是固定优先级（某端口总占优），也可以是动态轮流（上一次让给 A，这一次就优先 B），后者能保证双方都不饿死。

## 两条路的分工

| 维度 | 多体并行 | 双端口存储器 |
| --- | --- | --- |
| 想解决的问题 | 单体串行存取限死了带宽 | 两个主设备争用同一块存储器 |
| 手段 | 切成多个能独立工作的体，按低位交错流水 | 每单元两套读写电路，两个端口 |
| 关键限制 | 并发请求撞到同一个体 | 两端同时访问同一单元 |
| 容量扩展 | 加体即加容量，线性扩展 | 单元数不变，只加端口 |
| 成本压力 | 译码与协调逻辑变多 | 每单元电路翻倍，面积和功耗大 |

**多体并行是把一条流水线拉宽，双端口是给同一块存储器多开一个入口**，两者不冲突，真实系统里常常同时存在。它们和 Cache 的关系也很清楚：Cache 靠预测把访问挡在上层，多体和双端口则是当访问真的落到主存时，让主存本身尽量快地应答。

## 再练一组数

把条件换成八个存储体低位交叉，每个体的存取周期 `T = 500 ns`，总线传送周期 `τ = 100 ns`。先检查能否流水：`T / M = 500 / 8 = 62.5 ns`，而 `τ = 100 ns` 比它大，条件不满足——这意味着体还没恢复过来就要被再次启动，流水线会被体自身的恢复时间卡住。

此时有效的启动间隔应当取 `max(τ, T/M) = 100 ns`，读八个连续字的总时间仍可按 `T + (n-1) × 100 = 500 + 700 = 1200 ns` 算出，而单体串行读八字要 `8 × 500 = 4000 ns`，仍有 3.3 倍收益，只是达不到理想上的 8 倍。

结论要说得准确：**体数不是越多越好，超过 `T/τ` 之后再加体只是白花钱**，因为总线传送已经成了限制并行度的那个瓶颈。

## 突发长度和块大小是同一件事的两头

多体并行和 DRAM 的突发传输都在做同一个动作：把一次启动的固定开销摊到多个数据字上。这条思路往上一级延伸，就变成 Cache 的块大小选择。

Cache 里一个块是多少字节，决定了缺失时向主存要多少数据；主存侧一次突发能连续送出多少字，又决定了这个请求最自然的粒度。两边对不齐时，要么突发没填满、总线带宽浪费，要么一次突发跨了两个块、控制逻辑要额外拆分。所以现代机器上「Cache 块大小 = 主存突发传输长度 × 总线宽度」是很常见的约定。

这也解释了为什么按行遍历数组快、按列遍历同一个矩阵慢：行遍历的访问序列恰好是连续地址，能被低位交叉均匀分到各个体上，也能被一次突发覆盖；列遍历的步长等于矩阵的列数，一旦这个步长是体数的整数倍，所有访问撞进同一个体，并行度退化到单体，同时每次跨行还要重新激活行、把行缓冲里刚装好的数据扔掉。

## 小结

这一篇里能带走的公式只有一条：低位交叉连续读 `n` 个字用时 `T + (n-1)τ`，条件是 `τ ≤ T/M`。能带走的概念也只有一条：**并行的来源是「独立的控制通路」，而不是「更多的容量」**——高位交叉加了容量却没加通路，所以没有并行；多体和双端口都是实打实地在增开通路。

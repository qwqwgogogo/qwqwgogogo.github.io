## 什么时候轮到动态规划

三个条件同时满足才用它。**最优子结构**指大问题的最优解里包着小问题的最优解——把子问题的最优解替换成别的，整体不会更好。**重叠子问题**指递归下去会反复算同一批小问题，这是动态规划相对分治的分水岭：分治处理的子问题互不重叠，动态规划靠把结果存下来避免重复计算。**无后效性**指当前状态一旦确定，它之后怎么走与它是怎么来的无关——这是「能按一层一层往前推」的前提。

写法有两种：自底向上填表（递推），或者自顶向下加备忘录（记忆化递归）。两者时间一样，递推少了递归开销、还能顺手做空间优化；记忆化只算真正被问到的状态，在状态稀疏时更省。

## 基本思想：分解，再把答案存进表

动态规划与其说是一个算法，不如说是一套方法论，它的一般形式是求最优值，最长公共子序列、最大子段和、最优二叉搜索树都属这一类。名字反倒最容易误导，叫状态转移方程法更贴切。

做法的起点与分治法一样：把问题分解成若干子问题，先解子问题，再从子问题的解得到原问题的解。差别在于适合动态规划的问题分解出的子问题往往不是相互独立的；照分治那样递归下去，子问题实例多到让总代价变成指数级，而不同子问题的个数通常只有多项式量级。于是用一张表记录所有已解决的子问题，不管它以后会不会再被用到，算过就填进去，需要时查出来，指数级就降回多项式级。

## 备忘录与动态规划表

重不重叠，看递归树最直观。按 `F(n) = F(n-1) + F(n-2)` 直接递归，fib(3) 会被调用两次，fib(2) 同理。二分查找正相反，它分解出的子问题相互独立、没有重叠，所以归分治管而不适合动态规划。斐波那契严格说并不是动态规划的普适用场，却最适合用来理解重叠子问题性质。

备忘录方法为每个子问题建一条记录项。初始时存入一个特殊值（常取 -1）表示尚未解决；求解时先查这条记录，还是特殊值就是第一次遇到，算完写回去备用，已经不是特殊值就直接取用。它的控制结构与裸递归相同，只多了查表这一步，方向自顶向下。

动态规划表则是自底向上建表，保存每个子问题的解并返回最后一个。算 fib(5) 就是由 fib(0) 与 fib(1) 得 fib(2)，再由 fib(1) 与 fib(2) 得 fib(3)，一路推到 fib(5)。

## 四步法：先断定这是不是 DP 题

解决动态规划问题固定四步：辨别它是不是动态规划问题；确定状态；建立状态之间的关系；为状态添加备忘录或者动态规划表。第一步看题面形状：求最优解的问题都可以考虑，出现「最」字就留意；对排列计数的计数问题、某些概率问题也在范围内。所有的动态规划问题都满足重叠子问题性质，大多数经典问题还满足最优子结构性质，认出这两条就能确定它可用动态规划解。

## 第二步：确定状态

状态可以视为一组能唯一标识某个子问题解的参数，要尽可能小。斐波那契里 0 到 n 这些下标就是参数，由它们定出的 DP[0] 到 DP[n] 就是状态，转移方程写作 `DP(n) = DP(n-1) + DP(n-2)`。背包问题要用两个参数才能唯一确定一个子问题：物品编号 index 和容量 weight，DP[index][weight] 表示从 0 到 index 的物品装进容量 weight 的背包能达到的最优值。状态转移方程的长相取决于状态怎么定义，选状态必须谨慎。

## 第三步：构造状态转移方程

这一步最难，靠直觉和观察力，两者都要靠大量练习。练手用一个计数问题：只准用 1、3、5 三个数，允许重复、允许不同顺序，问构造出给定的数 n 有多少种方式。n = 6 共 8 种：1+1+1+1+1+1、1+1+1+3、1+1+3+1、1+3+1+1、3+1+1+1、3+3、1+5、5+1。

参数 n 可以唯一标识任意一个子问题，状态就取 DP[n]，含义是用这三个数形成 n 的序列总数。先列小值：DP[1] 到 DP[6] 依次是 1、1、2、3、5、8。求 DP[7] 按末尾那一块分类：给 DP[6] 的每个序列加 1，给 DP[4] 的加 3，给 DP[2] 的加 5，三类不重不漏，于是 `DP[7] = DP[6] + DP[4] + DP[2]`，推广成 `DP[n] = DP[n-1] + DP[n-3] + DP[n-5]`。

## 第四步：加备忘录或者填表

这一步最机械：把子状态的解存下来，下次用到时直接查表从内存里拿。

整数拆分是这一套流程的收尾例子：把正整数 n 拆成至少两份之和、求拆出的数最大乘积。暴力要回溯遍历所有拆分可能，它能交给子问题靠的是通过子问题的最优解获得原问题的最优解；递归里对第一段拆出的 i 取不再拆、继续拆、历史最好值三者之大，同一个式子搬进自底向上的表就是动态规划版本。

## 01 背包的问题描述

题面给的是：n 件**不可分割**的物品、容量为 c 的背包，物品 i 重 w[i]、价值 v[i]，问怎么选才能使装入的总价值最大而不超容量。装进记 1、不装记 0，不能把同一件装多次，也不能只装一部分。形式化写出来：给定 c > 0、wi > 0、vi > 0，要求一个 n 元 0-1 向量，使 Σ wi·xi 不超过 c 且 Σ vi·xi 最大。

示例把价值暂时去掉：容量 c = 9、n = 5、重量 wt = {2, 2, 4, 6, 5}，只问装进去的总重量最多多少。这一简化让骨架先露出来，状态和转移一点没变。

## 暴力递归与它的备忘录

暴力递归就是枚举物品集合的所有子集，算出每个子集的总重量，取与容量 c 最接近的那个。每件物品无非在最优子集中或者不在：走到第 i 件时手上是已装总重量 w，不装就推进下一件；装则先看 w + wt[i] 有没有超过 c，没超过才带着新重量推进。出口是物品走完或重量正好等于 c，出口处用当前 w 更新历史最大值。每件两个分支，n 件共 2^n 个子集，代价随物品数指数上涨。

重复计算在这棵树上看得到，所以备忘录需要两个维度：行是物品编号、列是当前总重量，格子记这个状态走没走过。进函数先查这一格，已记过就直接返回，没记过就置成已记录，再往两个分支展开。

## 自底向上的可达表

把递归翻成填表，状态就从「当前重量」变成「哪些重量凑得出来」。dp[i][j] 记只考虑前 i 件时总重量 j 是否可达，第一行由第 0 件定下：dp[0][0] 与 dp[0][wt[0]] 置 1。往后每行分两趟扫：第一趟把上一行为 1 的格子原样抄下来，即不装第 i 件；第二趟 j 只走到 c - wt[i]，上一行可达就把 dp[i][j + wt[i]] 置 1，即装上第 i 件。填完从 c 往下扫，第一个为 1 的 j 就是答案。当前行只靠上一行递推，所以这张二维表可以压成一维。

## 01背包

n 件物品，第 i 件重量 `w`、价值 `v`，背包容量 `W`，每件**要么整件拿、要么不拿**，求能装下的最大价值。

状态定义要带两个量：前若干件物品、以及剩余（或已用）容量。记 `dp[i][j]` 为「只考虑前 i 件、容量上限为 j 时的最大价值」，那么对第 i 件只有两种选择——不装，值等于 `dp[i-1][j]`；装得下且装了更好，值等于 `dp[i-1][j-w] + v`。状态转移方程就是这两项取大，一行写完：

```
dp[i][j] = max(dp[i-1][j], dp[i-1][j - w] + v)      （j >= w 时后者才存在）
```

初值一行全 0（容量 0 时价值 0，一件都装不下）。答案是右下角那个格。**「恰好装满」的变体要改初值**：只有 `dp[0][0]` 是 0，其余全设成不可能达到的负无穷，含义是「没装满的状态不算」。这一改是这类题最常见的失分点。

时间空间都是「物品数乘容量」。这个量级看着像多项式，其实取决于容量的**数值**而不是它的位数，所以被称为伪多项式——容量翻十倍，代价就翻十倍。

## 一维数组：为什么必须倒着循环

`dp[i][*]` 只依赖 `dp[i-1][*]`，两行之间是「上一层推下一层」，于是可以把表压成一行，用滚动数组把空间从「物品数乘容量」降到只有容量那一维。

关键在于遍历方向。推第 i 件时要用到「还没被第 i 件更新过」的旧值，所以容量必须**从大到小**扫：先更新大的 j，那个 `j - w` 的小位置就还是上一轮的值，每件物品只被计入一次。如果从小到大扫，`j - w` 早已被这一件更新过，再拿它去推 `j`，等于**同一件物品被装了第二次**——那正好是完全背包的转移方程。

所以一个循环方向就分出两种背包：01背包逆序，完全背包（每件不限数量）正序。

## 带价值的方程与那条边界

把价值加回来就是常规思路。最优解受两个约束：从 n 件里选，容量必须满足 C。记 F(i, c) 为 i 件物品放进容量 c 的背包得到的最大价值，第 i 件两种策略：不放，价值 F(i-1, c)；放，价值 v(i) + F(i-1, c - w(i))，取大。

物品下标也可以反着编：m(i, j) 是容量为 j、可选物品为 i 到 n 时的最优值。j 不小于 wi 时它取 max{m(i+1, j), m(i+1, j - wi) + vi}；而当 `0 ≤ j < wi` 时，剩余容量连第 i 件都装不下，第二项压根不存在，只能照抄 m(i+1, j)。

这条边界的落地写法有两种：在循环里判断 `j >= wt[i]`，或者把循环上界改成 `c - wt[i]`，让装不下的容量根本不进循环，一维写法用的就是后者。漏掉它，要么读进一个负下标，要么把放不下的物品算进答案。

## 为什么贪心不行

拿「单位重量价值最高就先拿」来试：容量 10，三件物品分别是「重 6 值 9」「重 5 值 6」「重 5 值 5」。贪心先拿比值 1.5 的那件，剩下容量 4 谁也塞不进去，总值 9；而放弃它去拿后两件，恰好装满，总值 11。**贪心的局部最优推不出全局最优**，因为背包这个约束是「整体装得下」，一件物品的取舍会影响后面所有位置——这正是必须保留整个容量维度、而不能只记一个「当前最好」的理由，也是判断「这题能不能贪心」的实操标准。

能贪心的题都有个共同形状：选完之后剩下的部分还是同一个问题，且更早的决定不会让后面的可选集合变小。

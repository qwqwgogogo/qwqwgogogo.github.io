## 一句话

Cache 存在的理由只有一个：**CPU 和主存的速度差**，而程序恰好有局部性——刚用过的和挨着用过的，大概率还会再用。所以把块搬进快的那层，赌它还会被碰到。

## 地址怎么切

三种映射方式的区别，就是主存地址被切成几段、中间那段拿来干什么：

| 方式 | 地址切分 | 定位过程 | 代价 |
| --- | --- | --- | --- |
| 直接映射 | 标记 \| **行号** \| 块内偏移 | 行号直接选中一行，比标记 | 冲突极高，两块抢一行就互相踢 |
| 组相联 | 标记 \| **组号** \| 块内偏移 | 组号选中一组，组内所有路**并行**比标记 | 折中，实际都用这个 |
| 全相联 | 标记 \| 块内偏移 | 和**所有行**并行比标记 | 电路最贵，只放得起很小的表（TLB） |

算例：主存 `64MB`、Cache `32KB`、块 `64B`、2 路组相联。
块内偏移 `log2(64) = 6` 位；Cache 共 `32KB/64B = 512` 行，分 `512/2 = 256` 组 → 组号 8 位；主存地址 26 位，标记 `26 - 8 - 6 = 12` 位。

**行数怎么算永远是从容量除到块大小**，别把「块」和「行」当成两个东西——同一个东西在主存里叫块、在 Cache 里叫行。

## 冲突缺失和抖动

直接映射下，两个热点地址只要映射到同一行就会反复互相逐出，这叫**冲突缺失**——明明 Cache 是空的却命中不了。提高相联度就是在买「放的位置多几个」，代价是比较器变多。

## 替换算法

组满了要踢谁：

| 算法 | 依据 | 备注 |
| --- | --- | --- |
| 随机 | — | 实现最简单，效果意外不差 |
| FIFO | 谁最先进来 | 有 Belady 异常 |
| LRU | 最久没被访问 | 408 默认答案，但计数器/栈开销大 |
| LFU | 访问次数最少 | 对「一次性刷爆」的老数据不友好 |

LRU 有个坑：顺序扫描一大块数据时，刚装进来的下一轮就被当成最久未用踢掉，命中率反而差。

## 写策略：写穿还是写回

| | 写直达 write-through | 写回 write-back |
| --- | --- | --- |
| 写命中 | 同时写 Cache 和主存 | 只写 Cache，置**脏位** |
| 写缺失 | 常配 no-write-allocate：直接写主存，不把块拉进来 | 常配 write-allocate：先把块拉进 Cache 再改 |
| 优点 | 主存永远是最新的，简单 | 省掉大量对主存的写 |
| 代价 | 每次写都慢，所以几乎一定要配**写缓冲** | 被替换时可能要多写回一次；DMA 直接读写物理内存时得先刷脏行 |

写直达几乎一定要配**写缓冲**，否则 CPU 每次写都要等主存。

## 缺失分三种

- **强制缺失**（冷启动/幂次缺失）：第一次碰这块，硬件再大也躲不掉；
- **容量缺失**：工作集比 Cache 大，装不下；
- **冲突缺失**：装得下但映射撞车。

对应的药不一样：加大容量治容量缺失，提高相联度治冲突缺失。预取治的不是缺失率而是**缺失惩罚**——它赌下一块马上要用，提前搬进来，把等待和计算重叠掉。

## AMAT

```
AMAT = 命中时间 + 缺失率 × 缺失惩罚
```

多级的时候从内往外算，L1 的缺失率会传染给 L2。这个式子解释了一个反直觉的现象：**块不是越大越好**。块变大，命中率一开始上升（顺序访问时一次拉进更多将来要用的数据，缺失惩罚被摊薄）；但块太大之后，一是拉一整块的时间线性变长，二是同一条 Cache 行变少、空间局部性反而抓不住，缺失率重新上升。所以有个最优块大小。

提高 Cache 性能的手段就沿着这三项展开：压**命中时间**用更小更快的 L1、地址译码和标签比较并行做；压**缺失惩罚**用多级 Cache、非阻塞 Cache（一次能挂多个缺失，MSHR 记录在途的缺失）；压**缺失率**用更大的块、更高的相联度。另外把指令 Cache 和数据 Cache 分开（哈佛结构）也常见，因为取指和数据访问基本不抢同一块热数据。

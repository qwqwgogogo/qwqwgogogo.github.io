## 一句话

流水线不是让一条指令变快，而是让**单位时间完成的指令变多**：一条指令的延迟没变，吞吐率上去了。

## 五段各自做什么

课件把指令处理固定切成五步。取指按程序计数器的地址从指令存储器取出一条指令并让地址往后走；译码解析操作类型与寄存器编号，并在同一拍从寄存器堆把源操作数读出来；执行做真正的运算——运算指令算结果，分支指令做减法比较，存取指令只算地址；访存只有需要读写数据的指令会用；写回把执行结果或读出的数据送进目的寄存器。

段与段之间必须有东西把值接住，这些边界寄存器就是流水寄存器，它们按同一时钟推进，每一拍把上一段的结果交给下一段。流水线切分的对象是指令内部的处理步骤，切的仍然是同一条指令的顺序，只是不同指令在不同步骤上同时在场。

## 八条指令落在哪几段

用核心子集核对一遍归属：取指段八条指令人人都要；译码段里存取指令认基址寄存器和目标寄存器，运算指令认两个源和一个目的，分支指令认两个比较对象加一个偏移；执行段只有分支指令要判方向、存取指令要算地址、运算指令要算结果；访存段只属于取数与存数两条；写回段属于取数和所有寄存器型指令，存数没有寄存器写回，分支的写回只是可选地更新程序计数器。

归属看清之后，性能账和冒险账都能直接从表里读出来：某段最忙的是哪类指令、哪两条指令会在同一拍撞到一起，全在这张分配关系里。

## 用具体延迟把账算清

给定存储器访问 200ps、运算 200ps、寄存器读写各 100ps，先忽略多选器与控制单元的延迟。取数指令串完五段是 800ps，存数是 700ps，寄存器型指令不访问数据存储器是 600ps，分支指令既不访存也不写回只有 500ps。单周期实现的时钟周期必须等于最慢那条，也就是 800ps，所有指令一律占满一整拍；流水线各段最慢是 200ps，于是周期可以压到 200ps。

四条指令跑下来，流水线要 1400ps，而不是公式最容易套出的那个数，因为前四条指令要爬完五段才有第一条完成，填充与排空的固定开销摊不薄，收益只有约 1.7 倍。把指令数换成一百万条量级，流水线时间约等于条数乘以 200ps 再加 1400ps 的开销，非流水线约等于条数乘以 800ps，比值就接近 4。同一套硬件，指令数差六个数量级，加速比从 1.7 走到 4，这说明加速比从来不是硬件的固有属性，而是硬件与程序规模共同决定的结果。

## 指令集要为流水线让路

MIPS 对流水线友好的特征不是巧合：定长指令字让取指与译码不必判断边界；寄存器编号字段位置对称，译码段一开头就能读寄存器；只有取数与存数两条指令允许访问存储器，运算与访存因此能干净分段；数据对齐保证一次访问取回整个字；每条指令最多写一个结果，并且写动作放在最后一级。最后一条是转发网络逼出来的约定，写口越少、写点越靠后，需要跟踪的相关就越少。

## 三段账

`k` 段流水线跑 `n` 条指令，总时间是 `(k + n - 1) × Δt`，其中 `Δt` 是最慢那一段的时间。

```
吞吐率  TP = n / ((k + n - 1) × Δt)   → n 很大时趋近 1/Δt
加速比  S  = 不用流水线的时间 / 用流水线的时间
           = (n × k × Δt) / ((k + n - 1) × Δt)  → n 很大时趋近 k
效率    E  = S / k
```

三个结论直接背：段数越多理想加速比越高，但**不可能超过段数 k**；`n` 越小启动开销 `k-1` 越难摊薄，所以短循环喂不饱流水线；`Δt` 由最慢的一段定死，给 ALU 加一级、让它比访存段还快，等于白加。

## 三类冒险，三种药

冒险就是流水线装不下冲突、只能停下来或改顺序的情况。按原因分：

| 冒险 | 冲突点 | 解法 |
| --- | --- | --- |
| 结构冒险 | 两条指令同拍抢同一个部件（例如同一套存储器既要取指又要读写数） | 指令和数据 Cache 分开、加硬件、或插气泡 |
| 数据冒险 | 后面的指令要用前面还没算完的结果 | 转发（旁路）、插气泡、编译器重排指令 |
| 控制冒险 | 分支跳不跳还不知道，后面取进来的指令可能是废的 | 分支预测、冻结、延迟槽 |

结构冒险就是硬件资源不够分：两条指令同一拍都要用同一套存储器，要么把它拆成指令和数据两路，要么让后面那条等。

停顿是流水线主动插入一个空拍来错开冲突，插进去的那个空拍常叫气泡。它是所有解法里最贵的一种，因为那一拍什么都没干，转发和指令调度存在的意义就是少插几次停顿。

数据冒险里最典型的是「后写先读」这条链：加法的结果要喂给下一条指令。转发就是**不等结果写回寄存器堆**，直接从流水线中段把值抄给下一条需要的部件，把它挡在写回阶段的依赖拉平。但有一类转发救不了——取数指令的结果要到访存段末尾才出来，紧接下一条就要用它，只能停一拍。编译器把无关指令插到这两条之间，就叫指令调度。

控制冒险的代价取决于分支频率。延迟槽的思路很实在：分支后面那一条指令**无论如何都会执行**（要么跳之前执行它，要么本来就该执行），编译器把有用指令塞进这个位置，预测错了也不亏这一条。

## 段数不是越多越好

分得越细，`Δt` 越短，理想吞吐越高；但每一段都要一套寄存器锁存，启动开销也变大，段间寄存器的延迟开始不可忽略，冒险也更难缠——一条依赖链被拉得越长，要停的拍数越多。超流水线（段数超过时钟能撑的）拿到的其实就是这个方向的收益，代价是分支惩罚被放大成好几拍。

超标量是每个周期发射多条指令，本质是把流水线复制几份，靠**程序里本来就存在的并行**吃饭；后面加多少发射宽度，都受 Amdahl 定律那种串行比例的限制。

级数加深还有一层不太被注意的代价：冒险检测变长。要比较的流水寄存器对数随级数增加，检测逻辑本身也得挤进更短的周期里，于是周期缩短与检测复杂度互相拉扯。真正的瓶颈往往不是运算部件不够快，而是「同一拍里必须做出的判断」越来越多。

## 三类解法的排序标准

判断一种冒险处理值不值得上，只看两点：它有没有可能猜错，猜错之后要花几拍收拾。冻结不猜，所以永远正确，代价固定；静态预测几乎不花硬件，猜错的代价随跳转比例上升；动态预测准确率高，但预测器、历史表和刷新逻辑都要面积与时间；转发属于「不猜」那一类，它只是把已经算出来的结果提前交出去，所以只要路径存在就稳赚。把这些方案叠起来用的时候，优先级也是按这个标准排的：先做无风险的资源拆分与转发，再谈预测与调度。

也正因为这套排序，课件把处理冒险的顺序写成先结构、再数据、最后控制：资源冲突用硬件补齐一次性解决，数据相关用转发加检测覆盖大多数，控制相关因为要预取指令，本质上必须猜，于是成了最难收尾的一类。

## 冒险检测要落成比较式

数据冒险的处理不能停在「有一条链」这种描述上，硬件能做的只有一件事：逐拍比较流水线寄存器里保存的编号。判定条件写成四条，即访存段流水寄存器的目的编号等于执行段流水寄存器的第一个源编号、等于第二个源编号，写回段流水寄存器的目的编号再分别比一次。四条之外还要加两道过滤：先行指令那一级的写寄存器标志必须有效，否则它根本不产生结果；目的编号不能是恒零寄存器，因为往它写东西会被丢弃，转发过去毫无意义。

检测出冲突之后只有两种动作可选。能把结果从早段取回来的，走转发，不浪费任何一拍；取不回来的，比如取数指令后面紧跟一条要用这个数据的指令，就只能让取指与译码停住，在执行段及其之后插入空操作。前者是连线问题，后者是时间问题，两者的分界就在于数据到底在哪一段末尾才出现。

## 收益与代价要一起报

只讲加速比的笔记是不完整的。五段流水线把周期从 800ps 压到 200ps，理论上四倍收益，实际要扣掉三类开销：结构冲突带来的等待、数据相关带来的停顿、分支误判带来的刷新。指令序列里分支密度高、依赖链紧，实测吞吐率就会明显低于公式值。因此描述一台流水线机器时，时钟频率、级数、每条指令平均周期数这三个量要同时给出，缺一个都可能被平均数骗过去。

这也是后面所有进阶技术的入口：把冒险处理做扎实，是为了让流水线接近理想值；加深级数与多发射，是为了让理想值本身更高；两条路都撞到同一堵墙——依赖与并行性的挖掘总有尽头，再往上就得改程序本身的执行顺序。

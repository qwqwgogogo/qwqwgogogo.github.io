## 归并排序

### 算法思想：分下去，治回来

归并排序的骨架是分治：先把大问题切成两个同形的子问题，解掉子问题再把结果拼接；切到只剩一个元素就不必再切，单个元素天然有序。

设当前区间为 `[l, r]`，取中点 `m = (l + r) / 2` 向下取整，把它切成 `[l, m]` 和 `[m + 1, r]` 两半。以 5、1、4、2、8、4 为例，`[0,5]` 在中点 2 处切成 `[0,2]` 与 `[3,5]`，`[0,2]` 切成 `[0,1]` 与 `[2]`，`[0,1]` 切成 `[0]` 与 `[1]`；这三步是同一操作在更小区间上重复，这种结构就是递归。

合并这一步叫二路归并：两头各放一个游标，较小者写入辅助数组并让该侧游标前移，一侧走空后把另一侧整段抄过去；序列里的 5 和 1 正是在这一步交换了先后。向下切分、向上返回时合并，n 段长度为 1 的序列最终长成一段长度为 n 的有序序列。

### 复杂度分析

总代价是拆分、子数组排序、合并三项之和；拆分只做一次加、除、取整，是 O(1)。按层看：每层各区间长度之和都是 n，合并时每个元素恰好被搬运一次，所以每层与 n 成正比；区间长度每往下一层减半，层数是对数级；两者相乘，最好、最坏、平均都是 n log n，没有输入能让它退化。

合并要临时区域存放待合并元素，其长度依次是 1、2、4、8 直到 n/2，而同一时刻要维护临时区和原数组两份，实际开辟到 2、4、8 直到 n，所以辅助空间总量与 n 同量级即 O(n)。和插入、冒泡、选择相比，归并排序是以空间换时间的典型，也不属于就地排序——就地排序的辅助空间是 O(1)。

### 稳定性分析

归并排序是稳定的，上例中两个 4 排完后仍保持原来的先后次序。根本原因是合并时对值相同的两个关键字不存在交换的可能：相等时规定取左半区那一个，它们就按原序列的左右顺序依次写出。把这条规则改成相等时取右边，同样的框架就会变得不稳定——稳定性正是这一步规则的直接后果。

## 计数排序

### 算法思想

计数排序是针对特定取值范围之间的整数进行排序的算法，它不比较两个元素谁大谁小，而是先统计给定数组中不同元素的数量，再对映射后的数组顺序输出，思路上接近一次哈希映射；取值范围不大时某些情况下比快速排序还快。

以 1、4、1、2、5、2、4、1、8 为例：最大值 8，就开一个长度 9（最大值加 1）、初值全 0 的计数数组，依次访问每个元素，读到 1 就把下标 1 那格加一。九个元素读完，计数数组记下 1 出现 3 次、2 出现 2 次、4 出现 2 次、5 出现 1 次、8 出现 1 次，其余为 0——排序在信息意义上已经完成，剩下的只是输出。最直接的输出是按每格次数把该值重复写出，得 1、1、1、2、2、4、4、5、8，但这样不知道相同数字对应原数组里哪一个元素。

把元素值直接当计数数组的下标，而数组下标没有负数，数据一旦变成 -1、4、1、-2、5、-2、4、-1、8 就越界。办法是把最小元素映射到下标 0、其余依次映射：找出 min 和 max，开一个长度 `max - min + 1` 的计数数组，把元素 v 记到 `v - min` 那格，输出时再反向平移；此例长度 11，-2 落在 0 号格记 2，-1 落在 1 号格记 3。

### 稳定性

要保证计数排序稳定，得先回答：原数组第 i 个元素排好序后落在哪个下标。计数数组中的 0 对输出没有影响，先去掉，摊开剩下部分只得到排序后数组的轮廓。

接着做一次累加，从下标 1 起令每格加上前一格的值即求前缀和，各格依次变成 0、3、5、5、7、8、8、8、9。此后每格含义从「出现几次」变成位置信息：下标 1 是 3，说明所有 1 出现在前 3 个位置；紧接的 5 表示 2 在第 4、5 位；下标 4 是 7，说明 4 在第 6、7 位；与前一格相等的下标 3，差值正好是次数 0，不占位置。

有了位置表就反过来扫描原数组：从 `i = n - 1` 起读出元素值 v，它在输出数组的正确位置就是累加数组中 v 那格的值减一，写入后把该格减一，表示值为 v 的最高一格已被占掉。必须从后向前遍历才能保证稳定性：靠后的相等元素先拿到靠后的格子，3 个 1 的相对位置原样保留。

### 复杂度分析与优缺点

实现里只有一层循环、没有嵌套：一遍找最值、一遍统计次数、一遍求前缀和、一遍倒序放置，所以时间复杂度是 O(n) 量级；空间是一个 `max - min + 1` 的计数数组加一份等长输出数组，用量由取值范围决定。

它不是基于比较的排序，因此不受 O(n log n) 下限约束，空间复杂度与数据范围成正比，适用于负输入但不适用于小数。当范围 `range = max - min + 1` 不明显大于 n 时相当高效，比快速排序和归并排序都优秀；范围一旦远超 n，统计数组大面积空置，时空都白耗。它还常被用作另一个排序算法（例如基数排序）的子过程。

## 桶排序

### 桶排序的思想

桶排序是所有排序中最简单的一种，它和计数排序、基数排序有很多相似和渊源之处。它更重要的是思想而非具体实现，拆开看有三层：若干个桶说明数据被放入桶中；每个桶有容量，所以桶中可能有多个元素；一次好的分配希望桶装得匀称，既不溢出也不太满。

正式一点说，桶排序先把数组分到有限数量的桶里，再对每个桶单独排序——桶内可换成别的排序算法，也可递归地再用一次桶排序——最后按编号从小到大把各桶内容依次接出来。它是鸽巢排序的一种归纳结果，因为不是比较排序，所以不受 O(n log n) 下限影响，数值均匀分配时用到线性时间，同样以空间换时间。

分配规则通常取整除。以 12 个元素为例，规定桶号为元素除以 10，则 0 号桶装 8、5、9，1 号桶装 15、19、12，2 号桶装 22、28、27，3 号桶装 39，4 号桶装 45、42。刚放入时右侧的桶都比左侧大，但桶内还是无序的——桶排序是借桶的位置先完成一次初步排序，剩下的只是各桶内排序，再按桶序、桶内序接出最终结果。

### 关于桶排序的算法分析

总代价由两部分组成：一遍 O(n) 的遍历处理每个元素，加上各桶内再次排序的时间总和。设 n 个待排序数字分到 m 个桶，分配均匀时平均每桶有 n/m 个元素；若桶内使用快速排序，单桶代价为 `(n/m) log(n/m)`，m 个桶合起来就是 `n (log n - log m)`。

桶数 m 越大第二项越小；极限情况 n 等于 m 时就能避免桶内排序，达到 O(n)，而这种一格一值的情形正是计数排序，所以计数排序可看成桶排序的特例；反过来桶数很少时单桶元素多，桶内排序的开销又回来了。

### 桶排序适用情况

桶排序的限制相当明显：桶的个数和大小都是人为设置的，每个桶又要避免空桶，所以既要求待排序列偏均匀，又要求桶的设计兼顾效率和空间。数据分布比较均匀、或跨度范围不很大时，排序速度相当快且简单。

数据跨度过大时空间消耗就很大；同样由于时间复杂度为 O(n + m)，m 比 n 大太多时性能也并不好，实际实现会用类似散列表的方式去挂桶，空间利用率高很多。开发中除了性能要求特别高且数据分布均匀的情况，桶排序用得很少，更多用于数据范围局限、需要哈希映射快速取值、需要统计每个数的数量这类特定环境；这些都要先确认数据范围，范围太大就得巧妙转化或改用其他算法。

## 基数排序

### 算法思想

与基于比较的排序算法相比，比较排序的时间复杂度最好也就是 O(n log n)，而且不能比它更小。计数排序更准确说是 O(n + k)，其中 k 表示待排序元素的取值范围，即最大与最小元素之差加 1。当元素的范围在 1 到 n 的平方时，计数排序达到 O(n²) 量级，就用不了了。

比如数组 170、45、75、90、802、24、2、66 共 8 个元素，最大与最小值之差为 802 减 2 等于 800，绝大多数计数格子空着，计数排序失灵。基数排序的总体思想是从元素的最低有效位到最高有效位逐位比较排序，并使用计数排序作为排序的子过程。

最大值 802 为三位数，先在不足三位的数字前面补 0。第一步按个位做计数排序，个位相同的数被排到相邻位置；第二步在这个结果上按十位排，得到 802、002、024、045、066、170、075、090；第三步按百位排，得到 002、024、045、066、075、090、170、802。

为什么一定要从低位往高位、且每趟都必须稳定？因为高位排序只能在不破坏低位已建立次序的前提下进行。以第二趟为例，802 和 002 的十位都是 0，先后由个位决定，只有这一趟用稳定排序，个位建立的关系才能带进下一趟；某一趟换成不稳定的做法，最后一趟结束时整体并不有序。

### 复杂度分析

设 d 表示最大值的位数，比如 802 是 3 位、d 为 3；n 是数组长度，b 是基数，十进制下 b 为 10。每趟按位排序的代价是 O(n + b)，共 d 趟，所以时间复杂度是 O(d × (n + b))。设 K 是计算机可表示的最大整数，d 等于以 b 为底 K 的对数，整个式子可写成 O((n + b) × log 以 b 为底 K)。

对一个较大的数 K，这个式子看着比基于比较的排序算法都慢，但事实未必。假设 K 不超过 n 的 c 次方、c 是常量，b 和 c 都是常数可以忽略，于是变成 O(n × log 以 b 为底 n)，可这依旧不比比较排序的最好时间复杂度更好。关键在底数 b 可以自己取：把 b 取到 n，log 以 n 为底 n 等于 1，时间复杂度就变成了 O(n)，线性。也就是说，当数字用 n 进制表示的时候，就可以对 1 到 n 的 c 次方范围内的数组进行线性排序。

对元素跨度比较大的数组，基数排序的运行时间可能比快速排序好，但它的渐近复杂度隐含更高的常数因子，并非完全线性，而快速排序更有效地利用硬件缓存。此外它使用计数排序作为子过程，计数排序要占用额外空间，所以空间复杂度为 O(n)。

## 延伸：外部排序与多路合并

归并这套把两段有序合成一段更长有序的做法，也是外部排序的基本操作。记录多到装不进内存时，先分批读入做内部排序，在外存上生成一批初始有序段，再把它们两两或多路合并。合并趟数直接决定读写外存的次数，所以优化方向是加大每次合并的路数、减少趟数。多路合并让一趟能同时消化更多有序段，趟数随路数按对数减少；为了让每趟挑选各段段头的工作不致变成新的瓶颈，可以用败者树这类结构来代替逐对比较。

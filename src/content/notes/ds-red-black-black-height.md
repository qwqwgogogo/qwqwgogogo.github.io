## 先把五条着色规则摆正

红黑树首先仍是一棵二叉搜索树，左小右大的那条基本规矩一点没改，查找、插入、删除的骨架照旧是二叉搜索树那一套；变化只在于每个结点额外涂了一种颜色，并让整棵树受五条着色规则约束：每个结点非红即黑；根结点是黑的；每个代表空的叶子结点一律算作黑色；红结点的两个孩子都必须黑，也就是树里绝不允许出现相邻的两个红结点；从任意一个结点到它所有后代空叶子的每条路径上，黑结点的个数完全相同。理解红黑树的全部关键，就在把这五条从「一堆规矩」读成「一种用颜色换来的高度约束」。

前三条是静态的形状约定，真正撑起全部威力的是第四条和第五条。第四条「红结点的孩子必黑」堵死了连续红，第五条「黑结点数量处处相同」把每条路径上的黑结点钉成一样的数目，这两条合起来限制了树能歪到什么程度。可以拿平衡二叉树来对照理解：AVL 用每个结点的平衡因子（左右子树高度差）来量平衡，红黑树则用颜色这条更松、更好维护的约束去量，黑高就是它替代高度差的度量衡。

## 为什么要有红黑树

大多数二叉搜索树的操作——查找、求最大最小、插入、删除——代价都是 `O(h)`，h 是当前这棵树的高度。运气好时树高是对数级，操作也就快；可一旦输入序列近乎有序，比如按 1、2、3、4、5 一个个插进去，二叉搜索树会退化成一条右斜的链，树高一路涨到和结点总数一样多，所有操作集体退回线性的 `O(n)`，二叉搜索树那点查找优势荡然无存。想让这些操作的最坏上限稳稳停在 `O(log n)`，唯一的办法是把树高长期压在 log n 附近。红黑树就是靠一套颜色约束做到的——它并不要求每一层都填满，但通过着色规则保证整棵树不会歪成一根棍，从根到叶子再长也不会超过最短路的两倍。

有人会问：平衡二叉树 AVL树 也把高度维持在均值附近，为何还要红黑树？区别在于调整树形时所付出的旋转代价，这一点放到下面和 AVL 比较里细说。

## 它靠什么不歪：三结点的小例子

判断红黑树「如何保持平衡」，用三个结点就能看清楚。设想三个关键字要挂成一棵树，其中一条完全退化的形状就是三个结点串成一列的斜链。给这条斜链着色：把根按规则涂成黑色，剩下两个结点无论怎么分配红和黑，都会踩到某条规则的雷——要么出现两个上下相邻的红结点违反第四条，要么两条通往空叶子的路径上黑结点数目不相等违反第五条。所有可能的配色方案没有一种合法。这说明红黑树的着色规则天生就拒绝「三个结点硬拉成一条链」，遇到这种形状唯一的出路是先把高低错开再配合染色。换句话说，只要一棵二叉搜索树被拉成斜链，无论怎么给它上色都不可能同时满足全部五条，于是能被合法着色的树形自然就被筛成了那些够矮、够平衡的形态。正是这种「树一旦想歪就必然违反规则」的隐式约束，把整棵树的形态逼回到近似平衡，而不是靠某个显式的高度检查去强制。

## 黑高的定义与一个算例

黑高是这一节的核心概念，后面所有关于树高的估计都从它出发。它的约定要读仔细：从某个结点 x 出发、且不把 x 自己算进去，一路走到它任意一片后代空叶子，这条简单路径上黑色结点的数目，就叫做 x 的黑高，记作 `bh(x)`。之所以强调「不含 x 自己」，是因为判断平衡关心的是 x 往下各条支路的一致性，起点算不算只影响一个常数，约定成不含更便于对同一层的兄弟结点比较。整棵红黑树的黑高定义为根结点的黑高，因为按第五条，根往下的黑高对全树是一致的，拿它代表整棵树即可。

算一个具体的例子：一棵根是黑结点 6 的树，6 的右孩子是红结点 15。要算 `bh(6)`，沿路径 6→15→10→9→空叶子 往下走，途中碰到的黑结点本有若干，但规定不能把起点 x 自身计入，所以从 6 往下真正算进黑高的只有 10 和那片空叶子两个，得 `bh(6)=2`；再算红结点 15 的黑高，从 15→10→9→空叶子 这条路上黑结点是 10 和空叶子两个，`bh(15)=2`。两者相等，恰好是第五条最直接的体现：在同一片子树里，无论从哪个结点开始往下数，到后代空叶子的黑高都一模一样。

## 从黑高推到高度上界

有了黑高就能量出红黑树到底有多平衡，推导只用两步。第一步，因为红结点不能相邻，任意一条从根往下走的路上红和黑是交错出现的，红顶多和黑一样多、绝不可能比黑还密；第二步，因为第五条保证每条路径的黑结点数目相同，最短的那条路径索性全是黑结点、长度正好等于黑高 `bh`，最长的路径则是黑红交替、长度至多是 `2bh`。把两步合起来就得出：从根到最远叶子的结点数，不会超过到最近叶子结点数的两倍，写成不等式就是 `bh ≥ h/2`，这里 h 是整棵树的高度。这句话正是红黑树「最长路径不超过最短路径两倍」那句直观结论的严格来历，也是它只做到近似平衡而非严格平衡的分界线。

再套一层二叉搜索树的规模估计：一棵黑高为 bh 的红黑树，把里面所有红结点都去掉、让黑结点直接接上，会得到一棵高度为 bh 的普通黑树，它至少有 `2^bh - 1` 个结点，也就是说红黑树自己的结点数 n 不会比这个更少。于是 `n ≥ 2^bh - 1`，两边取对数反解出 `bh ≤ log(n+1)`；再把前面 `h ≤ 2bh` 一代入，就得到那条被反复引用的引理——**一棵有 n 个结点的红黑树，树高 h 不超过 `2·log(n+1)`**。这条上界就是红黑树敢自称自平衡的数学依据：它承诺的是对数级的最坏树高，只是那个常数比 AVL 树要宽松一些，所以同样多结点下红黑树可能稍微高一点点，查找也稍微慢一点点，但量级不变。

值得再点一下这里用到的空叶子约定：所谓「叶子」在红黑树里指的是那些代表空的终端结点，一律当作黑色。正因为它们黑、且每条路径都以它们收尾，黑高才有了统一下界，第五、第四条才把红黑交替的节奏钉死。把空叶子想成黑色而不是「没有」，是理解黑高处处相等的关键。

## 与 AVL 的比较

| 维度 | AVL树 | 红黑树 |
| --- | --- | --- |
| 平衡约束 | 左右子树高度差 ≤ 1 | 五条着色规则，黑高处处相等 |
| 平衡强度 | 严格平衡，树更矮 | 弱平衡，树略高 |
| 同结点数树高 | AVL 不高于红黑树 | 更矮的是 AVL |
| 查找 | 更稳定、更快 | 略慢一点，仍在对数级 |
| 插入删除 | 可能大量旋转 | 重着色为主，旋转次数少 |

AVL树 比红黑树更平衡，代价是它每次插入删除都可能触发不少旋转；红黑树把约束放松成一套颜色规则，换来写操作时靠重新着色加少量旋转就能在局部修好。取舍因此很清楚：以查询为主、改动很少的场景选 AVL树，因为更矮的树查找更快；插入删除非常频繁的场景选红黑树，因为写的时候折腾得更少。两者本质上都是二叉搜索树为了不被拉成斜链而加的自平衡变体，区别只在「平衡」这个词各自采用的标准松紧不同。

## 一句话收口

把这一节串起来：五条着色规则里，第四条管「不许连着红」、第五条管「黑数处处等」；从这两条量出黑高 bh，从黑高约束出最长路径不超过最短路径两倍，也就得到树高上界 `h ≤ 2·log(n+1)`。这条上界就是红黑树作为自平衡二叉搜索树的全部承诺——它不追求 AVL树 那种严格的矮，只保证足够矮、使得最坏情况的查找、插入、删除仍然落在对数级，同时把维持平衡的代价压到重着色加偶尔旋转的程度。

## 用在哪里

工程里常见的自平衡二叉搜索库大多用红黑树实现，比如 C++ 标准库的有序关联容器 map、set，以及 Java 里对应的 TreeSet、TreeMap——它们既要按关键字有序地查找、又要频繁地增删元素，红黑树这种「写操作局部就能修好」的脾气正合适。操作系统层面，Linux 的完全公平调度器用它来组织待运行的进程、按虚拟运行时间排序取最短者，网络多路复用机制 epoll 的底层也用红黑树来管理大量注册的连接，图的就是在成片的结点里能快速增、删、查。这些被选中的场景有个共同点：读写都不算少、还要求维持一份有序。反过来，如果数据几乎只读不改，AVL树 更矮的树高更划算；如果根本不需要有序、只按关键字直达，那连自平衡都不要，直接上哈希更快。判断该不该用红黑树，本质是在「平衡强度」和「调整代价」之间取那个对当前读写比例最省的中点。

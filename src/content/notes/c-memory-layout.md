> 题目和顺序来自数据结构直播课的随堂材料，下面这份是我自己重新写的一版，不是课件原文。当时卡住的两个问题我原样留在最后。

## 一句话

内存里放的都是数字，区别只在**按什么规则去解释这段数字**。指针就是一个存地址的容器，语言规定它指向某个类型，于是访问它指向的东西时按那个类型的大小走。

## 五块地方

程序占用的虚拟地址空间，按系统习惯切成几段，每段的读写权限和放的东西都不一样。这张表就是进程的内存布局：

| 段 | 权限 | 放什么 | 谁管 |
| --- | --- | --- | --- |
| 内核段 | 不能读也不能写 | 操作系统自己 | 硬件 + OS |
| 栈 `stack` | RW | 局部变量、函数调用的现场 | 编译器自动进出 |
| 堆 `heap` | RW | `malloc` / `new` 申请的空间 | 程序员自己 `free` |
| 数据段 `.data` | RW | 已初始化的全局变量、`static` 变量 | 跟着程序加载 |
| 只读数据段 `.rodata` | RO | 字符串字面量、常量 | 跟着程序加载 |
| 代码段 `.text` | RO | 函数本身的指令 | 跟着程序加载 |

裸机上没有这套划分，整个地址空间就是程序员的，物理地址直接写；有了操作系统之后，分配权交出去，程序看到的是虚拟地址。

一个容易混的例子：`vector<int> a;` 这个对象本身在**栈**上，它内部维护的那块元素数组在**堆**上。所以拷贝一个 vector 会连带复制堆上那一整块，而 `int a[100]` 从头到尾都在栈上，出了作用域就没了。

## 指针和数组不是一回事

```c
int *p = (int *)0x100;	// 只有裸机上能这么直接写，OS 管着的地址空间里这是非法访问
```

`p[2]` 翻译成地址就是 `0x100 + 2 * sizeof(int)`，也就是 `0x108`。下标不是「第几个字节」，是「第几个对象」——偏移量由指针指向的类型决定，这就是为什么同一个 `p[2]`，`int *` 和 `char *` 算出来的地址差两倍。

`sizeof` 在这里会骗人：

```c
int arr[5];
sizeof(arr);   // 20，编译期就定下来的整块空间
int *q = arr;
sizeof(q);     // 4 或 8，量的是容器本身的大小
```

**数组名在定义它的作用域里代表整块空间，一旦作为参数传出去就退化成指针**：

```c
int fun(int arr[5]) {
	sizeof(arr);   // 4 或 8，那个 [5] 是装饰，收进来的只是地址
}
```

所以 C 里传数组进函数，长度必须另开一个参数带上——这是接口设计问题，不是语法问题。指针只是「存地址的容器」，它不知道也不关心那块地有多高。

## 结构体为什么比看起来大

```c
struct abc {
	char a1;	// 1
	short c1;	// 2
	int b1;		// 4
};
sizeof(struct abc);   // 8，不是 7
```

成员不是紧挨着摆的，每个成员的起始地址要是它自身大小的整数倍（超过编译器上限的按上限算）。于是 `a1` 占 0，1 号位填掉，`c1` 从 2 开始，`b1` 从 4 开始，一共 8。把顺序换成 `int / short / char` 是 4+2+1 再补 1 到 8，中间一处填充都不需要——声明顺序本身就是布局的一部分。

```c
struct x { int a; char b; int c; };
sizeof(struct x);   // 12：4 + 1(+3 填充) + 4
```

对齐是为了让 CPU 一次取完——拆成两次访问的代价在多数机器上是实打实的，某些架构上干脆是非法的。整个结构体的大小还要是最大成员对齐值的整数倍，所以尾部也可能有填充。这套规则统称内存对齐；想改它就用 `#pragma pack` 或 `__attribute__((packed))` 告诉编译器按几字节对齐，但那是拿性能换空间。

## 当时卡住的两个问题

**`const char *p1` 和 `char *const p2` 到底谁被锁住了。** 从右往左读就行：`p1` 是指针，指向 `const char`，所以**值不能通过这个指针改，指针自己可以换指向**；`p2` 是 `const` 的指针，指向 `char`，所以**指向定死了，指向的内容随便改**。中间再插一个 `*` 就是两个都锁。

**`static` 到底锁住了什么。** C 里写一个函数，它的符号默认对整个程序可见，于是多个 `.c` 里有同名函数就在链接期撞车。规矩是对外接口在 `.h` 里声明，只在当前文件里用的辅助函数一律加 `static`——`static` 把符号的作用域关进这一个编译单元，链接器就看不到它，也就撞不上。

## 对照着背

| 写法 | 指针能换指向 | 能改指向的值 |
| --- | --- | --- |
| `const char *p` | 能 | 不能 |
| `char *const p` | 不能 | 能 |
| `const char *const p` | 不能 | 不能 |

| | 数组 | 指针 |
| --- | --- | --- |
| `sizeof` | 整块空间 | 4 或 8 |
| 传给函数 | 退化成指针 | 就是指针 |
| 谁分配 | 编译器在栈上划 | 自己 `malloc` 或指向别处 |

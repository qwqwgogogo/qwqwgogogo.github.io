## 一句话

内存里放的都是数字，区别只在**按什么规则去解释这段数字**。指针就是一个存地址的容器，语言规定它指向某个类型，于是访问它指向的东西时按那个类型的大小走。

## 五块地方

程序占用的虚拟地址空间，按系统习惯切成几段，每段的读写权限和放的东西都不一样。这张表就是进程的内存布局：

| 段 | 权限 | 放什么 | 谁管 |
| --- | --- | --- | --- |
| 内核段 | 不能读也不能写 | 操作系统自己 | 硬件 + OS |
| 栈 `stack` | RW | 局部变量、函数调用的现场 | 编译器自动进出 |
| 堆 `heap` | RW | `malloc` / `new` 申请的空间 | 程序员自己 `free` |
| 数据段 `.data` | RW | 已初始化的全局变量、`static` 变量 | 跟着程序加载 |
| 只读数据段 `.rodata` | RO | 字符串字面量、常量 | 跟着程序加载 |
| 代码段 `.text` | RO | 函数本身的指令 | 跟着程序加载 |

裸机上没有这套划分，整个地址空间就是程序员的，物理地址直接写；有了操作系统之后，分配权交出去，程序看到的是虚拟地址。

一个容易混的例子：`vector<int> a;` 这个对象本身在**栈**上，它内部维护的那块元素数组在**堆**上。所以拷贝一个 vector 会连带复制堆上那一整块，而 `int a[100]` 从头到尾都在栈上，出了作用域就没了。

## 一个经典的错误：改一个字符串字面量

有一段很短、几乎每个人都会先写一遍再被吓一跳的程序：用一个字符指针去接一个引号串出来的字面量，然后按下标把其中某个字符改掉，再打印出来。语法全对，编译通过，运行却直接崩，或者更糟——什么都没发生。

问题出在指针指向的那块内存的**权限**上，不在指针本身。引号写出来的内容属于常量，它被放进只读数据段，`.rodata` 这一段的段权限是只允许读、不允许写，向它发起一次写操作就是越权访问，操作系统会立刻终止这个进程。对比一下另一种写法：同样的内容如果先拷进一个字符数组，数组在栈上、是可写的，改它没有任何问题。**这两行代码的差别不在语法，也不在类型，只在那块内存属于哪一段。**

这也是为什么「编译通过」和「运行正确」是两件独立的事：编译器只检查类型和权限声明是否自相矛盾，它不会替你推断某块地址在运行时到底可不可写。

## 分段管理模型与段权限

把上面的表再往下推一层。一个进程看到的虚拟地址空间，低端的一小段和高端的（在 32 位环境下大约 3G 以上的那部分）都归操作系统持有，程序对这些区域既不可读也不可写，访问它们一律触发异常——这一层保护是硬件配合操作系统的页表一起做的，不是编译器加的。

| 段 | 权限 | 放什么 | 谁负责申请与释放 |
| --- | --- | --- | --- |
| 内核段 | 不可读、不可写 | 操作系统自身 | 硬件与 OS 保护 |
| 代码段 `.text` | RO | 函数编译出来的机器指令 | 随程序载入，运行期只读 |
| 只读数据段 `.rodata` | RO | 字符串字面量、常量数值 | 随程序载入 |
| 数据段 `.data` | RW | 已初始化的全局变量、`static` 变量 | 随程序载入，进程结束才回收 |
| 堆 `heap` | RW | 运行期动态申请的空间 | 程序员自己申请、自己释放 |
| 栈 `stack` | RW | 局部变量、函数调用的现场 | 编译器在进出作用域时自动处理 |

静态段和动态段的划分标准是「什么时候被确定」：代码段、只读数据段、数据段的内容在编译链接期就定好了，程序一载入就在；堆和栈要到运行期才出现，地址是执行过程中才分配的。`static` 修饰的变量比较特殊，它的作用域是编译单元或者函数内部，但存储位置在数据段，生命周期到进程结束，这三件事互相独立，不要混着记。

## 各段的使用注意事项

**栈空间由编译器在编译时安排，函数返回时自动回收，写栈溢出通常表现为整个进程崩溃；堆空间必须由程序员自己维护，这是内存泄漏的重灾区。** 两段的差别不是速度也不是容量，而是「谁负责收尾」。

栈上的东西出了作用域就没了，不需要也不能去释放它；把栈上某个局部变量的地址存起来带出去，得到的是一个悬空的指针，那块地址随后会被下一次函数调用覆盖。堆上的东西不会自己消失，申请了不释放，它就一直占着，直到进程结束才被系统收回——这就是泄漏。反复申请又反复泄漏的程序，可用内存单调下降，最后申请失败。

堆还有一层容易被忽略的代价：**申请到的地址段必须整段释放，只释放一半会让剩下那半成为再也找不回来的孤儿。** 指针变量本身被覆盖掉之后，那块内存还在，只是没有任何途径能访问它，也谈不上释放。

## 全局区与静态区

课件把这一段单独列成「static 区」和「全局区」，说的是同一类东西：全局变量和 `static` 修饰的变量都不在栈上，它们在程序载入时就占好了位置，进程结束才回收。初值已经给出的那些落在数据段，只声明没有初值的那部分由链接器归到另一段去，运行时由系统清零，两种写法占的空间性质是一样的。

需要区分的是三件互不相干的事：变量的存储位置、它的作用域、它的生命周期。`static` 改变的是后两件在某个维度上的取值，并不把变量搬到堆上，也不让它变成全局可见。局部 `static` 变量在函数返回后仍然存在，但只有这个函数能访问它；全局变量整个程序都能访问，可一旦加上 `static`，可见范围就收缩到当前这一个编译单元。

## 栈帧里装的是什么

函数调用时，栈上会为这次调用划出一块连续区域，里面放着这一层用到的局部变量、传进来的参数、返回之后要落到的地址，以及为保存现场而压入的那几个寄存器的值。函数返回就是把这块区域交还给系统，栈顶指针直接退回去，里面的内容并没有被清空，只是不再属于这一层——这一点和出栈之后的数据仍然留在堆栈里是同一回事。

递归过深之所以会崩，是因为每一次调用都要新压一个栈帧，而栈的总容量在程序启动时就被划定了，它不像堆那样可以在运行期继续申请。想加深处理深度，要么把递归改成显式栈放到堆上管理，要么调大栈的容量上限，两种做法的代价不一样：前者把控制权交回给写程序的人，后者只是把崩溃推迟。

## 指针和数组不是一回事

```c
int *p = (int *)0x100;	// 只有裸机上能这么直接写，OS 管着的地址空间里这是非法访问
```

`p[2]` 翻译成地址就是 `0x100 + 2 * sizeof(int)`，也就是 `0x108`。下标不是「第几个字节」，是「第几个对象」——偏移量由指针指向的类型决定，这就是为什么同一个 `p[2]`，`int *` 和 `char *` 算出来的地址差两倍。

`sizeof` 在这里会骗人：

```c
int arr[5];
sizeof(arr);   // 20，编译期就定下来的整块空间
int *q = arr;
sizeof(q);     // 4 或 8，量的是容器本身的大小
```

**数组名在定义它的作用域里代表整块空间，一旦作为参数传出去就退化成指针**：

```c
int fun(int arr[5]) {
	sizeof(arr);   // 4 或 8，那个 [5] 是装饰，收进来的只是地址
}
```

所以 C 里传数组进函数，长度必须另开一个参数带上——这是接口设计问题，不是语法问题。指针只是「存地址的容器」，它不知道也不关心那块地有多高。

## 结构体为什么比看起来大

```c
struct abc {
	char a1;	// 1
	short c1;	// 2
	int b1;		// 4
};
sizeof(struct abc);   // 8，不是 7
```

成员不是紧挨着摆的，每个成员的起始地址要是它自身大小的整数倍（超过编译器上限的按上限算）。于是 `a1` 占 0，1 号位填掉，`c1` 从 2 开始，`b1` 从 4 开始，一共 8。把顺序换成 `int / short / char` 是 4+2+1 再补 1 到 8，中间一处填充都不需要——声明顺序本身就是布局的一部分。

```c
struct x { int a; char b; int c; };
sizeof(struct x);   // 12：4 + 1(+3 填充) + 4
```

对齐是为了让 CPU 一次取完——拆成两次访问的代价在多数机器上是实打实的，某些架构上干脆是非法的。整个结构体的大小还要是最大成员对齐值的整数倍，所以尾部也可能有填充。内存对齐要求每个成员的起始地址是它自身大小的整数倍，尾部填充则让整个结构体的大小满足同样的要求；想改它就用 `#pragma pack` 或 `__attribute__((packed))` 告诉编译器按几字节对齐，但那是拿性能换空间。

## 当时卡住的两个问题

**`const char *p1` 和 `char *const p2` 到底谁被锁住了。** 从右往左读就行：`p1` 是指针，指向 `const char`，所以**值不能通过这个指针改，指针自己可以换指向**；`p2` 是 `const` 的指针，指向 `char`，所以**指向定死了，指向的内容随便改**。中间再插一个 `*` 就是两个都锁。

**`static` 到底锁住了什么。** C 里写一个函数，它的符号默认对整个程序可见，于是多个 `.c` 里有同名函数就在链接期撞车。规矩是对外接口在 `.h` 里声明，只在当前文件里用的辅助函数一律加 `static`——`static` 把符号的作用域关进这一个编译单元，链接器就看不到它，也就撞不上。

## 对照着背

| 写法 | 指针能换指向 | 能改指向的值 |
| --- | --- | --- |
| `const char *p` | 能 | 不能 |
| `char *const p` | 不能 | 能 |
| `const char *const p` | 不能 | 不能 |

| | 数组 | 指针 |
| --- | --- | --- |
| `sizeof` | 整块空间 | 4 或 8 |
| 传给函数 | 退化成指针 | 就是指针 |
| 谁分配 | 编译器在栈上划 | 自己 `malloc` 或指向别处 |

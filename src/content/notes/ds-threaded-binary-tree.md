## 空指针从哪来

一棵有 n 个结点的二叉树用二叉链表存，每个结点两个指针域，一共 `2n` 个指针。这棵树真正有孩子的连接（有效分支）只有 `n-1` 条——除根之外每个结点恰好被一条边接进来，根没有人接它，所以边比结点少一。于是空着的指针域是 `2n-(n-1)=n+1` 个，这个数只跟结点数有关，跟树长什么形状无关，是一条很稳的等式。

这 `n+1` 个 NULL 不是垃圾，它们每个都对应一个「本该有孩子却没有」的位置，比如一片叶子的左右指针、一个只有左孩子的结点的右指针。线索二叉树的全部动机就是：与其让这些指针空着浪费，不如把它们利用起来，改成指向遍历序列里的邻居，等于给每个结点顺带记住了「在我前面的是谁、在我后面的是谁」。

## 线索要指什么

先把一棵普通二叉树做一次某种次序的遍历，会得到一个线性序列，序列里每个结点都有唯一的前驱和唯一的后继（头结点没有前驱、尾结点没有后继）。拿一棵具体的树举例：对它做中序遍历得到的序列里，某个结点的左边那个就是它的前驱、右边那个就是它的后继，这层关系是遍历完之后才浮出水面的。麻烦在于：在二叉链表里想问「某个结点的中序前驱到底是谁」，光盯着这个结点问不出来，必须从根重新遍历一遍才能定位，代价是线性的。

线索化的定义就是把这些前驱后继关系提前存进空指针里：

- 若某结点的左孩子为空，就让它原来的左指针指向它在该遍历序列里的前驱；
- 若某结点的右孩子为空，就让它原来的右指针指向它在该遍历序列里的后继。

这样指向前驱和后继的指针就叫线索，把一棵普通二叉树按某种次序遍历并填上这些线索的整个过程叫线索化。填完线索的树就是线索二叉树。

## 标志位解决「是孩子还是线索」

问题立刻出现：一个左指针，它到底指向左孩子，还是指向前驱？光看指针值区分不了，两种情况下它都是一个非空地址。解决办法是在每个结点里再加两个标志位，通常记作 ltag 和 rtag。

| 标志位 | 取 0 | 取 1 |
| --- | --- | --- |
| ltag | 左指针指向左孩子 | 左指针指向前驱线索 |
| rtag | 右指针指向右孩子 | 右指针指向后继线索 |

约定是：ltag 为 0 时左指针是孩子、为 1 时是前驱线索；rtag 为 0 时右指针是孩子、为 1 时是后继线索。有了这对标志位，遍历到任何指针先读相应的 tag，就知道该跟着走还是要停下来处理。这是线索二叉树比二叉链表多花的存储代价——每个结点两个比特位，n 个结点就多 2n 个标志位，换掉的是原本 NULL 那部分浪费的空间。

很多教材还会在链表头部额外挂一个头结点，让它的左指针指向整棵树的根、右指针指向中序遍历的最后一个结点，并让首结点和尾结点那两端的空线索都反过来指向这个头结点，从而把线索链闭合成一个环形，遍历时可以一直往后转直到回到头结点为止。这个头结点只是实现上的小技巧，不是线索二叉树逻辑上的必需部分；判断一道题有没有用它，只要看首尾结点的标志位是不是被接到了哨兵上即可。

## 中序线索化怎么做

线索化不是遍历完再回填，而是在一次遍历的当下顺手把线索接上，一趟就完成。做中序线索化时，需要一把「前驱」的参照，常规做法是用一个全局或外层的指针 pre 始终指向刚刚访问过的那个结点，cur 则是此刻正在处理的结点，两者一前一后像两根紧挨着的游标。

递归中序走到某个结点时，按「先左、再根、后右」的顺序处理，接线索的动作全部落在「处理根」这一步。真正接线索发生在处理当前结点 cur 这一刻：

1. 如果 cur 的左孩子为空，就把 cur->lchild 指向 pre，并把 ltag 置 1——此刻 pre 正是 cur 的中序前驱。
2. 反过来，如果上一轮记下的 pre 的右孩子为空，就把 pre->rchild 指向 cur，rtag 置 1——此刻 cur 正是 pre 的中序后继。
3. 处理完把 pre 更新成 cur，继续向右子树递归。

整个流程里，pre 像一个跟着游标往后挪的指针，每访问一个新结点就补上「新结点的左线索」和「旧结点的右线索」这两条边。之所以能在递归进行中顺手接线，是因为中序的「左—根—右」恰好让前一个被访问的结点就是当前结点的前驱：当处理到 cur 时，pre 记录的就是刚才中序里排在 cur 前面的那个结点，所以 cur 的左空位填 pre、pre 的右空位填 cur 都是正确的线索，不用另外算。头结点的左指针最后指向 NULL（它没有前驱），尾结点的右指针指向 NULL（它没有后继），这两端是天然的哨兵，遍历到它们就该停。

## 有了线索怎么遍历

线索二叉树最大的用处就是不求解递归、不压栈就能走完整棵树的某个序列，这叫正向遍历；反向走（求前驱）同理，只是把上面那张表左右、前后来回对调。以中序为例，先找到序列的第一个结点：从根出发一路往左走，走到 ltag 为 1 的那个，就是中序的头，因为中序总是先把最左的叶子访问掉。之后每一步只问一件事：后继在哪？

| 当前结点的情况 | 后继在哪 |
| --- | --- |
| rtag 为 1（右指针是线索） | 后继直接就是右指针指向的结点 |
| rtag 为 0（右指针是右孩子） | 后继在右子树里，往右走一步后一路沿左孩子下到底 |

第一种情况顺着现成的线索一步到位，第二种情况才需要进右子树找最左结点。因为 n+1 个空指针里有相当一部分已经是线索，平均下来每个结点找后继只需常数级动作，整趟遍历是线性的，而且不占用系统栈、也不用自己维护一个显式栈。

## 其它次序与好处

线索化不止中序：先序线索化、后序线索化都存在，规则一模一样，只是「前驱后继」按对应遍历序列来定义。考试里最常考中序，因为它的前驱后继最好找；先序线索化里找前驱也要绕（一个结点若 ltag 为 0，它的前驱得看父结点关系），后序线索化更繁琐，这些都是中序之外容易失分的地方。

值得用一个五行的小结点数一下账。三结点的斜树 A→B→C（每个只有右孩子），二叉链表里左指针全空、共 4 个空指针，恰好等于 n+1。对它中序遍历得到 A、B、C，线索化后 A 的左空位没有前驱留 NULL、A 的右指针本就是孩子不动，B 的左空位接前驱 A、C 的左空位接前驱 B，C 的右空位没有后继留 NULL——填进去的线索把浪费的空指针变成了 O(1) 的前驱查询。这就是整节内容的缩影：先数出 n+1 个空位，再按遍历序列把它们逐条填成前驱后继。

再点一下先序和后序线索化难在哪。先序线索化里，一个 ltag 为 0 的结点想求它的前驱，前驱不在自己身上、也不在孩子上，而往往藏在某个祖先的右子树里，得回溯才知道，所以先序能 O(1) 求后继却不好求前驱。后序正相反：后序能顺着线索 O(1) 求前驱，求后继却要绕。只有中序线索化两边都规整——前驱在左、后继在右，空指针的位置和邻居的方向天然对齐，这正是它在考题里被反复选中的原因。

把线索二叉树的收益和代价摊开看：递归遍历要用系统栈、非递归遍历要额外开辟一个栈来辅助，而线索化之后这些辅助一概不需要，能像扫数组一样顺着指针往前走。一句话总结这一节：线索二叉树的本质是用固定的标志位代价，把二叉链表里注定浪费的空指针改造成前驱后继的快捷方式，从而把「问邻居」从需要重新遍历降为常数查找，把「走完全程」从需要栈降为顺指针直走。它不改变树的结构、不改变遍历序列，只是把遍历结果里隐含的顺序关系提前物化到了指针上。

## 易错点收口

考题里最容易翻车的三处，这里集中提醒。第一，n+1 这个空指针数目对所有形态的二叉树都成立，别被树长得多斜多偏带去重新数边。第二，标志位是必须交代的，只说「空指针指向前驱后继」而不提 ltag、rtag 如何区分孩子与线索，答案就不完整。第三，中序线索化里找后继要分两种：右指针是线索时一步到位，右指针是右孩子时必须进到右子树再一路向左下到底——把这两条并成一条「顺着右指针走」是错的。第四，线索化是按某种遍历次序定义的，换了遍历次序前驱后继就全变，别把先序的线索当成中序的用。抓住这几点，这一节的定义、构造、遍历三种问法就都能答圆。

## 前言：方法不止一种，比较才有意义

解决一个问题通常不止一种办法，需要一套能比较不同算法性能的方法，再从中挑出合适的。衡量一个算法只有两个维度：执行时间和占用的内存空间，运行时间越短、内存占用越小的算法越优。

对效率的分析分成两个阶段。算法完成之前的**理论分析**，把所有其它因素（处理器速度、编译质量等）假设为恒定，考察的对象是算法本身，与它最终怎么被实现无关。算法实现之后的**实际分析**，要考虑算法用了哪门编程语言，把程序放到特定计算机上执行，消耗的时间与硬件水平直接相关，此时收集的是运行时间、所需空间这类真实的统计数据。

## 「好」算法的标准

能称得上算法，先要满足两条底线：一是**准确性**，它必须能彻底解决所讨论的问题；二是**健壮性**，由它编写出的程序在任何情况下都不能崩溃。

算法与程序是两个东西。算法是解决某个问题的想法与思路，程序是依据算法编写出来的、真正可以运行的代码。要依次输出一维数组里每个数据元素的值，先想到的是用循环结构处理，这个循环思路是算法，把它翻译成语句才是程序。

在准确性和健壮性都被满足之后，才轮到第三个筛选条件：由算法编写出的程序的运行效率。运行效率具体从两处衡量——程序的运行时间，以及程序运行所需内存空间的大小。运行时间更短、运行期间占用内存更少的算法效率更高。数据结构里用时间复杂度衡量运行时间的多少，用空间复杂度衡量所需内存空间的大小。

## 为什么不能只靠实测

把代码跑一遍，通过统计与监控就能拿到执行时间和占用内存，这条评估路径本身是正确的，很多教材还给它起了名字。把代码写完再上机统计的做法叫事后统计法，它得到的数字依赖硬件与软件环境，于是改用不依赖具体测试数据的事前分析估算法。

实测的局限有两条。

其一是**测试结果依赖测试环境**。同样一段代码，放在高端处理器上和放在低端处理器上，执行速度差很多；在这台机器上代码 a 比代码 b 快，换一台机器，结论可能完全相反。

其二是**测试结果受数据规模影响很大**。测试数据规模太小时，结果无法真实反映算法性能，例如小规模的数据排序里，插入排序反倒可能比快速排序更快。

于是需要一种不用具体测试数据、就能粗略估计算法执行效率的方法，这就是时间复杂度和空间复杂度分析方法。

## 复杂度估计方法

对一个给定的算法要做两项分析。第一项是从数学上证明算法的正确性，用到形式化证明的方法与相关推理模式，例如循环不变式、数学归纳法。第二项是在正确性的基础上分析算法的时间复杂度，它反映程序执行时间随输入规模增长而增长的量级，在很大程度上能反映算法的优劣。

度量一个程序的执行时间有两种方法。

**事后统计法**可行，但不是好方法，两个缺陷：想对设计的算法的运行性能做评测，必须先依据算法编制相应的程序并实际运行；所得时间的统计量依赖于计算机的硬件、软件等环境因素，有时反而掩盖了算法本身的优势。

**事前分析估算法**在编写程序之前，依据统计方法对算法进行估算。一个用高级语言编写的程序在计算机上运行时消耗的时间取决于四个因素：算法采用的策略与方法、编译产生的代码质量、问题的输入规模、机器执行指令的速度。

一个算法由控制结构（顺序、分支、循环三种）和原操作（固有数据类型的操作）构成，算法时间取决于两者的综合效果。为了便于比较同一问题的不同算法，通常的做法是从算法里选出一种对所研究的问题而言属于基本操作的原操作，以该基本操作重复执行的次数作为算法的时间量度。

## 时间频度与大O

一个算法执行所耗费的时间，理论上算不出来，必须上机运行测试才知道。但没必要对每个算法都上机测试，只要知道哪个算法花费的时间多、哪个少就够了。算法花费的时间与其中语句的执行次数成正比例，哪个算法中语句执行次数多，它花费时间就多。一个算法中的语句执行次数称为语句频度或时间频度，记作 T(n)。

把时间频度的最高次幂单独挑出来、丢掉系数与低次项，剩下的就是大O记号里的那个 f(n)。

在时间频度里 n 称为问题的规模，n 不断变化时 T(n) 也不断变化，需要知道它变化时呈现什么规律，为此引入时间复杂度。一般情况下，算法中基本操作重复执行的次数是问题规模 n 的某个函数，用 T(n) 表示；若有某个辅助函数 f(n)，使得当 n 趋近于无穷大时 T(n)/f(n) 的极限值是不等于零的常数，则称 f(n) 是 T(n) 的同数量级函数，记作 T(n) = O(f(n))，O(f(n)) 称为算法的渐进时间复杂度，简称时间复杂度。

这里的 O 属于 Landau 符号体系，同族还有小 o 符号与 Θ 符号，计算算法复杂度时一般只用到 O。这个符号最初用大写希腊字母书写，现在都用大写英文字母 O；小 o 符号同样用小写英文字母 o，Θ 符号则维持大写希腊字母。

T(n) = O(f(n)) 表示存在一个常数 C，使得当 n 趋于正无穷时总有 T(n) ≤ C·f(n)，也就是 n 趋于正无穷时 T(n) 的上界是 C·f(n)。f(n) 没有硬性规定，一般取尽可能简单的函数：O(2n²+n+1) = O(3n²+n+3) = O(7n²+n) = O(n²)，只写 O(n²) 即可。O 符号里隐藏着一个常数 C，f(n) 里一般不加系数。把 T(n) 看成一棵树，O(f(n)) 表达的是树干，只关心主干，细枝末节全部舍弃。

按数量级递增排列，常见的时间复杂度有：常数阶 O(1)、对数阶 O(log₂n)、线性阶 O(n)、线性对数阶 O(nlog₂n)、平方阶 O(n²)、立方阶 O(n³)、k 次方阶 O(n^k)、指数阶 O(2^n)。随着问题规模 n 增大，复杂度依次变高，算法的执行效率依次变低。常见算法时间复杂度由小到大依次为 O(1) < O(log₂n) < O(n) < O(nlog₂n) < O(n²) < O(n³) < … < O(2^n) < O(n!)。

对一个问题或一类算法，一般只需选择一种基本操作来讨论时间复杂度，有时也要同时考虑几种基本操作，甚至给不同操作赋予不同权值，以反映执行不同操作所需的相对时间，这种做法便于综合比较解决同一问题的两种完全不同的算法。

## 求复杂度的具体步骤

第一步，找出算法中的基本语句，即执行次数最多的那条语句，通常是最内层循环的循环体。第二步，计算基本语句执行次数的数量级，只要保证次数函数中的最高次幂正确即可，所有低次幂和最高次幂的系数都可以忽略，这样既简化分析，又把注意力集中在最重要的增长率上。第三步，用大O记号表示算法的时间性能，把基本语句执行次数的数量级放进大O记号中。

O(1) 表示基本语句的执行次数是一个常数，一般来说只要算法中不存在循环语句，其时间复杂度就是 O(1)。

其中 O(log₂n)、O(n)、O(nlog₂n)、O(n²)、O(n³) 称为多项式时间，O(2^n) 和 O(n!) 称为指数时间。计算机科学家普遍认为前者是有效算法，把这类问题称为 P（Polynomial，多项式）类问题，把后者称为 NP（Non-Deterministic Polynomial，非确定多项式）问题。

多项式级的复杂度通常可以接受，很多问题都有多项式级的解，即对规模为 n 的输入能在 n^k 时间内得到结果，这类问题称为 P 问题。有些问题没有多项式时间的解，但可以在多项式时间里验证某个猜测是否正确。比如问 4294967297 是不是质数，直接入手要把小于它平方根的所有素数都拿出来逐个试除；而这个数等于 641 与 6700417 的乘积，验证这个分解只需做一次乘法，顺带说明费马的猜想不成立。大数分解、Hamilton 回路之类的问题，都可以在多项式时间内验证一个解是否正确，这类问题叫做 NP 问题。

## 两条分析法则

简单的输入输出语句或赋值语句，近似认为需要 O(1) 时间。

顺序结构依次执行一系列语句，用大O下的求和法则：若算法两个部分的时间复杂度分别为 T1(n) = O(f(n)) 和 T2(n) = O(g(n))，则 T1(n) + T2(n) = O(max(f(n), g(n)))；特别地，若 T1(m) = O(f(m))、T2(n) = O(g(n))，则 T1(m) + T2(n) = O(f(m) + g(n))。

选择结构如 if 语句，主要时间耗费在执行 then 字句或 else 字句所用的时间，检验条件本身也需要 O(1) 时间。

循环语句的运行时间体现在多次迭代中执行循环体以及检验循环条件的时间耗费，一般用大O下的乘法法则：若算法两个部分的时间复杂度分别为 T1(n) = O(f(n)) 和 T2(n) = O(g(n))，则 T1·T2 = O(f(n)·g(n))。

复杂的算法可以分成几个容易估算的部分，再用求和法则与乘法法则合起整个算法的时间复杂度。另外两条运算法则：若 g(n) = O(f(n))，则 O(f(n)) + O(g(n)) = O(f(n))；O(C·f(n)) = O(f(n))，其中 C 是一个正常数。

## 五个数量级各算一遍

**O(1)**：用三个赋值语句完成两个变量的值交换，三条语句的频度均为 1，该程序段的执行时间是一个与问题规模 n 无关的常数，时间复杂度为常数阶，记作 T(n) = O(1)。如果算法的执行时间不随问题规模 n 增加而增长，即使算法中有上千条语句，执行时间也不过是一个较大的常数，此类算法的时间复杂度仍是 O(1)。

**O(n²)**：外层循环 i 从 1 走到 n，内层循环 j 从 1 走到 2n，内层里有一条自增语句。外层语句的频度是 n-1，内层语句的频度是 (n-1)(2n+1) = 2n²-n-1，合计 f(n) = 2n²-n-1+(n-1) = 2n²-2，去掉低阶项、去掉常数项、去掉高次项的系数，该程序的时间复杂度 T(n) = O(n²)。另一段两层循环累加求和的写法，外层频度 n+1、内层与循环体各 n²，同样落在平方阶。

对步进循环语句一般只需考虑循环体中语句的执行次数，忽略该语句中步长加一、终值判别、控制转移等成分；当有若干个循环语句时，算法的时间复杂度由嵌套层数最多的循环语句中最内层语句的频度 f(n) 决定。

**O(n)**：两条初始化语句频度合计 2，一个循环的循环体里有三条语句，循环执行 n 次、循环体内三条语句各 n-1 次，于是 T(n) = 2 + n + 3(n-1) = 4n-1 = O(n)。

**O(log₂n)**：i 从 1 开始，每轮把 i 乘以 2，直到 i 超过 n 才停。设该语句的频度是 f(n)，则 2^f(n) ≤ n，得 f(n) ≤ log₂n，取最大值 f(n) = log₂n，因此 T(n) = O(log₂n)。

**O(n³)**：三重嵌套循环，最内层是一条自增语句。当外层取到 m、中层取到 k 时内层执行 k 次，外层为 m 时中层可取 0 到 m-1，最内层共进行 0+1+…+m-1 = (m-1)m/2 次；外层从 0 取到 n，累加得 0 + (1-1)·1/2 + … + (n-1)n/2 = n(n+1)(n-1)/6，所以时间复杂度为 O(n³)。

一条经验规则：把常量 c 撇开不看，`O(c)`、`O(log₂n)`、`O(n)`、`O(n·log₂n)` 这几档算效率高的；`O(2ⁿ)`、`O(n!)` 只要 n 稍微大一点就算不动了；夹在中间的平方阶、立方阶属于「n 小的时候还能跑」的那一类。

## 空间复杂度

与时间复杂度的讨论类似，一个算法的空间复杂度 S(n) 定义为该算法所耗费的存储空间，它也是问题规模 n 的函数，渐进空间复杂度常常简称为空间复杂度。

空间复杂度是对一个算法在运行过程中临时占用存储空间大小的量度。一个算法在计算机存储器上占用的存储空间包括三个方面：存储算法本身所占用的存储空间、算法的输入输出数据所占用的存储空间、算法在运行过程中临时占用的存储空间。输入输出数据占用的空间由要解决的问题决定，通过参数表由调用函数传递而来，不随本算法的不同而改变。存储算法本身的空间与算法书写的长短成正比，要压缩这方面的存储就得编写出较短的算法。运行过程中临时占用的空间随算法而异：有的算法只需要占用少量的临时工作单元，且不随问题规模的大小而改变，这种算法是就地进行的，属于节省存储的算法；只占用少量且不随规模变化的临时单元的算法叫就地算法，这一项正是空间复杂度里要统计的临时空间。有的算法需要占用的临时工作单元数与解决问题的规模 n 有关，随 n 增大而增大，当 n 较大时将占用较多的存储单元，快速排序和归并排序算法就属于这种情况。

当一个算法的空间复杂度为一个常量，即不随被处理数据量 n 的大小而改变时，可表示为 O(1)；当一个算法的空间复杂度与以 2 为底的 n 的对数成正比时，可表示为 O(log₂n)；当一个算法的空间复杂度与 n 成线性比例关系时，可表示为 O(n)。若形参为数组，则只需要为它分配一个存储由实参传送来的一个地址指针的空间，即一个机器字长空间；若形参为引用方式，则也只需要为其分配存储一个地址的空间，用它来存储对应实参变量的地址，以便由系统自动引用实参变量。

## 同一份代码的四种口径

时间复杂度进一步可以划分为最好、最坏、平均、摊均四种。

一份在长度为 n 的整型数组里查找整数 x 的代码，功能是把 x 在数组中的位置找出来，找到就直接返回。要查找的变量 x 可能出现在数组的任意位置：如果第一个元素正好是 x，就不需要继续遍历剩下的 n-1 个数据，时间复杂度是 O(1)；如果数组中不存在 x，就得把整个数组都遍历一遍，时间复杂度成了 O(n)。同一段代码在不同情况下的复杂度不一样，为此引入三个概念。

**最好时间复杂度**是在最理想的情况下执行这段代码的复杂度，对应要查找的变量 x 正好是数组的第一个元素。

**最坏时间复杂度**是在最糟糕的情况下执行这段代码的复杂度，对应数组中没有要查找的变量 x、需要把整个数组都遍历一遍。

**平均情况时间复杂度**处理的是极端情况概率不大的问题。要查找的变量 x 在数组中的位置有 n+1 种情况：在数组的 0 到 n-1 位置中，以及不在数组中。把每种情况下查找需要遍历的元素个数累加起来再除以 n+1，得到需要遍历的元素个数的平均值，即 (1+2+3+…+n+n)/(n+1) = n(n+3)/(2(n+1))，省略掉系数、低阶、常量，得到的平均时间复杂度就是 O(n)。

这个结论正确，计算过程却有问题：n+1 种情况出现的概率并不一样。要查找的变量 x 要么在数组里、要么不在数组里，为方便理解假设两者的概率都是 1/2；要查找的数据出现在 0 到 n-1 这 n 个位置的概率也一样，为 1/n，根据概率乘法法则，出现在任意位置的概率就是 1/(2n)。把每种情况发生的概率考虑进去，1·1·1/(2n) + 2·1/(2n) + 3·1/(2n) + … + n·1/(2n) + n·1/2 = (3n+1)/4。这个值就是概率论中的加权平均值，也叫作期望值，所以平均时间复杂度的全称应该叫加权平均时间复杂度或者期望时间复杂度。引入概率后前面那段代码的加权平均值为 (3n+1)/4，用大O表示法去掉系数和常量，这段代码的加权平均时间复杂度仍然是 O(n)。

把最坏时间复杂度、最好时间复杂度和平均时间复杂度放在一起看，同一段顺序查找的代码在两种输入下整整差出一个量级。大多数情况下并不需要区分这三种，很多时候一个复杂度就能满足需求；只有同一块代码在不同情况下的时间复杂度有量级的差距，才会用这三种表示法来区分。

**摊均时间复杂度**听起来与平均时间复杂度很像，应用场景却更特殊、更有限。一段往定长数组里插入数据的代码，数组满时先用一轮循环遍历数组求和并清空数组，把求和结果放到数组的第一个位置，再插入新数据；数组一开始有空闲空间时，则直接将数据插入。最理想的情况下数组中有空闲空间，只需将数据插入到下标为 count 的位置，最好情况时间复杂度为 O(1)；最糟糕的情况下数组中没有空闲空间，要先做一次数组的遍历求和再插入数据，最坏情况时间复杂度为 O(n)。按概率论的方法算平均：数组长度为 n，按插入位置不同可分为 n 种情况，每种情况的时间复杂度是 O(1)，除此之外还有一种额外情况，即数组没有空闲空间时插入一个数据，时间复杂度是 O(n)，这 n+1 种情况发生的概率一样都是 1/(n+1)，加权平均 1·1/(n+1) + … + 1·1/(n+1) + n·1/(n+1) 的结果是 O(1)。

这个例子其实不需要引入概率论。对比查找与插入两份代码有两点差别：查找函数只有在极端情况下复杂度才是 O(1)，插入函数在大部分情况下时间复杂度都是 O(1)，只有个别情况下复杂度才比较高、为 O(n)；插入函数里 O(1) 的插入和 O(n) 的插入出现的频率非常有规律，而且有前后时序关系，一般是一个 O(n) 的插入之后紧跟着 n-1 个 O(1) 的插入操作，循环往复。针对这种特殊场景，不必找出所有输入情况及相应发生概率再计算加权平均值，改用一种更加简单的分析方法：对付这种有固定时序的操作序列，用摊还分析法把耗时多的那次操作平摊到后面耗时少的若干次操作上。每一次 O(n) 的插入都会跟着 n-1 次 O(1) 的插入，把耗时多的那次操作均摊到接下来的 n-1 次耗时少的操作上，这一组连续的操作的均摊时间复杂度就是 O(1)。

均摊时间复杂度和摊还分析的应用场景比较特殊，不会经常用到。对一个数据结构做一组连续操作，大部分情况下时间复杂度都很低、只有个别情况下比较高，而且这些操作之间存在前后连贯的时序关系，这时就可以把这一组操作放在一块儿分析，看能否将较高时间复杂度那次操作的耗时平摊到其他那些较低时间复杂度的操作上。在能够应用均摊时间复杂度分析的场合，一般均摊时间复杂度就等于最好情况时间复杂度。

## 对照着背

| 概念 | 一句话口径 |
| --- | --- |
| 理论分析 | 假设其它因素恒定，只考察算法本身，与实现无关 |
| 实际分析 | 算法实现后在特定机器上执行，收集运行时间与所需空间的统计数据 |
| 好算法的底线 | 准确性：能彻底解决问题；健壮性：任何情况下不崩溃 |
| 效率的两个方面 | 运行时间、运行所需内存空间的大小 |
| 实测的两个局限 | 结果依赖测试环境；结果受数据规模影响很大 |
| 事后统计法缺陷 | 必须先编出程序并实际运行；统计量依赖硬件软件环境 |
| 事前估算的四个因素 | 算法策略、编译产生的代码质量、输入规模、机器执行指令的速度 |
| 时间量度取什么 | 取基本操作（原操作）重复执行的次数 |
| 数量级顺序 | O(1) < O(log₂n) < O(n) < O(nlog₂n) < O(n²) < O(n³) < O(2^n) < O(n!) |
| P 与 NP | 多项式时间可解的是 P；多项式时间内可验证猜测的是 NP |
| 求和法则 | 两段顺序执行取 max(f(n), g(n)) |
| 乘法法则 | 两段嵌套执行取 O(f(n)·g(n)) |
| 空间三来源 | 算法本身、输入输出数据、运行中临时占用 |
| 平均的两种算法 | 简单平均除以 n+1；加权平均按 1/(2n) 与 1/2 加权，得 (3n+1)/4 |
| 摊还的适用条件 | 大部分操作很快、个别操作很慢，且两者有固定前后时序 |

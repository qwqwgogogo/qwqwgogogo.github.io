## 定义里的两个关键词

树是 n 个结点的有限集合：n 为 0 时是空树，非空时有且只有一个根，剩下的结点分成若干棵**互不相交**的子树。一棵树里一个孩子都没有的结点叫叶子节点，有孩子的叫分支结点；结点拥有的孩子数就是它的度，所有结点的度里最大的那个才是整棵树的度。结点按根在第 1 层往下数，最深的结点落在第几层，这棵树的深度就是几。

二叉树和树的差别在两处：二叉树**规定左右**，左孩子和右孩子颠倒就是另一棵树；二叉树**允许为空**，而且每个结点最多两个孩子不等于它是个「度为 2 的树」——一个孩子时还要区分是左还是右。所以「二叉树是特殊的树」这句话是错的，它是另一种结构。

## 几条能算的性质

| 说法 | 公式 |
| --- | --- |
| 二叉树第 i 层最多 | `2^(i-1)` 个结点 |
| 深度为 k 的二叉树最多 | `2^k - 1` 个结点 |
| 叶子数与度为 2 的结点数 | `n0 = n2 + 1` |
| n 个结点的树，总度数 | 一定是 `n - 1` |
| 含 n 个结点的完全二叉树深度 | `log2(n+1)` 向上取整 |

`n0 = n2 + 1` 这条最好用的形式是「叶子数 = 度为 2 的结点数 + 1」，题目给一半就能求另一半。总度数等于结点数减 1，是因为除根以外每个结点都恰好被一条边连着——树的边数永远是 `n-1`，这一条在图和树混合出题时用来做区分。

满二叉树每层都填满；完全二叉树只要求最后一层从左往右连续排、不许中间断。两者的关系是满的必完全，完全的未必满。编号从 1 开始数，第 i 个结点的双亲是 `i/2` 向下取整，左孩子 `2i`、右孩子 `2i+1`——**数组存完全二叉树就靠这三行**，堆就是这么实现的。

## 四种存法

链式最直白：数据域加左右孩子指针，空位置填 NULL，n 个结点的二叉树里有 `n+1` 个空指针，这个富余后来正好被线索化拿去用了。

顺序存储用数组按下标编号存，只对完全二叉树划算；一旦树形退化成一条链，`2i` 会迅速越界，为了放 n 个结点要开 `2^h - 1` 个单元，浪费指数级的空间。

双亲表示法是每个结点只记「我爸是谁」，向上一路走很快，向下的孩子要遍历整张表找——适合频繁查祖先、不常查孩子的场景。孩子表示法则反过来，把每个孩子串成表挂在结点后面。

孩子兄弟表示法是每个结点存「第一个孩子」和「下一个兄弟」两根指针，它一出现就把树和二叉树缝在了一起：任何一棵树或森林用它表示出来，形状就是一棵二叉树，规则叫**左孩子右兄弟**。森林转成二叉树时，第一棵树的根还在根上，第二棵及以后的树全部挂到它的右子树上去——这也是为什么「一棵树转换出来的二叉树，根结点没有右孩子」。

## 遍历的四种写法

先序是根左右，中序是左根右，后序是左右根，层序是从上往下、同层从左往右。名字记的是**根结点在哪个位置被访问**，孩子那两棵子树的相对顺序永远不变。

层序遍历必须靠队列，宽度优先地一层层推；另外三种是递归，改写成非递归就自己拿栈模拟，重点是「访问」和「展开」的时机不同——中序非递归要沿着左孩子一路压到底再弹出来访问，先序则压栈时就访问。

## 由序列还原二叉树

**中序 + 另一个** 才能确定一棵树：先序或后序能告诉你根是谁，中序负责把左右子树切开——根在中序里把整段分成两半，左边全是左子树，右边全是右子树，递归下去即可。先序 + 后序不行，因为只剩一个度为 1 的结点时，无法判断那孩子是左还是右。层序 + 中序同样可以，性质和先序一样是「能定根」。

线索二叉树是把上面提到的 `n+1` 个空指针利用起来：指向前驱和后继，配一个标志位说明这根指针是孩子还是线索。于是遍历不用递归也不用栈，顺着线索就能走完全程。中序线索化最常考，坑在于「找后继」分两种情况：有右子树就去右子树的最左结点，没有就顺着线索走下去。

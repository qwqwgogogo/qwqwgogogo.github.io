## 一句话

**补码的全部意义，是让减法在硬件里消失**：符号位和数值位一起进加法器，加和减走同一条电路，溢出的事留给判断逻辑单独处理。

## 定点数把小数点钉死

数据在机器里就是一串二进制位，小数点放在哪，靠的是约定而不是存储。所谓定点数，就是把小数点的位置固定下来的数值类型，通常由一个符号位加上若干数值位组成。按小数点钉在哪里，分成两类：

| 类型 | 小数点位置 | 形式 |
| --- | --- | --- |
| 定点整数 | 钉在最低位之后 | `XXXXXX.0` |
| 定点小数 | 钉在符号位之后 | `0.XXXXXX` |

约定是强制的：有符号数里小数点默认紧跟着符号位，无符号数里小数点默认排在最前面。正因为位置写死了，硬件不必为每个数单独记录小数点，运算时把它当成整数处理，最后再由约定解释成整数或纯小数。整数和纯小数都用定点数表示；既有整数部分又有小数部分的实数，定点这一套位置固定不住，只能交给浮点数——小数点会随阶码移动，这一点留到浮点章节再讲。

## 加法器与 ALU

现代计算机里加法是最频繁的基本操作，它在硬件层面由加法器电路实现。加法器接收两个二进制数，按逐位相加的规则处理，并沿位链传递进位。减法的手动逻辑虽然和小学竖式类似，机器内部却不单独做减法，而是把它折算成加法：取反再加。原因是加法器天生擅长做加法，让同一套门电路兼办减法，比再造一个减法器划算得多。

把加法器、移位器、逻辑门打包在一起的核心部件叫 ALU，也就是算术逻辑单元。ALU 负责算术运算、逻辑运算、比较和移位这几类工作，而它的内部核心正是那颗加法器。各类定点数的加减由 ALU 直接完成，乘除和浮点运算则是在加法器与移位器的基础上反复迭代出来的。写代码的人只管写下减号，底层怎么取反、怎么补加，全由硬件自动处理，程序员感知不到。

## 原码为什么加不动异号

原码的表示方式是符号位直接拼上绝对值，比如 `1 1010` 读作负十。它的致命弱点是符号位不参与运算，于是加减必须分情况讨论：

- 同号相加：符号位保持不变，数值位直接相加。
- 异号相加：要先比较两个数绝对值的大小，用大的减小的，再把结果的符号定成绝对值较大那一个。

问题出在第二步。异号运算时硬件无法一眼看出谁大谁小，得多跑一次比较逻辑才能定符号，控制通路绕了一圈。原码做减法同理，先得判断大小以确定结果符号，再拿绝对值相减。这种「先比较再决定加还是减」的分支，正是原码不适合直接当运算码的原因。

## 补码让符号位一起加

补码把符号位当成数值的一部分，让它在加法器里跟着一起加，从此加减统一。设机器字长为 `n+1` 位（一位符号加 `n` 位数值），模是 `2^(n+1)`：

```
[A + B]补 = [A]补 + [B]补   (mod 2^(n+1))
[A - B]补 = [A]补 + [-B]补
```

其中 `[-B]补` 等于把 `[B]补` 连符号位一起按位取反再加 1。这意味着减法器根本不需要存在：一个加法器外加一路取反门就够。原码里那次「先比大小」的额外动作被彻底省掉，因为补码加法的结果符号是自动算出来的，正负一目了然。计算机内部有符号数默认就用补码存放，重点要练熟的就是补码加减。

补码还有一个附带好处：零的表示是唯一的，`+0` 和 `-0` 在补码里是同一串位，不会出现原码那种一个零两种编码的歧义。

## 溢出怎么判

字长固定意味着能表示的范围有限，`n+1` 位补码覆盖 `[-2^n, 2^n - 1]`。两个数相加的结果一旦跳出这个区间，就是溢出，分正溢出和负溢出两个方向。判断方法有三种：

| 方法 | 判据 | 特点 |
| --- | --- | --- |
| 按符号看 | 两正相加得负、两负相加得正即溢出 | 手算直观，硬件要额外取符号位比较 |
| 按进位看 | 符号位的进位 `C_s` 与最高数值位的进位 `C_{s-1}` 不一致即溢出 | 硬件最省，加法器现成两根进位线 |
| 双符号位 | 用两位编码符号，结果 `01` 正溢、`10` 负溢，`00`/`11` 正常 | 变形补码，一眼看出往哪边溢出 |

第一种说法是「和的符号位与两个加数的符号位都不同」才算溢出，因为同号相加才会溢出，异号相加绝不会。第三种双符号位是把符号扩展成两位，正常时两位相同，溢出时一位正确一位错误，正负方向直接写在符号对上。

值得强调的是，这三条不是三套独立规则，而是同一件事的三种写法。以正溢出为例，真值超出了最大正数，数值位向符号位进了 1，而符号位自己没有向更高位进出去，于是 `C_s` 与 `C_{s-1}` 不相等，同时双符号位呈现 `01`，符号位判法也报出「两正得负」。抓住正溢出的物理图像，三种判法可以互相推出来。

## 两个容易错的点

第一，**溢出和进位是两码事**。无符号数最高位向外进 1 是正常进位，对应处理器的 CF 标志；补码最高位向外进 1 不一定代表溢出，要看符号位那一位的进位是否和它一致，对应 OF 标志。同一条加法指令会同时置起 CF 和 OF，把其中一个当成另一个用就出错。

第二，**两个 `n` 位补码相加，理论上要 `n+1` 位才保证装得下结果**。机器字长固定、多不出这一位时，才会产生溢出概念。溢出不是硬件算错了，而是位数不给，结果无处安放。

## 数值走一遍

设字长为 5 位（1 位符号 + 4 位数值），能表示的补码范围是 `[-16, 15]`。把十进制转成补码，负数用「取反加一」：

```
[+9]补 = 0 1001     [-9]补 = 1 0111
[+6]补 = 0 0110     [-6]补 = 1 1010
```

先算 `9 - 6`。减法被折成加法，`[9]补 + [-6]补 = 01001 + 11010 = 1 00111`，丢掉超出字长的进位后得 `00111`，读作 +3，正确。这里最高位产生了一个进位，它被模 `2^5` 自然丢弃，是正常进位，不是溢出，CF 与 OF 恰好演示了二者的区别。

再算 `9 + 6 = 15`，`01001 + 00110 = 01111`，符号位仍是 0，没超出上界，正常。把加数换成更大的正数，`9 + 8 = 17`，`01001 + 01000 = 10001`，两个正数加出了负的结果，符号位判法立刻报警——这就是正溢出。改用双符号位重看这一步：`9` 写成 `00 1001`，`8` 写成 `00 1000`，相加得 `01 0001`，两位符号变成了 `01`，正好是正溢出的标记；而负溢出（比如 `-9 + -8`）会得到符号对 `10`。正常结果两位符号相同，`00` 为正、`11` 为负，只要它们一正一负就说明越界。三条判法在同一个数上给出的是同一个结论。

## 对照着背

| | 原码 | 补码 |
| --- | --- | --- |
| 符号位 | 不参与运算 | 参与运算 |
| 减法 | 转成比较绝对值再减 | 加上相反数的补码 |
| 零 | 有 `+0` 和 `-0` 两种 | 唯一 |
| 硬件代价 | 需要额外的比较逻辑 | 一个加法器通吃 |

原码加减法直观但绕，补码加减法把符号位一并丢进加法器，溢出留给双符号位或进位异或去判——把这条主线记牢，定点加减这一节就完整了。

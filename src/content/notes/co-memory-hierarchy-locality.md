## 一句话

任何一台机器都造不出「又大、又快、又便宜」的存储器，只能造出一个**分层**的假象：让程序自己把最常用的那一小撮数据顶到最上层去，其余的沉在下面慢慢等着。这一篇讲的是这套假象成立的前提，以及描述它的全部术语。

## 为什么非要分层

一个程序在它的一生里会碰到海量的地址，但在任何一个瞬间，它真正关心的地址只占整个地址空间里很小的一小块。这个观察是整个存储器设计的支点：如果程序对全部地址一视同仁、以完全相同的概率去访问它们，那么无论把上层做得多快都没用，因为下一次访问落到哪一层完全看运气，层次结构就没有意义了。

正因为不是这样，才可以用一条「把活跃的一小块放在小而快的器件上、把全部数据放在大而慢的器件上」的构造，让程序感受到的**速度接近最快的那一层，成本接近最便宜的那一层**。厨房台面的比喻之所以成立，就在于做菜时手里的几样调料会被反复用到，而不常用的那瓶油可以留在架子上。

## 局部性原理

CPU 访问存储器时，无论取指令还是取数据，被访问的单元倾向于聚集在一个较小的连续区域里。这个行为模式就叫局部性，它被拆成两维，两维的来源不一样，工程上的用法也不一样。

### 时间局部性

如果某个信息项此刻正在被访问，那么它在不远的将来很可能再次被访问，这就是时间局部性。

它的来源主要是控制结构本身：循环体里的指令和变量在一轮又一轮中被重复触碰；函数调用时栈顶的若干单元在返回之前被密集读写；查表热项、迭代矩阵元素，都会把同一批数据反复过手。做 Cache 管理时对应的手段是「刚被访问过的东西优先保留」，替换算法里 LRU 的判据直接就是这一条。

### 空间局部性

在最近的将来要用的信息，很可能在地址上和此刻正在用的信息挨着，这就是空间局部性。

它的来源有两个。一是指令本身：绝大多数时间里程序是一条接一条顺序执行的，只有遇到转移才会跳走；统计上一台机器里顺序执行与跳转访问的比例大致在 5:1 这个量级。二是数据结构：数组、结构体、记录在存储器里都是按地址连续摆放的，访问了 `a[i]`，紧接着访问 `a[i+1]` 是很常见的模式。

空间局部性对应的硬件手段是**按一批连续的字一起搬运**，而不是一个一个字地搬——这正是下一节「块」这个概念存在的理由。

两维合起来才是完整的赌注。时间局部性是「这个还会再被用到」，空间局部性是「它的邻居马上会被用到」，任何只依赖其中一维的设计都会在另一半负载上失效。

## 存储器层次结构的具体台阶

把上面那套逻辑摊开，就得到一张从 CPU 往外扩散的表。存储器层次结构的核心规则只有一条：越靠外的层越慢、越大、越便宜。

| 层级 | 典型器件 | 速度量级 | 每比特成本 | 角色 |
| --- | --- | --- | --- | --- |
| 寄存器 | 触发器 | 最快 | 最高 | CPU 内部，指令直接寻址 |
| 高速缓存 L1/L2/L3 | SRAM | 几到几十个纳秒 | 高 | 盖住 CPU 与主存的速度差 |
| 主存储器 | DRAM | 几十到上百纳秒 | 中 | 程序运行时的实际工作区 |
| 磁盘、固态硬盘 | 磁性介质 / NAND 闪存 | 微秒到毫秒 | 低 | 主存的后备，长期保存 |

**越靠上的层越快、越贵、越小**，这是判分层题的口诀。层次结构要达到的效果，是对用户呈现一个「容量按最下层算、速度按最上层算、成本按最下层算」的虚拟存储器。

## 块与行：唯一允许的数据搬运单位

层次之间的数据交换只能发生在相邻两层，不能跨层：主存的数据不会直接跳进寄存器，磁盘的数据也必须先经主存中转。而在这样相邻的两层之间，搬运的基本单位不是字节，也不是字，而是一个固定大小的**块**。

同一个概念在两层里有两套叫法：站在主存（或磁盘）那边叫**块（Block）**，站在 Cache 那边叫**行（Line）**，也有教材称缓存行。两者的尺寸必须严格相等，因为搬过去的是整段地址连续的内容。

一次性搬一大块的代价是占用更多带宽，收益是把目录、标记、有效位这类管理信息的开销摊薄到更多字节上，整体仍然划算。常见的块大小是 16、32、64、128 字节这一类 2 的幂——之所以取 2 的幂，是为了让「块内偏移」正好对应地址的低位比特，硬件上只要做位段切割，不需要除法。

块大小是一个设计参数而不是常数：块越大，一次搬进来的将来会用到的邻居越多；但块越大，同样的容量能放下的行数就越少。这里的取舍留到 Cache 那一节算账。

## 命中与缺失

处理器提出一次地址请求时，只会发生两种事情。

- **命中（Hit）**：请求的数据恰好在上层里，直接从上层取出，不必去碰下面那层慢得多的器件。
- **缺失（Miss）**：上层里没有，必须向下层发出请求，把包含目标数据的整个块搬上来，之后才能继续。

描述这两种情况的量一共有四个，混不得：

| 量 | 定义 | 想压低它的办法 |
| --- | --- | --- |
| 命中率 | 命中次数占总访问次数的比例 | 加大容量、提高相联度 |
| 缺失率 | 缺失次数占比，等于 1 减命中率 | 同上 |
| 命中时间 | 在上层成功取出一次所花的时间 | 把上层做小、译码和比较并行做 |
| 缺失惩罚 | 一次缺失带来的额外延迟 | 加一层 Cache、让下层更快 |

命中率是衡量层次结构效率的核心指标。现代处理器的 L1 在典型负载上能把命中率推到 95% 以上，这是整套分层敢做赌注的底气：绝大多数请求在最近的快层就被消化掉了，只有极少数才会真的往下走。

命中时间的构成里不只是「读一次 SRAM」，还包括按索引选行、把标记取出来和请求地址比对、确认有效位为 1、以及把数据送回处理器的传输时间。

缺失惩罚则是一串动作的总和，它比命中时间长一到两个数量级。先确认缺失、再向下层发出请求、等低层把数据准备好、把整块搬上来、必要时腾出一个位置并写回被污染的旧块，最后才能把数据交给处理器。所以在设计账本里，缺失惩罚才是那个真正咬人的数字。

把四个量放在一起看，命中率越高，平均访问时间里缺失惩罚所占的比重就越小；这也是后面所有 Cache 优化共同的靶心。

## 主存内部的三件套

层次再抽象，最底下总得有个真实的器件在存数据。主存这一侧的硬件骨架是固定的：CPU 这边有**存储器地址寄存器 MAR** 和**存储器数据寄存器 MDR**；主存这边有**地址寄存器、地址译码器、存储矩阵、读写控制电路**，中间由地址线、数据线、控制线连起来。

读操作按这个次序走：CPU 把要访问的地址送进 MAR，地址经地址线到达主存并锁进地址寄存器，译码器把它翻译成「选中哪一条字线」的电信号，读写控制电路把对应单元的内容放到数据线上，数据回到 CPU 后锁进 MDR。

写操作的次序不同，而且常考：**先把要写的数据送进 MDR，再把目标地址送进 MAR，最后才发出写命令**。写之前数据必须先就位，否则数据线在写信号到达的那一刻是空的。

一次完整的访存要占用的时间，是从地址稳定、译码选通、读出或写入、到数据回到 CPU 可用为止的全部过程，不只是存储矩阵本身的访问时间。

## CPU 与主存之间的那几根线

总线是所有部件共享的传输介质，按功能分三类，考题里问「谁决定了能寻址多大空间」，答案永远是地址线。

- **地址线**：指出要访问哪个位置。地址线的根数决定可寻址单元个数，32 根地址线按字节编址能覆盖 4GB。
- **数据线**：搬运数据本身。数据线的根数就是一次并行传输的位宽，32 根数据线一次送 32 位。
- **控制线**：读写信号、时钟、中断请求等协调信息，决定这次传输是读还是写、什么时候算完成。

CPU 内部通过总线接口部件挂到存储器总线上，不同速度的总线段（处理器总线、存储器总线、I/O 总线）之间用桥接器衔接；现代设计把这些功能大量收进 CPU 内部，片外的桥已经比早年少得多。

## 这一篇和后面几篇的关系

有了局部性，才谈得上 Cache 的三种映射和写策略；有了「块」这个单位，才谈得上页和缺页——虚拟存储器本质上是把同一套层次思想在主存与磁盘之间再做一遍；有了缺失惩罚这个概念，AMAT 那条式子才有意义。反过来说，如果程序没有局部性，以上所有机制都会退化成纯粹的成本浪费。

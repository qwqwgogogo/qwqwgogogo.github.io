## 串是一个有限序列

串是由零个或多个字符组成的有限序列。串中字符的个数称为串的长度，一个字符都没有的串称为空串，它依然是一个合法的串。用 C 语言写出来，`char str[] = "abcdef";` 就是一个串的字面量，长度为 6。

这里藏着一个容易被忽略的代价。C 语言把 `'\0'` 规定为字符串的结束标志，只给一个字符数组时想知道它有多长，必须从头扫到尾、数出终止符的位置，求长度是一个 `O(n)` 的操作。把 length 单独做成一个字段之后，取长度退化成一次内存读，代价与串长无关，变成常数级。

是否用 `'\0'` 收尾，各语言并没有统一做法，用 length 字段来约束有效字符的范围反而更通用：读字符以 length 为准，数组里多出来的空间一概不看。

## 定长顺序存储与变长分配

串的数据类型有两种典型表示，考点在于各自的取舍。

| 表示法 | 空间来源 | 长度信息 | 代价 |
| --- | --- | --- | --- |
| 定长顺序存储 | 编译期定好的字符数组 | length 字段 | 超过上限就存不下，用不满就浪费 |
| 变长分配存储 | 运行时动态申请来的空间 | length 字段 | 长度可变，但改动往往伴随重新分配 |

串的顺序存储最常见的写法是定长数组加一个长度字段，字符一般从下标 0 起存放，是否额外留一格放 `'\0'` 属于可选设计。另一种写法把数组换成一个字符指针，空间按实际串长申请，结构体里只保留首地址和长度。两种表示之上的运算完全同名同义，区别只在于空间从哪来、上限由谁决定。

## 串的初始化：赋值不能用等号

串是带长度字段的结构，不是标量，因此不能像整数那样用等号直接赋值。等号对结构体做的是浅层复制，两个串会共享同一块堆内存，一边改写另一边跟着变，释放时还会重复释放。规范的做法是定义一个初始化函数，形如 `strAssign(目标串指针, 源字符序列)`，由它按源串的实际长度申请空间、逐字符拷入、再把长度写进 length 字段。凡是赋值、拼接、求子串这类会动到空间的操作，都走「先备好空间再拷贝」这条路。

## 朴素匹配慢在哪

串就是有限个字符组成的序列；子串是串中任意个连续的字符组成的子序列，原来的串叫主串；串长是字符个数，不含任何字符的空串也是一个合法的串。

串的最主要运算之一是模式匹配，也就是在主串里寻找与模式串相同的子串，并返回它所在的位置。暴力匹配（Brute-Force）的做法是把模式串以字符为单位沿主串从左往右滑动：对上一个位置就逐字符比，第一个字符对上就继续往后比，中途失配就把模式串挪到主串的下一个起始位置重新起步，直到某一次全部对上、或者滑到主串末尾为止。

模式匹配最直白的做法是拿模式串贴着主串一个个位置试：对齐后逐字符比，一旦失配就把主串的指针**退回到本次开始位置的下一个**，模式串指针归零重来。这个回溯就是全部代价——主串的指针从不前进得比期望快，最坏情况时间复杂度 `O(n×m)`，出现在「主串一片 a、模式串是 aaab」这种有大量重复前缀的场合。

## KMP 只改一件事

KMP 的核心观察是：失配点之前那段已经比成功的字符，本身就携带了信息——它既是被匹配过的一段，也是模式串的一段，没必要把主串的指针往回退。于是模式串指针退回一个由**自身结构**决定的位置，主串指针原地不动，整个匹配变成单趟扫描，时间复杂度 `O(n + m)`。

那个「退到哪个位置」就是 next 数组，next 数组数的就是每个位置左边那段串里，最长的相等真前缀和真后缀有多长。

还有一句要紧的话：next 数组里的值只跟模式串有关。失配点之前比成功的那些字符，本来就是照着模式串的前缀比上的，主串那一段只是它的副本，把主串也考虑进去纯属冗余。一张只由模式串决定的表就够用了。

## 跳过不可能成功的比较

拿模式串 `abcabd` 与主串 `abcabxxxx` 走一遍。从主串第 1 个字符起比，前 5 位全部对上，在第 6 位失配。

失配这件事本身就给出了信息：既然比到 `p[6]` 才断，说明 `s[1..5]` 这段就是 `abcab`。那么把起点改到 `s[2]` 或 `s[3]` 再试，模式串的首字符 `a` 要分别去撞 `b` 和 `c`，根本不用比就能断定失败。而起点挪到 `s[4]` 时，`a` 撞上的正是 `a`，这一次是有可能成功的。

暴力匹配会把这两次注定失败的尝试老老实实做一遍，KMP 则在失配的那一刻直接跳到 `s[4]`：主串指针一步不退，只改模式串指针。要跳得准，就得事先把「第 j 位失配时该退到第几位」存下来，这就是 next 数组存在的理由。

## 前缀与后缀先把口径定死

手算 next 只用到两个概念。串的前缀是指包含第一个字符、但不包含最后一个字符的那段子串。串的后缀指包含最后一个字符、但不包含第一个字符的那段子串。以 `aba` 为例，前缀是 `a` 和 `ab`，后缀是 `a` 和 `ba`，两边都不允许取到整串本身。

next 数的正是这两类子串里长度相等的那一对：第 j 个字符匹配失败时，把前 `1..j-1` 个字符组成的串记作 S，next[j] 等于 S 的最长相等前后缀的长度再加 1。

## 手算 next

取模式串 `a b a b c`，next[j] 看的是**第 j 个字符之前那一段**里最长的相等真前缀和真后缀，再把长度加 1：

```
下标 j    1  2  3  4  5
字符      a  b  a  b  c
next[j]   0  1  1  2  3
```

第 1 位之前什么都没有，按约定填 0。第 2、3 位之前的段分别是 `a` 和 `ab`，都找不到相等的真前缀和真后缀，长度 0 加 1 得 1。第 4 位之前是 `aba`，头尾的 `a` 相等，长度 1 加 1 得 2。第 5 位之前是 `abab`，最长相等前后缀是 `ab`，长度 2 加 1 得 3。

两套约定都得会认：教材口径是下标从 1 开始、首位为 0、值是「最长相等前后缀长度加 1」；代码里常见的写法把同一张表整体右移一位、首元素取 -1，含义完全相同，套公式时**必须看清题目用的是哪一种**，差一位就全错。

## next 值的三条规律

第一条，next[j] 的值每次最多增加 1。相邻两位之间只多进来一个字符，相等的前后缀最多只能伸长一格，所以表里不会出现跳着上涨。

第二条，模式串的最后一位字符不影响 next 数组的结果。每一位看的是它自己前面那一段，末位从来没被任何一段包含过，改它会改写出 next 表之外的东西。

第三条是 next 数组本身的定义：当主串与模式串的某一位字符不匹配时，模式串要回退到的位置。退的位置由表给出，主串指针因此不必回溯。

## 匹配时怎么用

失配发生在主串第 `i` 位、模式串第 `j` 位时，让 `j` 跳到 `next[j]`，`i` 保持不动，再继续比。这一跳的正当性是：跳到那个位置恰好能让模式串的前 `next[j]-1` 个字符对上刚刚已经匹配过的尾巴，所以那一段不必重新比。如果 `next[j]` 跳过去还失配，就继续用更小的 `next` 往回跳，一路跳到 0 才意味着「这里彻底没戏」，主串指针前进一步。

KMP 不改变匹配的**结果**，第一个成功的位置和朴素算法完全一样，它省掉的只是重复比较。这也是判断题里那句「KMP 更快，所以匹配位置不同」的错误所在。

写成骨架就是：两个指针各自往前走，相等就双双加一；不相等时只动模式串指针，把它换成 `next[j]`，直到 `j` 归零才让主串指针单独前进一格。主串指针从头到尾不回退，是这两个算法在代码上最直观的分水岭。

## next 数组是怎么推出来的

求 next 表不能一位一位从头重扫，那样又退化成平方级。递推的思路是：算 next[17] 时 next[16] 已经是已知的。

设 next[16] = 8，它的含义是前 15 个字符里，长度为 7 的前缀和后缀相等，也就是 `p[1..7]` 与 `p[9..15]` 逐位相同。现在要往第 16 位后面再接一个字符，只需要看能不能把这对相等段各伸长一位，即比较 `p[8]` 与 `p[16]`。若相等，next[17] 就是 8 + 1。

若不相等，不能就此罢休，因为 next[8] 又给了下一层相等关系。设 next[8] = 4，说明 `p[1..3]` 与 `p[5..7]` 相等；把它和 `p[1..7]` 等于 `p[9..15]` 拼起来，就同时知道 `p[1..3]` 等于 `p[9..11]`、`p[5..7]` 等于 `p[13..15]`。于是候选退一层，改比 `p[4]` 与 `p[16]`：若相等，说明有 3 个字符的相等前后缀再各接一位，即 `p[1..4]` 与 `p[13..16]`，next[17] = 3 + 1。

再不等就再退。设 next[4] = 2，即 `p[1]` 与 `p[3]` 相等，也就等价于 `p[1]` 与 `p[15]` 相等，此时比 `p[16]` 与 `p[2]`：相等就有 `p[1..2]` 与 `p[15..16]`，next[17] = 2 + 1。若还是不等，继续用 next[2] = 1、next[1] = 0 往下退，一旦取到 0，递推就结束了，next[17] 只能填 1。

看清楚了：整个过程和匹配本身是同一种动作——比较、不等就按表回退、回退到零就收手。所以求 next 表的代码与 KMP 的匹配代码长得几乎一样。

## 求 next 的代码骨架

把上面那段递推翻成程序，只需要三个量：正在填表的位置 `i`、当前候选的相等前缀长度 `j`、以及表本身。

```
i 从 1 起、j 从 0 起，next[1] 置 0
只要 i 还没越过串尾：
    若 j 为 0，或 p[i] 与 p[j] 相等：
        i、j 各加一，把 j 写进 next[i]
    否则：
        j 退回 next[j]
```

两个分支对应上面推理的两条路：字符对上就把相等段伸长一格并前进；对不上就让 `j` 沿着自己已经算好的表往回退，退到 0 时下一格必然填 1。整段没有内层嵌套循环，`i` 单调前进，因此求表本身是线性的。

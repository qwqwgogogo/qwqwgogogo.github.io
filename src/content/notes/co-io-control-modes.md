## 先摆好四种方式的位置

I/O 数据传送主要有三种控制方式：程序直接控制、中断控制和 DMA 控制，再往上还有通道方式。四者的区别只有一件事——CPU 在数据搬运过程中被绑住多久：程序直接控制全程参与，中断方式在每次传输时参与一次，DMA 只在开始与结束时参与，通道方式下 CPU 连启动细节都不必管。端口编址与接口结构这些前置内容在接口那一篇，这里只讲传送过程。

## 无条件传送

程序直接控制方式靠查询程序本身来控制主机与外设之间的数据交换，最简单的形态是无条件传送，也叫同步传送。它假定外设永远处于就绪状态：CPU 在固定的周期内访问 I/O 设备，用相应的 I/O 指令对接口中的寄存器做信息输入或者输出，实质是用程序定时来同步传送数据。适用于开关、继电器、七段显示器件、简单的机械式传感器这类设备，常见于各类巡回采样检测和过程控制场合。

硬件上它是最省的。接口里只需要数据锁存器和三态缓冲器：锁存器暂存来自总线或者输入设备的数据，保证传输过程中内容稳定；三态缓冲器有高电平、低电平与高阻三种输出状态，用来控制数据流向、避免总线冲突。芯片使能信号 CE 决定这些器件何时参与工作，读写信号 WR 与 RD 决定方向——写信号有效时数据从 CPU 流向设备，读信号有效时数据从设备流向 CPU。地址线负责选中对象，译码器根据地址选择对应的电路部分，M/IO 这类信号说明当前是访存还是访 I/O。整个接口不需要定时信号，也不需要状态查询，只做读写控制和地址译码。

它的三个特点：**定时访问**，CPU 按预设时间间隔访问端口，不等任何外部事件，传输有周期性但可能浪费 CPU；**接口简单**，没有复杂同步机制，只要基本的数据锁存与缓冲加上读写控制；**效率问题**，慢速设备更新慢，CPU 的访问频率远高于设备的实际更新速率，这段等待对整体性能影响不大，但对高速设备就必须频繁访问，会显著占用 CPU、降低处理器效率。一个温度传感器每分钟更新一次，处理器每分钟读一次即可，中间大量时间可以做别的事；换成高速网络接口或者高速磁盘驱动器，这种做法就成了性能瓶颈，只能改用中断驱动、DMA 或者更先进的技术。

## 条件传送：程序查询方式的内部过程

条件传送方式也叫异步传送方式，通常就直接称作程序查询方式，适用于有多个控制、状态和数据寄存器的较复杂接口——设备的控制必须依据特定的状态条件。CPU 周期性执行一段查询程序，用 I/O 指令读取状态寄存器里的就绪、忙、完成这类标志位，据此判断外设能不能传数据，决定是继续查询还是启动传输。打印机处于就绪状态时主机才发送打印数据，处于忙状态时主机就等它变成就绪。

一次完整的数据交换可以拆成六步，内部靠两个触发器串起来：

1. CPU 执行 I/O 指令向接口送出启动命令，设备选择电路对地址译码选中该接口，完成状态触发器 D 被清零、启动命令触发器 B 被置 1；
2. I/O 接口向外设发出启动设备命令，数据开始准备；
3. 外设把准备好的数据送入接口的数据缓冲寄存器；
4. 外设回送设备工作结束信号，使状态触发器 D 置 1、命令触发器 B 清零；
5. CPU 不断读取接口状态，查询到 D 为 1，说明外设准备就绪；
6. CPU 执行 I/O 指令从数据缓冲寄存器取走数据，一次交换完成。

这个过程的关键是状态查询与条件控制：数据只在合适的时刻被传输，既不会太早也不会丢，代价是 CPU 在等待期间只能反复查询，这段时间被完整地花在轮询上。条件传送的特点有三个：状态查询（只看就绪、忙、完成这些标志位，只有设备处于合适状态才传输）、异步操作（不必固定轮询周期，随时可查，一旦就绪立即传，比无条件传送灵活）、效率提升（对状态变化不可预测或者更新频繁的设备，避开了设备没准备好时的无效轮询）。它仍然有上限：设备就绪状态变化极快时 CPU 要频繁查询，依然浪费；响应时间很短或者 I/O 请求很多时，就该换成中断驱动或者 DMA。

## 哪些设备适合查询，哪些不适合

| 设备类型 | 特点 | 合适的传送方式 |
| --- | --- | --- |
| 随机启动的低速设备，如键盘、鼠标 | 何时被操作由用户决定，定时查询会在设备未启动时空耗大量时间 | 中断驱动，只在设备有输入时通知 CPU |
| 由操作系统启动的设备，如磁盘、磁带、光盘 | 一旦启动可连续传大量数据，速率高、块大，频繁查询极耗 CPU | DMA，或者中断驱动 |
| 字符类设备，如针式打印机 | 每打一个字符启动一次，字符间传输时间长 | 条件传送，查询负担不重 |

## 定时查询与独占查询

条件式程序查询按查询被启动的方式不同，分为定时查询和独占查询两种，可依外设特点选择。

**定时查询**是最简单的策略，基于固定的周期性检查：每个查询周期内 CPU 执行若干 I/O 指令读状态寄存器，设备就绪就传，没就绪就等下一个周期再来。它的优点是规律性和可预测性强，便于系统做资源规划与调度，对状态变化不太频繁但又需要及时响应的设备能在资源利用与响应及时性之间取得平衡。缺点也很直白：不管设备是否就绪都要按固定间隔查询，设备不常使用时大量查询是白做的；如果设备状态变化不吻合这个间隔，可能出现查询时还没就绪、或者早已就绪却要等下一轮才被看到的延迟。适合的场景是低速 I/O 设备、需要由处理器或其他硬件逻辑触发 I/O 操作的非独立启动设备，以及系统负载较低、处理器有空闲时间做查询的时候。

**独占查询**更接近按需查询：CPU 不总是主动去查，而是等设备状态发生变化、由设备置起状态标志提示之后再查询，因此减少了空闲轮询。优点是精准针对实际状态变化、省处理器资源，对有明显触发条件或者变化不规律的设备响应更及时，等待时间更短。代价是实现难度上升——查询的触发条件更复杂，需要额外逻辑判断何时该查；如果触发条件判断不准或者出错，设备状态就可能没被及时查询和处理。适合高速 I/O 设备、能够独立启动 I/O 并需要处理器实时响应的设备，以及实时性要求高的系统。

两种查法各有得失：定时查询实现简单但设备不常用时效率低，独占查询效率高却要求设备具备状态变化通知的能力。设计者按设备的使用模式与性能需求权衡，而不是默认后者更好。

关于独占查询还有一个名字上的坑要留意：另一种常见口径把独占查询理解成立即查询，即启动 I/O 之后 CPU 独占处理器、什么别的事也不做，反复执行查询指令直到设备就绪。两种说法都还属于程序查询方式，与中断方式的区别没有变，差别只在轮询是被定时节拍触发、被状态变化触发，还是被程序自己无休止地触发。做题时按题目给出的定义判断，不要靠名字猜。

## 中断控制方式：CPU 在等待期间做别的事

中断控制 I/O 方式是为了解决程序查询里 CPU 过度等待外设的问题而提出的。流程涉及两个进程：进程 R 要做 I/O，先通过系统调用请求服务，操作系统启动外设做第一个数据的传送，然后把 R 挂起、置为阻塞态，调度器从就绪队列里选另一个进程 P2 上 CPU——这就是 CPU 与外设的并行。外设完成后向 CPU 发中断请求，CPU 中止正在执行的 P2、保存它的上下文（程序计数器和寄存器状态），转入中断服务程序；服务程序把数据从外设缓冲取到进程缓冲，并启动后续数据的传送；执行完毕返回 P2 的断点继续跑，外设和 CPU 再次并行。I/O 如果是 R 请求的，操作系统随后唤醒 R，把它放回就绪队列。

省下来的正是那段等待时间。麻烦在于中断方式仍然以字或者字节为单位搬数据，每搬一个都要走一遍保护现场、恢复现场、返回的全过程，所以传一大块数据时，中断本身成了瓶颈——这也是 DMA 出现的理由。响应时机、判优、屏蔽这些机制细节在中断那一篇里。

## DMA：数据不过 CPU 寄存器

DMA（直接存储器存取）允许外设与主存之间直接交换数据，而不需要 CPU 直接参与传输过程，处理大量数据或者高速数据流时能显著减轻 CPU 负担。控制这块搬运的硬件是 DMA 控制器，它专门用来控制总线做 DMA 传送，负责协调外设与主存之间的数据传输，确定传输方向（外设到主存还是主存到外设）、传输的数据量和起始地址，自己维护内存地址、字节计数器和传输长度。传送时 CPU 暂时让出总线控制权，由 DMA 控制器接管总线，通过挪用主存周期完成与主存之间的数据交换——数据不经过 CPU 的寄存器，这正是它与中断方式的根本差别：中断方式下数据要走 CPU，DMA 方式下 CPU 只是让出了总线。

一次 DMA 传送的过程分六步：

1. **初始化**：CPU 对 DMA 控制器做设置，指定源地址、目标地址、传输的数据量和传输方向；
2. **DMA 请求**：外设准备好数据或者需要接收数据时，向 DMA 控制器发出请求；
3. **DMA 响应**：控制器检查当前的总线状态，需要时向 CPU 发出总线请求信号，请求让出总线控制权；
4. **CPU 响应**：CPU 收到总线请求后暂停当前程序，保存程序计数器和状态寄存器的值，允许控制器接管总线；
5. **数据传输**：控制器按初始化时设置的参数控制外设与主存之间的传输，可以挪用一个主存周期完成一次交换，也可以独占若干个主存周期完成一批交换；
6. **DMA 结束**：传完后控制器向 CPU 发中断信号告知数据传输结束，CPU 恢复先前保存的现场，继续执行被中断的程序。

## 三种占用主存的方式

总线被两边同时想要怎么办——CPU 也要访存，DMA 也要访存。共享主存资源就必须协调，三种策略的差别是 CPU 让路的程度，通常让 DMA 的请求优先级更高。

| 方式 | 做法 | 代价 | 适用 |
| --- | --- | --- | --- |
| CPU 停止访问 | DMA 请求访存时让 CPU 暂停、释放总线，DMA 独占总线与主存，传完再归还 | 简单，但 DMA 频繁时 CPU 等待时间长 | 传输量大、允许 CPU 暂时歇一会 |
| 周期挪用 | DMA 在 CPU 不用总线的间隙抢一个周期，传完一个数据单元立刻归还 | 每次搬运多一次仲裁 | 实时系统、对 CPU 性能要求高、传输量较小 |
| 交替分时 | 把一个存储周期分成两个时间片，一份给 CPU、一份给 DMA | 双相位定时的硬件要求严 | 高带宽需求、要求 CPU 与 DMA 真并行 |

**CPU 停止法**最粗暴：DMA 控制器请求访问主存时向 CPU 发停止信号，使 CPU 暂停执行、释放总线控制权，控制器独占总线和主存完成这段传输，结束后释放总线，CPU 恢复执行。实现简单，代价是 CPU 的等待时间随 DMA 操作频率上升而变长。

**周期挪用**（也常被称作周期窃取）允许 DMA 控制器在 CPU 不使用总线的间隙抢占总线：搬一个数据占用一个存取周期，之后立刻把总线还给 CPU 继续执行。它平衡了两边的需求，对 CPU 干扰最小，适合数据传输量较小的情况。要记住窃取的是总线周期，不是 CPU 的指令周期——CPU 只是那一拍没访存而已，指令照常执行。

**交替分时访问**把每个存储周期切成两个时间片，CPU 和 DMA 控制器在同一存储周期内轮流访问主存，实现真正的并行。它最大限度利用了主存带宽，在高带宽需求的应用里特别有效；代价是要有精确的双相位定时，硬件上不如前两种省事。

## DMA 为什么直接对物理内存动手

没有 DMA 控制器时，CPU 是唯一通过 MMU 的地址转换与 cache 层次来存取存储器的主体：程序发出访存，虚拟地址经 MMU 换成物理地址，命中 cache 就快、缺失才访问主存。引入 DMA 之后，控制器直接访问存储器，不经过地址转换机制，也不经过 cache 层次。用物理地址的原因有两条：一是直接性，控制器不与 CPU 的地址转换过程打交道，必须拿物理地址；二是效率，绕开转换就减少了 CPU 介入，传输更快。

由此带来两类问题。

**跨页问题**。虚拟地址空间里连续的缓冲区，映射到物理内存后可能分散在多个页面。由于 DMA 按物理地址工作，一次传输通常被限制在单个物理页面内；请求跨越多个物理页面时，就得拆成多次传输，每次只在一个页面内搬。解决办法两条路：操作系统在初始化 DMA 时把跨页请求分解、为每个物理页面分别设置一次传输；或者用具备跨页传输能力的高级 DMA 控制器，代价是硬件更复杂、成本更高。也有在 DMA 接口里放一张小型地址映射表做虚拟到物理转换的做法，但并不常见，同样是因为复杂度和成本。

**缓存一致性问题**，也就是 I/O 一致性问题。DMA 与 CPU 可能访问同一片区域，看到的却不是同一份数据。DMA 从磁盘把数据直接读进主存时不更新 cache，若 CPU 早先把这块数据读进 cache 并改过，主存里的内容和 cache 里的值就对不上；反过来，cache 采用写回策略时，CPU 改过的数据可能还没写回主存，DMA 这时从主存读走的就是过期内容。两个方向都会出错：DMA 写入主存后 CPU 可能仍从 cache 读到旧值，CPU 改了 cache 未写回时 DMA 读到的是旧值。

处理手段可以分层：用 MESI 一类的缓存一致性协议，DMA 访问主存时触发必要的刷新或者失效；设计支持缓存感知的 DMA 控制器，写之前通知缓存子系统刷新或使相关行无效，读之前检查缓存里有没有更新的副本；由软件管理，操作系统或者驱动在 DMA 前后执行缓存刷新，或者把缓冲区映射成 uncached、write-through 属性使其绕过缓存；在硬件上增加监视部件自动处理 DMA 与 cache 的交互；或者做分区策略，把内存划成 DMA 专用区与 CPU 缓存区，减少冲突，代价是灵活性下降、要求仔细管理内存分配。实际系统通常按需求组合几种，而不是只用一种。

## 通道：把一批 I/O 任务交给一台小处理器

通道再往上走一层：它是一台带自己指令集的小型处理器，执行一段通道程序，一条命令就能管理好几台设备的成批传输，并在完成时中断 CPU 报告结果。这样 CPU 只剩启动与收结果两个动作，通道、DMA、中断三级正好对应一次命令管一批设备、一批数据、一个字的粒度差别。按服务的设备类型和占用方式，通道通常分为字节多路通道（以时间片轮转为大量低速设备逐字节服务）、数组多路通道（成块传输与多路并发兼顾）和选择通道（独占一台高速设备直到传完）三类。大型系统里靠多通道并行，把 I/O 开销从主 CPU 上卸载下来，这也是 I/O 处理器的思路。

## 一张表收口

| 方式 | 数据经由 | 单位 | CPU 介入 | 适合 |
| --- | --- | --- | --- | --- |
| 无条件传送 | CPU | 字 | 全程，按固定周期访问 | 开关、指示灯、慢速采样 |
| 条件传送 | CPU | 字 | 全程，查询到就绪才传 | 针式打印机一类字符设备 |
| 中断 | CPU 寄存器 | 字 | 每个字一次中断 | 键盘这类零散输入 |
| DMA | 直连主存 | 块 | 启动一次、结束一次中断 | 磁盘、显卡这类大块传输 |
| 通道 | 直连主存 | 一批任务 | 一条通道程序 | 多设备并发的大型系统 |

从查询到中断、从中断到 DMA、从 DMA 到通道，每一步都在把 CPU 从数据搬运上往下摘：查询方式让 CPU 全程陪着设备，中断方式让 CPU 只在每个字上出现一次，DMA 让 CPU 只在头和尾出现，通道让 CPU 只交出一段任务描述。代价是硬件越来越复杂、灵活性越来越低，所以简单设备至今仍用查询方式实现。

## 三个易错点

**以为无条件传送不需要地址译码**。它省掉的是状态查询与握手，选设备、选寄存器仍然靠地址译码。

**把周期挪用理解成偷 CPU 的指令周期**。挪用的是主存存取周期，CPU 只在被挪用的那几拍不能访存，指令照常执行。

**以为 DMA 完全不需要中断**。搬运过程不需要，但初始化要 CPU 做、结束要靠中断通知，CPU 还要恢复现场。

## I/O 接口站在中间干什么

CPU 和外设之间哪哪儿都不匹配：速度差几个量级、数据宽度不同、时序不同、信号电平不同。I/O 接口就是夹在中间做适配的那块硬件，它要缓冲数据、报告状态、接收 CPU 的命令、把外设的数据格式转成机器能用的格式、还要做地址译码。接口里那些能被 CPU 读写的寄存器叫 I/O 端口，一个设备通常有数据端口、状态端口、控制端口三类。

## 端口怎么编址

| | 独立编址 | 统一编址 |
| --- | --- | --- |
| 地址空间 | 端口号和内存地址各一套，互不冲突 | 端口占内存地址，混在一起分 |
| 指令 | 要有专门的输入输出指令 | 普通访存指令就能操作端口 |
| 硬件 | 要多一根区分「访存还是访端口」的信号 | 不需要这根线，但可寻址的内存少了 |
| 灵活性 | 端口指令少，功能受限 | 任何对内存能做的运算都能对端口做 |

这一条也是操作系统的接口：Linux 既提供端口指令式的系统调用，也支持把设备寄存器映射进内存地址空间，两种路子都活着。

## 四种控制方式，按 CPU 被绑住的程度排

**程序查询方式**最原始：CPU 反复读状态端口，等外设准备好。它又分两种：无条件传送假定设备永远就绪（比如常亮的指示灯，程序不需要检查），条件传送则必须查状态位。条件传送里还有两种查法——独占查询是 CPU 什么都不干光等，把时间全花在轮询上；定时查询是每隔一段时间查一次，中间可以去算别的，代价是可能要等下一轮才看得见设备已经好了。CPU 利用率极低，但硬件最省、时序最直白，简单设备一直用它。

**程序中断方式**把「等」换成了「被打断」：CPU 发出 I/O 命令后就去干别的，设备完成后发一个中断请求，CPU 在指令边界响应，进中断服务程序取走数据。省下的正是那段等待时间。麻烦在于它仍然**以字或者字节为单位搬数据**，每搬一个就要走一遍中断全过程——保护现场、恢复现场、返回——所以传一大块时，中断本身成了瓶颈。

**DMA** 把搬运这件事从 CPU 手里彻底拿走。控制这块搬运的硬件叫 DMA 控制器，它自己维护内存地址、字节计数器和传输长度，收到 CPU 的启动命令后就独立地把外设与主存之间的数据一块块搬过去，全程不经过 CPU 的寄存器，只在整块传完（或出错）时才发一次中断。它和中断方式的根本差别是：中断方式下数据要走 CPU，DMA 方式下 CPU 只是让出了总线。

总线被两边同时想要怎么办——CPU 也要访存，DMA 也要访存。解决办法是让 DMA 的请求优先级更高，它按**周期**借用总线：搬一个数据占用一个存取周期，之后立刻还给 CPU，这叫周期窃取。窃取的是总线周期，不是 CPU 的指令周期，CPU 只是那一拍没访存而已。

**通道**再往上走一层：它是一台带指令集的小处理器，执行一段通道程序，一条命令就能管理好几台设备的成批传输，并在完成时中断 CPU 报告。这样 CPU 就只剩「启动」和「收结果」两个动作了。通道、DMA、中断三级正好对应「一块设备、一批数据、一次命令管多台」的粒度差别。

## 一张表收口

| 方式 | 数据经由 | 单位 | CPU 介入 | 适合 |
| --- | --- | --- | --- | --- |
| 程序查询 | CPU | 字 | 全程死等 | 极简单设备 |
| 中断 | CPU 寄存器 | 字 | 每个字一次中断 | 键盘这类零散输入 |
| DMA | 直连主存 | 块 | 启动一次、结束一次中断 | 磁盘、显卡这类大块 |
| 通道 | 直连主存 | 一批任务 | 一条通道程序 | 多设备并发的大型系统 |
